# HSK 결과 중심 관리자 화면 재설계

## 시작 문제

HSK 화면의 상하 순서를 검수 흐름 우선으로 바꾼 뒤에도 첫 화면의 3분의 2가
`수준 선택 → 자동 대조 → 교수자 확인` 절차 설명에 쓰였다. 실제 작동 증거인 최근 49/35/14와
LOCK 전 30건 검증은 작게 배치돼, 검증 대상과 작동 결과를 확인하기 어려웠다.

## 채택한 설계

- H1을 `HSK 3.0 어휘 기준·점검`으로 바꿨다.
- `0 · 설계 기준`의 논리에 맞춰 페이지 순서는 `HSK DB 탑재·수준 대응 → 실제 점검 결과`로
  확정했다. 결과 중심 원칙은 운영 결과 Hero 내부에서 유지했다.
- PRAGMA 입문·중급·고급은 각각 HSK 1–4·1–5·1–6급 누적 범위와 2,000·3,600·5,400개를
  같은 카드 안에 결합했다. 각 카드 하단에는 1–4급 세부 수량, 5급 1,600개 추가, 6급 1,800개
  추가만 보조 정보로 두고, 같은 대응을 역방향으로 반복하던 HSK 구간 카드와 상한 막대는 제거했다.
- 전체 DB 11,000개 연결은 헤더에 남기되 실제 점검에 쓰지 않는 HSK 7–9급과 HSK 주제 427개는
  기본 화면에서 제외했다.
- 최근 결과의 첫 문장을 `49개 중 35개를 HSK 참고 범위에서 확인했습니다`로 바꾸고 49·35·14를
  같은 결과표에 묶었다. 71%는 `35/49`의 보조 설명으로 내렸다.
- 30건 검증은 최근 사례와 분리해 `12개 조건 · 시험 콘텐츠 30건 · 점검 결과 저장 30/30` 전폭
  상태 줄로 표시했다.
- 절차는 `PRAGMA 수준 선택 → HSK 누적 범위 대조 → 확인 항목을 교수자에게 전달` 한 줄로 압축했다.
- 공식 출처는 페이지 최하단으로 이동했다.
- 페이지 내부 본문 글자의 하한을 12px로 올렸다.

## 해석 경계

- `71%`는 현재 화면에 표시된 최근 한 사례의 HSK 참고 일치이며 전체 콘텐츠 품질 지표가 아니다.
- `30/30`은 감사 계약과 저장 기록이 만들어졌다는 장치 시험 결과이며 콘텐츠 적합률이 아니다.
- 확인 대상은 자동 오류나 탈락 조건이 아니며 교수자가 고유명사·전문용어와 문맥을 판단한다.

## 작업 종료 시 남은 문제

30건은 12개 수준·방향·모드 조건에서 장치가 작동하는지 확인한 시험이고, 49/35/14는 최근 저장
콘텐츠 한 건의 실제 어휘 점검 결과다. 기술적으로는 다른 증거이지만 두 결과를 같은 주 화면에
연속 배치하자 사용자가 차이를 즉시 이해하기 어려웠다. 현재 로컬 구현에는 30건 상태 줄이 남아
있으며, 다음 반복에서는 이를 주 화면에서 제거하고 연구 증거 문서에만 보존하는 방안을 우선한다.

## 실화면 검증

- localhost 1265×711 첫 화면에서 LIVE 운영 DB와 세 PRAGMA 수준의 HSK 누적 범위·신규 구성만
  한 번씩 표시됨을 확인했다.
- 이어지는 영역에서 독립 30/30 상태 줄, `49개 중 35개` 제목, 49·35·14 결과표와 한 줄 작동
  방식을 확인했다. HSK 7–9급·HSK 주제는 보이지 않고 공식 출처는 페이지 최하단에 위치했다.
- `14개 확인하기`는 `/admin/review?hsk=candidates`를 열어 HSK 확인 후보 14건을 표시했다.
- HSK 관련 Vitest 14/14, typecheck, 변경 파일 ESLint와 production build 1,910 modules가 통과했다.

## 2026-08-11 후속 적용

- 사용자 확정에 따라 30건 장치 시험 상태 줄을 주 화면에서 제거했다. 시험의 목적·30/30 저장·hash
  불변 증거는 `2026-08-10-hsk-audit-validation-30.md`와 `EVD-20260810-04`에 계속 보존한다.
- 최근 운영 카드에는 `최근 콘텐츠 점검 결과`와 `최근 저장 콘텐츠 1건을 전수 대조했습니다`를
  표시해 49/35/14가 한 콘텐츠의 실제 점검 결과임을 명확히 했다.
- localhost 1265×711 실데이터 화면에서 30건·30/30 문구 0건, 새 표제 1건, 입문·한→중·HSK
  1–4급 누적·49/35/14와 `/admin/review?hsk=candidates` 연결을 확인했다.
- 표적 Vitest 8/8, typecheck, 변경 화면 ESLint와 production build 1,910 modules가 통과했다.
  브라우저 오류는 없고 기존 React Router 향후 버전 경고 2건만 확인됐다.

## 2026-08-11 점검 방식 귀속과 용어 정리

- HSK 점검의 상세 계산 방식은 데이터·수준 대응·최근 결과를 함께 소유하는 `/admin/corpus`에
  배치했다. 입력, DB 표제어 정확 일치 계산, 결과·정책 버전 저장과 교수자 검수 연결을 세 단계로
  표시했다.
- 정확 일치는 목록 밖 어휘 사용을 금지하는 허용 목록 규칙이 아니며, 콘텐츠 전체가 수준에 비해
  너무 쉽거나 어려운지와 교체·재생성 필요 여부를 판정하지 않는다고 명시했다.
- 최근 49/35/14 결과의 14개는 `교수자 검수 후보`로 표시했다. 후보가 곧 수정 필요를 뜻하지 않고
  고유명사·전문용어·분절 결과일 수 있다는 해석 경계를 결과 바로 아래에 뒀다.
- `/admin/prompt-harness`에는 상세 HSK 박스를 중복하지 않고 `규칙 기반 검사`의 사례와 corpus 이동
  경로만 남겼다. 상위 체계는 `규칙 기반 검사 → 프롬프트 통제 기반 검토 → 교수자 검수·승인`으로
  표시했다.
- localhost 실데이터 화면에서 PRAGMA 입문·한→중·HSK 1–4급 누적, 최근 콘텐츠 한 건의
  49/35/14, 상세 점검 방식과 양방향 난이도 판정 한계를 확인했다. corpus와 prompt-harness의
  브라우저 오류는 0건이었다.

## 2026-08-11 실제 점검 사례 서사 보정

- `최근 콘텐츠`라는 추상 표현과 35/49 비율 막대만으로는 점검 대상과 수치의 의미를 알 수 없고,
  비율을 콘텐츠 통과율이나 난이도 적합률로 오독하게 한다는 사용자 피드백을 확인했다.
- `scenarios` 행에 이미 저장된 title·speech_act·learner_level·mode·language_direction을 기존
  조회에 함께 포함했다. 별도 집계·테이블·네트워크 요청은 추가하지 않았다.
- 실제 카드에는 `처음 만난 조원에게 감사 인사 전하는 글`과 `감사·PRAGMA 입문·번역·한→중·학습
  미션 1건`을 먼저 표시했다. 결과는 `점검 대상 1건 → 문장부호·공백 제외·중복 제거한 중국어
  단어 단위 49개 → HSK 1–4급 누적 데이터셋에서 정확히 확인 35개·교수자 검수 후보 14개`로
  연결했다.
- 35/49 비율 띠와 71% 표시는 제거했다. 35개는 목록 조회에서 확인된 단어이고 14개는 실패가 아닌
  교수자 검수 후보라는 해석 문장을 결과 바로 아래에 배치했다.
- 페이지 순서는 `DB·수준 대응 → 규칙 기반 검사 → 가장 최근 점검 기록 → 공식 출처`로 확인했고,
  브라우저 오류는 0건이었다.
