# Contrast Lens — 최종 UI brief (구현 전 승인용) · 2026-09-12

승인된 방향: 새 문항·응답 스키마·DB·프롬프트·규칙 없이, MJT2 화면에서 MJT1을 **잠금 카드**로 병렬해
「같은/유사한 표현 형식이 다른 관계에서 어떻게 달리 기능하는가」를 보이게 한다. **판단 전에는 P/D/R
단서를 주지 않고, 제출 후에 대비를 드러낸다.** MJT3·4·5·DCT는 건드리지 않는다.

정의(과장 금지): 현재 20건에서 같은 명제핵은 **0/20**, 같은/유사 실현 구문은 **15/20**(아래 §3). 그러므로
이번 렌즈는 「같은 말」이 아니라 **「같은/유사한 표현 형식 · 다른 관계 · 다른 기능」**을 보여 주는 장치다.

## 2. 화면

### 2-1. MJT2 판단 전 (PC ≥ lg 좌우 / 모바일 위아래) — **shared_form 모드**

```
┌ 표현 판단 · 2/5 ───────────────────────────────────────────────────────────────┐
│ ┌ 🔒 방금 판단한 상황 ─────────────────┐  ┌ 맥락 대비 판단 ─────────────────────┐ │
│ │ 나는 매주 사적으로 만나는 친한 친구와  │  │ 나는 같은 직급 동료와 몇 차례 자료를  │ │
│ │ 내일 우리 집에서 보드게임을 하기로     │  │ 주고받았는데, 지난번에 받은 회의실     │ │
│ │ 했다. 친구의 카드 게임도 가져와 달라고 │  │ 예약 안내 링크를 잃어버렸다. 메신저로  │ │
│ │ 부탁하려 한다.                         │  │ 다시 보내 달라고 부탁하려 한다.        │ │
│ │ 관계 · 매주 만나는 친한 친구            │  │ 관계 · 몇 차례 자료를 주고받은 동료    │ │
│ │                                        │  │ [동등] [아는 사이] [부담 낮음]  ← 현행 │ │
│ │ 明天我们说好在我家玩桌游。             │  │ 我把之前收到的会议室预约说明链接弄丢了。│ │
│ │ 你就把那个小卡牌游戏也带来吧。         │  │ 你就把那个链接再发我一次吧。           │ │
│ │                                        │  │                                        │ │
│ │ 내 선택 · 다소 적절                    │  │ 이 번역안은 이 상황에 맞나요?          │ │
│ └────────────────────────────────────────┘  │  ○ 현재 상황에 맞음                   │ │
│                                              │  ○ 너무 직접적 (상황에 비해 단정적)   │ │
│                                              │  ○ 지나치게 우회적 (요청이 흐려짐)    │ │
│                                              │                         [답안 확인하기]│ │
│                                              └────────────────────────────────────────┘ │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

- 잠금 카드에 **없는 것**: P/D/R 칩 · 참고 판정 · 해설 · 강조 구간 · 「무엇이 달라졌나」. 강조 구간은 현행 규칙(제출 후에만 표시, `ScaleView:493`)과 맞춰 제출 후에 켠다.
- MJT2 자기 카드의 칩은 **현행 그대로**(CANONICAL이 「판단 전에도 표시」). 이 브리프는 그 결정을 건드리지 않는다. 다만 잠금 카드에서 칩을 빼면 학습자는 「무엇이 달랐는지」를 두 상황문에서 **읽어야** 한다 — 그것이 의도다.
- 모바일: 잠금 카드가 위, **펼침 기본**(shared_form) — 상황문 2문장이라 화면 1/3 이내. 판단 UI가 첫 화면에 안 들어오면 카드를 접힘 기본으로 바꾼다(구현 시 실측).

### 2-2. MJT2 판단 전 — **lookback 모드**(5건)

잠금 카드가 **접힘 기본**, 제목 한 줄만: `🔒 앞선 판단 돌아보기 · 친한 친구 · 내 선택 다소 적절` (펼치면 2-1과 같은 내용). 「같은 표현」을 암시하는 어떤 문구도 없다.

### 2-3. MJT2 제출 후 (현행 `FeedbackBox` 아래에 추가)

```
┌ 권장 답안 · 이 상황에서는 너무 직접적 ─────────────────────────────────────────┐  ← 현행
│ 첫 장면의 ‘你就把…吧’라는 직접적인 요청 방식과 동등한 권한·낮은 부담은 유지되지만 … │
└────────────────────────────────────────────────────────────────────────────────┘
┌ ⇄ 두 상황 나란히 보기 ─────────────────────────────────────────────────────────┐
│ ┌ 앞 상황 ────────────────────┐   ┌ 이 상황 ────────────────────┐              │
│ │ 매주 만나는 친한 친구         │   │ 몇 차례 자료를 주고받은 동료   │              │
│ │ [동등] [친밀] [부담 낮음]     │   │ [동등] [아는 사이] [부담 낮음] │              │
│ │ …▌你就把那个小卡牌游戏也带来吧▐│   │ …▌你就把那个链接再发我一次吧▐  │              │
│ │ 내 선택 다소 적절 · 참고 적절  │   │ 내 선택 ○○ · 참고 너무 직접적  │              │
│ └───────────────────────────────┘   └───────────────────────────────┘              │
│ 달라진 것은 관계의 거리입니다 — 매주 만나는 친한 친구 → 몇 차례 자료를 주고받은 동료. │
│ 같은 「你就把…吧」가 앞에서는 괜찮았고, 여기서는 조정이 필요합니다.                   │
└────────────────────────────────────────────────────────────────────────────────┘
```

- 문장 생성 규칙(새 콘텐츠 없음): 축 문구 = P→「지위·권한 관계」, D→「관계의 거리」, R→「부탁·사안의 부담」(두 축 이상이면 「관계의 거리와 부담」) · 전후 = 두 문항의 `relation_ko`(자연어) · 마지막 문장 = shared_form이면 「같은 「{명단의 구문}」가 앞에서는 {MJT1 참고 판정 요약}, 여기서는 {MJT2 참고 판정 라벨}」, lookback이면 **「표현도 달라졌습니다. 두 판단을 나란히 두고 보세요.」**로 끝내고 「같은」을 쓰지 않는다.
- 왜 「달라진 것」이 P/D/R 정답 노출이 아닌가: 제출 후이고, 두 카드의 칩은 현행에서도 이미 보이는 정보다. 새로 드러나는 것은 「그 차이 때문에 같은 형식의 기능이 달라졌다」는 연결뿐이다.
- 기존 MJT2 `explanation_ko`는 그대로 위 FeedbackBox에 남는다(w2-0처럼 MJT1을 직접 언급하는 해설은 자연히 연결되고, 아닌 해설도 충돌하지 않는다).
- 완료 화면 recap·MJT3 이후는 **불변**.

## 3. 표시 정책 — 15 shared_form / 5 lookback (사람이 정한 명단)

기계 판별 불가(틀 구문 「把…吧」는 공통 문자열 2자). 정책은 코드 명단 `contrastLensPolicy.ts`에 **scenario_id → {mode, sharedForm}**로 두고, 명단에 없으면 `lookback`.

| 모드 | 미션 | 명단에 적을 구문 |
|---|---|---|
| shared_form (15) | w2-0 「你就把…吧」 · w2-1 「把…吧」 · w3-0 「小小地感谢你一下」 · w3-1 「真的太感谢…我都不知道怎么谢你才好了」 · w4-0 「只说…这部分，简直完美」 · w4-1 「…得还行」 · w6-0 「不行。…」 · w6-1 「不行，…你还是找别人…吧」 · w9-1 「是我的一点小失误」 · w10-1 「(咱/我)们就定这个吧」 · w11-0 「也可以考虑…吧」 · w11-1 「我不同意…这样安排就是不合适」 · w12-1 「多少(让我)有点不方便」 · w13-0 「请你/请您…吧」 · w13-1 「帮我…吧」 | 그대로 |
| lookback (5) | **w5-0**(「告诉我来不来就行」↔「我就按你会来安排了」) · **w5-1**(「你看怎么样」↔「那就说定了」) · **w9-0**(「让你受累了」↔「只是给你添了点小麻烦」) · **w10-0**(「你看怎么样」↔「就这么定吧」) · **w12-0**(「问题都在你这边」↔「都是因为你…」 — 같은 전략이나 같은 형식은 아님) | — |

향후 authoring criterion(생성계약 §3, hard rule 아님): MJT1 X는 **같은 화행 + 가능한 한 같은 명제핵 + 같은 실현 구문**, 앵커에서 한 축만, 그 축을 `relation_ko`에 자연어로. 명단은 새 미션 승인 시 교수자 검수 한 줄로 채운다(P2: 다음 스키마 변경 때 `contrast_plan`으로 이사).

## 5. course-level 교체 — **3슬롯 최적안**

목표 셋(P 비대칭 확대 · R high 추가 · 같은 주 A/B 관계 대비)을 **각 교체 1건이 동시에** 만족하도록 고른다. 관계 대비가 없는 주가 정확히 w9·w11·w12 셋이므로, 이 세 주에서 **통역 미션(-1)** 하나씩을 새 코어로 만든다. 번역 미션(-0)은 연구자 판정 이력(11-0-1 · 12-0-1~4 · w9-0 round5)이 실려 있어 남긴다.

| 슬롯 | 현재 anchor | 새 anchor(안) | 장면 방향(자연어) | 동시에 만족 |
|---|---|---|---|---|
| **w9-1** 사과·통역 | equal / acquaintance / low | **speaker_lower / distant / high** | 처음 대면하는 상급자(외부 심사위원·거래처 임원)에게 중대한 실수(자료 누락으로 일정 차질)를 사과 | P↑ · D distant↑ · **R high** · A/B 대비 P·D·R |
| **w11-1** 반대·통역 | equal / acquaintance / mid | **speaker_lower / acquaintance / high** | 팀장의 결정(납기 앞당기기 등)에 부하가 근거를 들어 반대 — 11주 최고난도 화행에 맞음 | P↑ · **R high** · A/B 대비 P·R |
| **w12-1** 불만·통역 | equal / acquaintance / mid | **speaker_higher / acquaintance / high** | 담당자가 협력업체 담당자의 반복된 중대 오류(잘못된 납품)에 불만 제기 — 하향 방향(현재 1/20) | P↑(higher) · **R high** · A/B 대비 P·R |

변경 전 → 후(20 anchor):

| 축 | 전 | 후 |
|---|---|---|
| P | equal 16 · lower 3 · higher 1 | equal **13** · lower **5** · higher **2** |
| D | acquaintance 16 · close 2 · distant 2 | acquaintance 15 · close 2 · distant **3** |
| R | low 7 · mid 13 · high **0** | low 6 · mid 11 · high **3** |
| 주차 A/B 관계 대비(P 또는 D 다름) | 7/10 (w9·w11·w12 미달) | **10/10** |

- **3건으로 충분한 근거**: 세 문제의 교집합(대비 없는 주 3 = 교체 자리 3)이 정확히 맞아떨어진다. 남는 편향은 higher 2/20·close 2/20인데, 이건 「부족」이 아니라 「희소」이고 이번 목표에 없다. 6건 확대는 이 둘을 목표로 삼을 때만.
- 순서: 현재 20건 승인·편성은 **그대로** → 새 코어 3건(장면 근거 검사) → 미션 → v3 검수 → 승인 → 세 슬롯의 편성만 교체. 옛 3건은 승인된 채 미편성으로 남긴다(보관은 별도 승인).
- 통역 코어는 R25 `context_spec`(A/B/C 역할)과 1인칭 훈련 시점 규칙을 그대로 따른다. 새 authoring criterion(§3)도 이 3건부터 적용 — MJT1 X를 앵커와 같은 명제핵·같은 구문으로.

## 7. 수용 기준 (구현 완료 판정)

1. MJT2 판단 전 화면의 잠금 카드에 P/D/R 칩·참고 판정·변화축 문구가 **없다**(테스트).
2. MJT2 제출 후 두 상황과 변화축 문장이 보이고, lookback 5건에는 「같은」이 **없다**(테스트).
3. `responses`·DCT 저장 페이로드·content hash가 변경 전과 **동일**하다(스냅샷 테스트).
4. 20건 `inspect`·검수·승인 경로에 영향 0(기존 DB 계약 테스트 그대로 통과).
5. typecheck · vitest · build 통과, UI는 PC(lg↑)와 모바일 두 폭에서 확인.
