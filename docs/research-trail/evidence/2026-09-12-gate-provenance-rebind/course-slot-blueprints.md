# 3슬롯 새 코어 blueprint (생성 전 승인용) · 2026-09-12

대상 = **w9-1 · w11-1 · w12-1**(전부 통역 미션). 번역 미션(-0)은 연구자 판정 이력이 실려 있어 남긴다.
아직 코어·미션을 생성하지 않았다. 이 문서는 승인을 받기 위한 장면 설계안이다.

원칙: P/D/R 값을 맞추려고 역할을 만들지 않는다. **통번역 현장에서 실제로 흔한 관계**를 먼저 고르고,
그 관계가 자연스럽게 갖는 조건을 P/D/R로 적는다. 아래 세 장면은 모두 A(발화자)–B(청자)–C(학습자 통역사)
구조이며 현행 `context_spec.interpreter_role_contract`를 그대로 쓴다.

## 슬롯 1 · w9-1 사과 · 통역 · 한→중

| | 현재 | 새 안 |
|---|---|---|
| P/D/R | equal / acquaintance / low | **speaker_lower / distant / high** |
| 장면 | 동호회에서 몇 번 만난 회원에게 10분 지각 사과 | 아래 |

**장면(자연어)**: 한국 업체의 실무 담당자 A가, **오늘 처음 대면하는** 중국 거래처의 **생산 총괄 임원 B**에게,
자기 쪽 착오로 잘못된 사양서가 전달돼 **상대 생산 일정이 이틀 밀리고 재작업이 생긴 일**을 사과한다.
학습자 C가 통역한다.

- `relation_ko`: 거래처 생산 총괄 임원, 오늘 처음 대면
- `role_pair`: speaker_ko「사양서를 잘못 보낸 실무 담당자」 / addressee_ko「거래처 생산 총괄 임원」
- `standard_situation_code`: `work.apology_delivery_error.apology`
- **P가 lower인 이유**: 실무 담당자 → 상대사 결정권자. 수용 여부·후속 조치 판단이 B에게 있다. 직급을 억지로 만든 것이 아니라 사과 상황의 권한 구조 그대로다.
- **D가 distant인 이유**: 오늘 첫 대면. 사전 접촉은 문서뿐.
- **R이 high인 이유**: 이틀 지연 + 재작업 비용이 이미 발생했고 수리 제안이 필요하다.
- 초점 `apology_accountability_repair`와의 정합: 책임 인정 범위와 수리 제안이 관계 조건 때문에 크게 달라지는 전형적 자리다.
- **MJT1(X) 제안**: **D만** acquaintance로 — 「여러 차례 화상회의로 협의해 온 같은 임원」에게 같은 성격의 사과. 명제핵(사양서 착오 → 일정 지연 → 사과·수리)과 실현 형식을 유지하고 관계 거리만 바꾼다.

## 슬롯 2 · w11-1 반대·이견 제시 · 통역 · 한→중

| | 현재 | 새 안 |
|---|---|---|
| P/D/R | equal / acquaintance / mid | **speaker_lower / acquaintance / high** |
| 장면 | 교대 간격 연장에 반대 | 아래 |

**장면(자연어)**: 몇 차례 협업해 온 중국 파트너사의 **프로젝트 총괄 B**가 검수 기간을 일주일 단축하자고
제안하자, 한국 측 **실무 담당자 A**가 「그 기간으로는 확인해야 할 안전 항목을 끝낼 수 없다」는 근거를 들어
반대한다. 학습자 C가 통역한다.

- `relation_ko`: 파트너사 프로젝트 총괄, 몇 차례 함께 일한 사이
- `role_pair`: speaker_ko「검수를 맡은 실무 담당자」 / addressee_ko「파트너사 프로젝트 총괄」
- `standard_situation_code`: `work.schedule_compression.opposition`
- **P가 lower인 이유**: 일정 결정 권한이 총괄에게 있다. 반대는 그 권한을 향해 올라간다.
- **R이 high인 이유**: 이미 내려진 결정을 되돌려 달라는 요구이고, 안전 항목이 걸려 있다.
- 초점 `opposition_stance_mitigation`과의 정합: 완화가 지나치면 이견이 감춰지고, 부족하면 상급자의 결정을 정면 부정하게 된다 — 11주차가 「최고난도 단일 화행」인 이유가 그대로 드러난다.
- Yu(1999) 경계: 고P 상황에서 직접형이 반드시 부적절하다고 전제하지 않는다. 저자 caveat(화자 비우위 조건)와 후속 반론을 함께 두고 판정은 초점 정의에 맡긴다.
- **MJT1(X) 제안**: **R만** mid로 — 같은 총괄에게 「회의 자료 서식 변경안」에 반대. 사람·관계는 그대로 두고 사안의 무게만 낮춘다.

## 슬롯 3 · w12-1 불만 제기 · 통역 · 한→중

| | 현재 | 새 안 |
|---|---|---|
| P/D/R | equal / acquaintance / mid | **speaker_higher / acquaintance / high** |
| 장면 | 텐트를 정리하지 않고 반납한 일에 불만 | 아래 |

**장면(자연어)**: 한국 **발주사 담당자 A**가, 몇 차례 거래한 중국 **협력업체 담당자 B**에게, 같은 표기 오류가
**세 번째 반복돼** 재인쇄 비용과 납기 지연이 생긴 일에 불만을 제기하고 재발 방지를 요청한다. 학습자 C가 통역한다.

- `relation_ko`: 협력업체 담당자, 몇 차례 거래한 사이
- `role_pair`: speaker_ko「발주사 담당자」 / addressee_ko「협력업체 담당자」
- `standard_situation_code`: `work.repeated_defect.complaint`
- **P가 higher인 이유**: 계약상 발주–수주 관계의 권한 비대칭. 현재 20건 중 하향 방향은 1건뿐이라 스펙트럼의 빈칸이다.
- **R이 high인 이유**: 반복 발생 + 실제 비용 + 재발 방지 요구.
- 초점 `complaint_problem_accountability`와의 정합: **권한이 있을 때 문제를 어떻게 제기하는가**가 화용적으로 가장 어려운 자리다. 확인된 사실(세 번째 반복·비용)까지만 책임을 묶고 상대 개인을 몰아붙이지 않는 경계가 이 문항의 초점이 된다.
- ⚠️ 생성·검수 시 금지선: 지위를 근거로 한 위압적 표현을 「적정」으로 두지 않는다. 적정 대역은 사실 범위를 지키는 문제 제기이고, 비적정은 ①책임 과대 귀속 ②문제 불명확 두 방향으로 둔다(현행 대역 유지).
- **MJT1(X) 제안**: **P만** equal로 — 같은 종류의 표기 오류를 **같은 회사 다른 팀의 동등 직급 담당자**에게 제기. 명제핵과 실현 형식을 유지하고 권한 관계만 바꾼다.

## 생성 순서(승인 후)

1. 코어 3건 생성 → 장면 근거·의미 검사 → `save_generated_core`
2. 미션 3건 승격 → production gate
3. content-review v3 → 교수자 승인
4. **편성은 해당 세 슬롯만 교체**. 현행 20건의 승인·편성은 이 작업과 독립이다.
5. 옛 3건은 승인된 채 미편성으로 보존한다(보관은 별도 승인).

MJT1 authoring criterion(생성계약 §3 추가 예정, hard rule 아님): MJT1↔MJT2는 **같은 화행 + 가능한 한 유사한
명제핵 + 가능한 한 유사한 실현 형식**을 우선하고, 차이는 관계 조건에서 만든다. 이 3건부터 적용한다.
