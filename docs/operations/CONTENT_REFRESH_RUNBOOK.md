# PRAGMA 콘텐츠 refresh 실행 절차

## 현재 생성 콘텐츠의 지위 · 2026-08-05 사용자 확정

현재 DB에 존재하는 **모든 생성 코어와 학습 미션**은 프롬프트·문항·상황 시나리오·검수
체계를 개선하기 위한 개발·테스트 콘텐츠다. 특정 run이나 중→한 파일럿에만 적용되는 예외가
아니다. 현재 `reviewed` 상태인 콘텐츠도 그 시점의 개발·데모 사용 가능 판정일 뿐, LOCK 뒤
생산할 최종 정식 콘텐츠로 간주하지 않는다.

- 현재 콘텐츠는 파이프라인·UI·프롬프트 시험, 데모, DDR 반복 개발 증거로 사용할 수 있다.
- 현재 콘텐츠의 수량·상태를 최종 생산 코퍼스나 최종 내용 타당도 근거로 보고하지 않는다.
- 콘텐츠에 영향을 주는 조건을 모두 LOCK하기 전에는 구행을 고쳐 최종본으로 승격하지 않는다.
- LOCK 뒤 새 `content_release_id`와 새 run ID로 코어부터 미션까지 깨끗하게 전량 재생산하고,
  현재 세대와 섞지 않는다.
- 현재 생성물의 실제 삭제·비활성화는 참조 관계와 범위를 읽기 전용으로 확인하고 연구 증거를
  보존한 뒤 별도 파괴적 작업 승인으로 수행한다. 이 문서는 삭제 승인이 아니다.
- 사용자·인증 데이터, 원자료/source bank, LLM 호출 원장, 연구 기록, 학습자 로그의 보존·삭제는
  생성 콘텐츠와 별도 범위다. 명시적 승인 없이 함께 삭제하지 않는다.

LOCK 게이트에는 최소한 생성계약·스키마, 화행별 target feature와 대역 정의, P·D·R 및 통역
참여자 구조, 원문 길이·언어·방향 규칙, MPJ/DCT 문항 설계, 자동·사람 검수 기준,
프롬프트·모델·provenance, 생성 내용에 영향을 주는 학습자 흐름이 포함된다.

과거 30셀 방향 파일럿과 6셀 카나리는 당시 검증의 기록이다. 최종 콘텐츠 제작 전에 같은 실험을
자동 반복하는 요구사항으로 해석하지 않는다.

## 목적

두 정합성 결함을 해결한 뒤 선정 모델을 적용하고 최종 수업 콘텐츠 제작과 운영 동결을 끝낸다.
현재 후보 ID는 `supabase/functions/_shared/contentRelease.ts`를 따른다. 후보 버전 갱신은
최종 LOCK 선언이 아니며, 기존 콘텐츠의 일괄 재생성이나 삭제 승인을 뜻하지 않는다.

선정 결정은 Astra Medium·원본 프롬프트 유지·비동기 생성, Opus 기본 독립 검토·Fable 선택 검토다.
선정 사실과 운영 기본값 적용은 구분한다. 추가 모델 비교나 프롬프트 축약 실험은 후순위다.
근거: `docs/dev-log/2026-09-08-freeze-readiness-audit.md`.

## 실행 순서

1. 기존 문항 계약 호환과 후보·해설 정합성 수정을 완료한다. 구버전 검사 불일치를 콘텐츠 불량으로
   간주하지 않는다. 승인 이력·연구 증거·학습자 로그를 보존한다.
2. 선정 모델의 실제 요청 설정, 프롬프트 버전·해시와 문항 계약을 고정하고 최종 제작 release/run을 정한다.
3. 세 교과목의 확정 주차에 필요한 콘텐츠를 코어부터 제작한다. 정규 화행 주차는 번역 1·통역 1이며
   13주 선택 화행도 포함한다. 후보 수량과 최종 승인 수량을 따로 기록한다.
4. `focused_v1`에 따라 규칙·일치하는 저장 품질점검을 재사용한다. 중대·불확실 쟁점과 변경분을
   교수자가 판단하고 승인한다. 추가 독립 모델 검토는 필요한 쟁점에만 선택 적용한다.
5. 승인한 미션을 편성하고 실제 사용할 주차 자료를 확정한다. `generated`를 자동 승인하지 않는다.
6. 최종 release로 번역·통역의 실제 학습 수행, 피드백·수정·완료 저장·재조회와 저장 실패 복구를
   확인한다. 동일 버전에서 이미 확보한 적합한 증거는 재사용하고 남은 경계만 확인한다.

## 보존 원칙

- `learner_mission_logs`는 생성 콘텐츠와 별도 연구 기록이다. 기본적으로 삭제하지 않는다.
- `assessment_form_items`가 참조하는 `experiment_locked` 시나리오는 자동 삭제하지 않는다.
- `package_items`와 `curriculum_week_scenarios`는 새 콘텐츠 ID로 재편성하기 전까지
  임의로 연결을 옮기지 않는다.
- 구버전 행을 수작업으로 신버전처럼 고치지 않는다. 새 후보로 재생성한다.
- 카나리 실행 중 출력은 `.tmp/content-canary`를 사용하되, dev-log나 evidence index에서
  근거로 채택한 JSON은 `docs/research-trail/evidence/<날짜>-content-canary/`로 복사하고
  SHA-256을 기록한 뒤에만 임시 원본을 정리한다.

## 최종 동결 조건

- 모델·프롬프트·계약과 최종 release/run 식별자를 기록했다.
- 세 교과목의 필수 미션·수업 자료가 최종 승인·편성과 일치한다.
- 최종 콘텐츠에서 필요한 번역·통역 학습 흐름과 완료 저장·실패 복구의 확인 근거가 있다.
- `지금 반드시 해결` 결함이 없고, 남은 권장·후속 항목은 동결을 막는지 명시적으로 분류했다.
- 사용자 최종 동결 결정과 증거를 기록한다. 이후 학습 내용·판정에 영향을 주는 변경만 새 버전과
  해당 변경 범위의 재검증을 요구한다. 이 절차를 추가 실험·반복 전수 검토의 근거로 사용하지 않는다.
