날짜의 최신값 또는 자동으로 제공된 요약으로 현행본을 추측하지 않는다.

## 대외·내부 용어 규칙

**미션 구조 표준 표현** — 「판단 → 산출」 대비가 구조 명칭에서도 드러나게 한다.

- 정식 서술: **한 개 학습 미션은 판단형 MJT 5문항과 DCT형 통번역 산출 과제 1개로 구성된다.**
- 표·도식·간결 표기: **판단형 MJT 5문항 → DCT형 통번역 산출 1과제**
- MJT는 개별 판단 응답 단위이므로 `5문항`, DCT형 통번역 산출은 새 출발텍스트를 직접
  번역·통역하는 수행 단위이므로 `1과제`로 센다.
- 약칭: 간결하게 지칭할 때는 `MJT5+DCT1`을 쓸 수 있다(2026-09-16 확인). 정식 서술과
  표·도식 캡션에는 위 표준 표현을 쓴다. `MJT5`가 MJT 5번 문항과 겹치므로, 문항을 세는
  맥락에서는 약칭을 피하고 표준 표현을 쓴다.
- ⛔ `MJT 다섯 판단 활동 + DCT형 통번역 산출 과제 1회` ·
  `MJT 5문항 + DCT형 통번역 산출 1과제`는 쓰지 않는다.

용어는 세 층으로 구분한다.

- **A. 연구·설계 문서(논문·README·도식·교수자 자료)** — 정식 용어는
  **판단형 MJT(Metapragmatic Judgement Task)**와
  **DCT형 통번역 산출 과제**(DCT: Discourse Completion Task)다.
  필요 시 개별 문항을 `MJT1`~`MJT5`로 식별한다.
- **B. 학습자 화면** — `MJT`·`DCT` 약어를 직접 노출하지 않는다(2026-09-16 연구자 결정).
  학술적 과제 유형명보다 「지금 무엇을 해야 하는가」가 바로 보이는 **행동 중심 명칭**을
  우선하되, 아래 표로 연구 문서의 구조와 1:1 대응을 유지한다.

  | 구조 | 코드 유형 (mission_v6) | 학습자 화면 명칭 |
  | --- | --- | --- |
  | MJT1 | scale4 | 상황에 맞는지 판단하기 |
  | MJT2 | scale4 + reason_choice | 판단하고 이유 고르기 |
  | MJT3 | fix_choice | 고친 표현 고르기 |
  | MJT4 | free_correction | 직접 고치고 비교하기 |
  | MJT5 | multi_judge | 여러 표현 비교하기 |
  | DCT | dct | 직접 번역하기 / 직접 통역하기 |

  `mission_v6`의 제출 화면 제시 순서는 **MJT1 → MJT2 → MJT5 → MJT3 → MJT4 → DCT형 통번역 과제**다(2026-09-26 사용자 지시).
  위 표와 저장 데이터의 문항 ID는 유지한다. 화면 순번으로 응답 ID를 다시 부여하지 않으며, 핵심 정리는 활동 라벨과 원래 문항 ID로 연결한다.

- **C. 코드·DB·JSON·프롬프트** — 기존 내부 식별자(`mpj_items`, `mpj_response_v2`,
  `MPJ_TYPE_ORDER_*` 등)는 호환성을 위해 유지한다. 내부 식별자를 대외 학술 용어에 맞추기 위해
  전면 rename하지 않고, 내부 식별자를 대외 과업명으로 사용하지도 않는다.
- **연구 문서용 세부 한국어 활동명은 이 문서에서 확정하지 않는다.** 이 문서가 고정하는 것은
  MJT 번호 · `mission_v6` 코드 유형 · 학습자 화면 명칭의 대응뿐이다. 논문에서 각 MJT를 어떤
  한국어 활동명으로 부를지는 논문 용어대장과 제3·4·5장 정렬에서 별도로 확정한다 —
  **앱 정본이 논문 용어를 선점하지 않는다.**
- 역사 기록은 당시 표기를 보존할 수 있지만, 현행 정본과 새 문서의 대외 서술은 위 규칙으로
  통일한다(화면은 B의 행동 중심 명칭).
- 기간 추정이나 감사 품질 점수는 정본에 두지 않는다. 완료 여부는 기능·콘텐츠·실행 증거의 명시적
  게이트로만 판정한다.

## 최신 학습설계와 운영 구현의 구분

2026-09-14 사용자 결정으로 현재 구현된 `mission_v6`를 정식 mission format으로 채택했다
(DEC-20260914-02). 요청 미션의 순서는 `scale4 → scale4 → fix_choice → free_correction → multi_judge → DCT`다.
MJT 5개·MJT3 선택지 3개·MJT5 후보 4개는 이번 버전의 구현 계약이며 화용교육의 보편적 최적값으로
해석하지 않는다. MJT4는 자유교정문, MJT5는 후보별 독립 band 판단을 수집한다.
DEC-20260914-03은 MJT2 판단 확정 뒤 inline reason-choice 1회와 MJT4 피드백의 선택적 contrast 1회를
추가한다. 문항 수는 유지하며 저작 원칙과 대표 1건의 구현 범위를 구별한다.
정식 format 채택과 정상 승인·편성·DB 저장 연결 완료는 구별한다. 현재 연결 상태와 검증 근거는
`docs/dev-log/2026-09-14-mission-v6-implementation-review.md`의 채택 후속 절을 따른다.

아래 두 문단의 생성·문항·대역 계약은 **기존 `mission_v5`에 한정**하며 v6에 전용하지 않는다.
기존 소스의 `mission_v5` 생성·검사·러너 계약은 **판단형 MJT 5문항 + DCT형 통번역 산출 1과제**에 동기화됐고
운영 DB·Edge·Railway에 반영됐다. 신규 생성 순서는
`scale4 → judge3 → fix_choice → reason → multi_judge`이고, 네이티브 응답은
`mpj_response_v2`로 저장한다. 과거 `mission_v5` MJT4 행은 legacy 구현으로 읽기 호환하며
자동 변환하지 않는다. 네이티브 MJT5의 실생성·저장·교수자 검수·학습자 종단은 별도 확인 대상이다.

현행 네이티브 학습자 계약은 상황문을 140자 이내의 정확히 두 문장으로 만들고 MJT·DCT의
`preceding_turn`을 null로 둔다. MJT3은 수정안 3개 중 권장안 1개를 고르고, MJT5는
`적정 2·조정 필요 2`의 후보 4개를 비교하고 각 범주에서 하나씩 선택한다. 내부 BEST/WORST 값은
보존하되 화면에서는 적절한 표현·조정할 표현으로 안내한다. 적정 후보 사이에 유일한 1등을 요구하지 않는다.
저장된 `contrast_plan_v1`의 공통 Anchor A와 대역 계약은 프롬프트 버전이 바뀌어도 보존한다.
직접 산출 전 recap은 문항에서 실제로 본
표현 한 조각과 근거 한 개를 짧게 연결한다. 화면 폭에 따라 줄바꿈하며 말줄임으로 근거를 숨기지
않는다. 학습자용 P/D/R 칩은 원시 저장 코드를 노출하지
않고 관계·거리·부담을 명시적으로 확인하는 교수 단서로 판단 전에도 표시한다.

화행 학습 주차의 수업 단위는 **화행 1개 + 완전한 미션 2개**다(각 미션 = 판단형 MJT 5문항 → DCT형 통번역 산출 1과제).
주차와 두 미션의 학습목표는 특정 `target_feature` 하나가 아니라 같은 화행의 핵심 화용 판단
묶음이다. `target_feature`는 문항 생성·진단·피드백·근거 추적을 위한 내부 태그로만 사용하며,
주차 또는 미션 전체의 목표로 표시하지 않는다. 수업시간, 주당 수업 횟수와 시간 배분은 앱 계약과
논문 주장 범위에 넣지 않는다.

두 미션은 같은 화행·수준·언어방향을 따르는 독립적인 완전 미션이다. 2026-09-10 사용자 확정에 따라
교과목은 번역(번역 2개)·통번역 반반(번역 1개·통역 1개)·통역(통역 2개)으로 구분한다.
시나리오 생성 수량·비율은 재료 제작 설정이며 교과목 유형과 분리한다. 기존 교과목의 저장 유형은 자동 변경하지 않는다.
과거 6/6·9/3 주수 배분은 운영 정책으로 사용하지 않는다. 미션 2는 미션 1의
사실상 복제본이 아닌 새로운 상황을 제공한다. 둘 사이의 변화축이나 진단차원 coverage를 표준 생성·
검수·편성 계약으로 만들지 않으며, 특정 맥락 변수의 효과를 비교하는 실험쌍으로 해석하지 않는다.
기존 `speech_act_ab_v1` 필드와 검사는 역사 데이터 호환용으로 남길 수 있지만 새 표준 편성은 이에
의존하거나 값을 새로 작성하지 않는다.

승인된 경험 구조는 다음과 같다.

- 화행 학습 주차에는 같은 화행·수준·언어방향의 완전한 미션 두 개를 교과목 유형에 맞게 편성한다.
  통번역 반반에서는 번역 미션과 통역 미션을 순서대로 수행한다.
  13주도 교강사가 기학습 화행 하나를 고르는 `선택 화행 집중 보완`으로 같은 단위를 따른다.
  고부담으로 한정하지 않으며, 주차별 중심 질문은 상황·P·D·R에 따라 조정하는 수업 안내다.
  중심 질문을 생성·검수 통과 조건이나 평가 준거로 사용하지 않는다.
  7·14주 메타화용 토론은 누적 수행 기록을 활용하며 새 미션을 배정하지 않는다. 번역과 통역은 각 역할·
  매체에 맞는 독립적인 상황·원문을 사용하며, 두 미션의 시간·난도가 같거나 1:1이 최적이라는
  연구 주장을 하지 않는다. 과거 Scope Lock v1 배치 생성 manifest는 역사적 수량·인덱스 호환용이다.
- 미션 1과 미션 2는 각각 한 화면의 미션 안내에서 판단 연습과 직접 통번역의 순서, 직접 옮길 상황과 단서를 확인한다(DEC-20260910-08).
- 학습자 주차 화면은 학습목표·두 미션의 연결 안내·유형별 시작 버튼 하나씩·수업자료 링크로 구성한다.
  중심 질문은 주차 화면에서 제거하고 교강사가 구두로 안내한다. 실제 미션의 DCT 바로가기는
  제공하지 않으며, 직접 이동은 저장 없는 개발자 미리보기에서만 사용한다(DEC-20260910-07).
- 통역 장면은 1인칭 훈련 시점과 구체적인 관계·사건으로 간결하게 서술한다. 통역사 C의
  현장 배치·역할 소개를 강제하지 않으며 원문 충실성과 원문 인물 간 P/D/R은 유지한다.
  인물·용건·권한·신뢰·채널의 개연성을 생성·의미 검수에서 확인한다(DEC-20260907-02).
- 미션 2는 미션 1과 동일하거나 공백·문장부호만 바꾼 장면을 사용하지 않는다. 의미상 복제 여부의
  최종 판단은 교수자 검수에 맡기며 별도의 의미 유사도·변화축 시스템을 만들지 않는다.
- 두 미션은 같은 화행을 다른 상황에서 두 번 완전하게 수행할 기회를 제공한다. 이를 조건 통제,
  맥락 변수 효과, 전이 또는 학습효과 입증으로 표현하지 않는다.
- 상단 진행은 `미션 안내 → 표현 판단 → 직접 옮기기 → 피드백 → 다듬기`의 조용한 5단
  horizontal macro progress를 사용한다. 표현 판단 내부에서는 `표현 판단 n/5`로 표시한다.
- AI 피드백은 해당 DCT 최초안 제출 뒤에만 요청한다. 수정 권고 뒤 학습자는 수정안을
  확정하거나 이의 제기에 근거를 남기고 최초안을 최종안으로 유지할 수 있으며, AI 판정과
  학습자 최종 결정은 함께 보존한다.
- 피드백은 한 화면에서 우선 점검할 한 기준을 한 번 표시한다. 완료 화면의 최초안·최종안·기억할
  한 가지와 최초안 AI 피드백을 구분한다. 수정 여부를 개선 판정으로, AI 설명을 학습자 이유로 표시하지 않는다.
- Judge3 대역은 과소→적정→과잉의 의미 순서를 유지하되, 가운데 선택만 안전한 정답처럼
  보이지 않도록 세 선택지를 같은 시각적 무게와 설명 밀도로 제시한다.

실제 구조·문서가 충돌하면 충돌한 파일과 코드·테스트 근거를 함께 보고하고 조용히 어느 한쪽을
최신으로 간주하지 않는다.

## 2층 기록 규칙

1. 현행 정본은 날짜 없는 파일 하나를 제자리에서 수정한다.
2. 변경 이력은 Git이 보존한다.
3. 사람이 읽고 인용할 이정표가 필요할 때만 `history/PRAGMA_자료명_YYYY-MM-DD.md`를 발행한다.
4. 이정표 스냅숏은 발행 커밋 이후 수정하지 않는다. 정정은 새 날짜 스냅숏으로 발행한다.
5. `history/legacy/`는 이 규칙 도입 전에 날짜를 붙여 계속 수정하던 판본이다. 파일명의 날짜가
   정확한 동결 시점을 보장하지 않으므로, 특정 시점의 내용은 Git 커밋으로 확인한다.
6. `history/`와 `history/legacy/`의 파일은 현재 구현 근거로 사용하지 않는다.

이 규칙은 생성계약 3종에만 한정하지 않는다. `fullworkflow01~10`처럼 일련번호·날짜로 누적된
자료도 먼저 `현행 후보 / 역사 자료 / 판정 필요`로 목록화한 뒤 같은 2층 구조를 적용한다.
판정 전에는 파일을 삭제하거나 이름만으로 최신본을 확정하지 않는다.

## 논문 저장소와의 관계

논문 저장소의 `01_정본/00_정본목록.md`는 교차 저장소의 시작 경로를 알려주는 목록이다.
앱 구현 중에는 이 파일과 앱의 세 경로가 일치하는지 대조하되, 불일치하면 한쪽을 추측으로
고치지 않고 보고한다. 앱 저장소의 코드·테스트·계약 변경은 이 저장소 안에서 함께 검증한다.
