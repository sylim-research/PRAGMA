# 콘텐츠 품질 관리 — 단계별로 누가 무엇을 보는가

<sub>2026년 10월 기준 · 관리자 대시보드 「콘텐츠 품질 관리」 카드 4개와 같은 순서</sub>

PRAGMA의 학습 콘텐츠는 만들어진 뒤 네 단계를 거쳐 수업에 쓰입니다.

| 단계 | 맡는 쪽 | 하는 일 |
|---|---|---|
| 1. 학습 콘텐츠 생성 | Gemini 3.1 Pro (중국어 원문만 GPT-6 Astra) | 시나리오와 학습 미션을 만든다 |
| 2. 자동 규칙 점검 | 규칙 점검 코드 · **AI 없음** | 형식·구성·언어 방향·생성 기록을 세고 대조한다 |
| 3. AI 품질 심사 | GPT-6 Astra | 의미·화행·자연성·해설을 읽고 판단한다 |
| 4. 교수자 최종 승인 | 교수자 | 학습자 화면 그대로 확인하고 사용 여부를 정한다 |

---

## 1. 학습 콘텐츠 생성

- **기본은 Gemini 3.1 Pro입니다.** 학습 미션은 한→중이든 중→한이든 모두 Gemini가 만듭니다.
- **예외는 중→한 시나리오의 중국어 원문 하나입니다.** 중→한에서는 이 원문이 학습자가 번역·통역할 출발 텍스트이므로 자연스러운 중국어여야 합니다. 그래서 원문이 들어가는 시나리오 뼈대만 GPT-6 Astra가 씁니다(2026-10-26부터).
- 「중→한」을 따로 적는 것은 한→중이 기본이라는 뜻이 아닙니다. 「Gemini가 기본, 중국어 원문만 Astra」라는 뜻입니다.

## 2. 자동 규칙 점검 — AI 없이 코드가 세고 대조한다

이 단계는 모델을 부르지 않습니다. PRAGMA 안에 직접 써 넣은 점검 코드가 정해진 규칙대로 필드를 확인하고, 개수를 세고, 문자열을 대조합니다.

- **돈이 들지 않고, 같은 콘텐츠에는 늘 같은 결과를 냅니다.**
- **의미는 판단하지 않습니다.** 「이 거절이 관계에 맞게 공손한가」는 3단계 AI 품질 심사와 교수자의 몫입니다.
- **어디에 있나:** 규칙 본문은 [`src/lib/pragma/missionRules.ts`](../src/lib/pragma/missionRules.ts), 규칙을 한 번에 돌리는 파일은 [`src/lib/pragma/contentReviewDomain.ts`](../src/lib/pragma/contentReviewDomain.ts)입니다. 교수자가 검수를 돌리면 같은 코드가 Supabase 서버의 검토 기능(`content-review`)에서 실행됩니다.
- **관리자 화면:** 「생성계약·운영 프롬프트」 화면의 「품질관리 구조 → 규칙 보기」에서 규칙 전체를 볼 수 있습니다.

### 결과는 두 가지로 나뉜다

- **불통과(fail):** 구조나 계약을 어긴 것입니다. 고쳐서 다시 점검하기 전에는 AI 품질 심사로 넘어가지 않습니다.
- **확인 신호(warning):** 글자 패턴이나 개수만으로는 확정할 수 없는 위험입니다. 저장을 막지 않고, 교수자가 실제 문제인지 판단하도록 넘깁니다. 결과 화면에는 「정규식·집계 기반 신호이며 의미 판단이 아닙니다」라고 함께 표시됩니다.

### 지금 실제로 실행되는 규칙 — 17개 + 문항 수 점검

규칙 번호(R1~R33)는 연구·운영 기록의 추적 번호라 다시 쓰지 않습니다. 아래는 현행 시나리오와 학습 미션에 실제로 실행되는 규칙만 추렸습니다.

**시나리오에 실행 (9개)**

| 번호 | 무엇을 확인하나 | 결과 |
|---|---|---|
| R1c | 시나리오 형식이 맞는지, 주제·하위 주제·영역(일상/업무 등) 조합이 허용된 것인지 | 불통과 |
| R9 | 상황·관계·해설에 「중국인은…」「한국인은…」처럼 국가 단위로 일반화하는 표현이 있는지 | 확인 신호 |
| R10 | 요청한 언어 방향과 데이터의 방향이 같은지, 원문·참고 표현이 맞는 문자(한글/한자)로 쓰였는지. 중국어 산출에 한글이 섞이면 불통과 | 불통과·확인 신호 |
| R16 | 번역/통역 요청과 글/말 매체가 맞는지. 상황문이 반대 수행 장면을 적은 것처럼 보이면 신호 | 불통과·확인 신호 |
| R17 | 산업 분야가 업무 영역에서만 지정됐는지 | 불통과 |
| R25 | 새 시나리오에 서버가 넣는 상황 설정과 통역 역할(A·B·C, 관계·거리·부담) 값이 있는지 | 불통과 |
| R26 | 업무 시나리오에 지정 산업을 보여 주는 어휘 단서가 실제로 있는지 | 확인 신호 |
| R29 | 원문 분량이 수준별 상한을 넘지 않는지(넘으면 불통과), 하한·문장 수(2~4문장)를 지키는지, 화용 집중 구간이 원문 안에 정확히 있는지 | 불통과·확인 신호 |
| R30 | 학습자에게 보이는 상황문이 정중성·완화·선택권·강도 같은 답의 평가 기준을 미리 드러내는지 | 확인 신호 |

| | 초중급 | 중급 | 고급 |
|---|---|---|---|
| 번역 | 45~65 | 60~85 | 80~110 |
| 통역 | 30~45 | 40~60 | 55~85 |

**학습 미션에 실행 (12개)**

| 번호 | 무엇을 확인하나 | 결과 |
|---|---|---|
| R1 | 미션 형식이 맞는지. 틀리면 나머지 규칙은 실행하지 않는다 | 불통과 |

| R32 | 출처를 밝히지 못한 문항 기록이 20%를 넘는지 — 넘으면 교수자가 먼저 볼 신호 | 확인 신호 |

시나리오와 미션 양쪽에 도는 R9·R10·R16·R30을 한 번씩 세면 17개입니다.

**문항 수 점검:** 현행 기준인 MJT 5문항 + DCT 1과제를 갖췄는지도 함께 확인합니다.

### 이전 미션 형식에만 쓰는 규칙 — 16개

R2~R8, R11, R12, R14, R18, R19, R21, R27, R28, R33은 이전 미션 형식(mission_v5)에 쓰던 규칙입니다. 판정 라벨의 개수와 분포, 수정안 개수, 문항 사이 중복, 상황문 복사 관계, 채널(이메일·메신저/대면·전화) 매핑 등을 봅니다. 현행 미션에는 자동 적용하지 않고, 기록 보존을 위해 코드에 남겨 둡니다. R22는 2026-08-09에 폐기했고, 어휘 수준 참고는 HSK 3.0 어휘 대조가 따로 맡습니다.

### 확인 필요

- 각 규칙이 생성계약의 어느 조항에서 왔는지 일대일 대응표는 아직 만들지 않았습니다.
- 「규칙 보기」의 설명 문안은 「연구자 확인 전」 상태입니다.

## 3. AI 품질 심사 — GPT-6 Astra

규칙 점검을 통과한 콘텐츠를 GPT-6 Astra가 읽고 판단합니다. 한 번의 심사에서 다음을 함께 봅니다.

- 원문의 의미가 보존됐는지
- 화행·관계·거리·부담 설정이 타당한지
- 판정과 해설이 서로 맞는지
- **한중 양방향 언어 자연성** — 중국어 표현도 여기서 점검합니다
- 수준에 맞는지, 문화를 일반화하지 않는지, 정답이 하나로만 굳지 않는지

## 4. 교수자 최종 승인

교수자는 학습자에게 보일 장면과 문항을 학습자 화면 그대로 확인합니다. 그리고 규칙 점검의 확인 신호와 AI 심사 의견을 보고 수정·보류·사용을 정합니다. AI 의견은 참고 자료이고, 사용 여부는 교수자가 결정합니다.

## 중국어 표현 검토는 어디로 갔나

- 2026-10-10에 다른 회사 모델로 중국어만 한 번 더 보는 선택 단계를 두었습니다. 2026-10-26부터는 3단계와 같은 GPT-6 Astra가 이 단계를 맡게 되었습니다.
- 2026-10-29 연구자 결정으로 이 단계를 앱의 흐름에서 뺐습니다. 중국어 표현은 3단계 AI 품질 심사가 함께 봅니다. 필요할 때는 연구자가 앱 밖에서, 공개 가능한 문장만 골라 따로 참고 검토합니다. 이 검토는 승인 조건이 아닙니다.
- 앱 안의 선택 기능 코드는 지우지 않았고, 대시보드에서만 뺐습니다.
