보존하며, 작업 목록의 `결과 이어받기`로 기존 품질점검·초안 저장을 진행한다. 일시적 오류는 저장된

생성 완료 표시는 교수자 검수·승인 완료 표시와 구분한다.

## 1. 관리자 구조의 목적

관리자 화면은 단순 콘텐츠 CRUD가 아니라 다음 체인을 운영하는 도구다.

```text
생성 조건 통제
→ 코어 생성
→ 규칙 기반 검사
→ Full Mission 승격
→ 교수자 검수·승인
→ 15주 편성·게시
→ 학습자 실행
→ 수행·이견·수정 기록 확인
```

AI는 초안을 만들고 교수자가 교육용 공개 여부를 결정한다. 규칙 기반 검사와 프롬프트 통제 기반
검토는 교수자 검수·승인을 대체하지 않는다.

## 3. 코어 생성

### 3.1 개별 생성

관리자는 최소 다음 조건을 통제한다.

- 화행
- 학습 지원 수준
- 번역·통역 모드
- 언어 방향
- domain
- theme/topic
- P·D·R
- 직장 장면의 industry와 business function

topic은 사건 시드이고 P·D·R보다 우선하지 않는다. 조건에 맞는 topic이 없으면 조용히 다른 화행의 topic으로 폴백하지 않고 생성 계획 단계에서 실패한다.
industry는 업무가 일어나는 분야, business function은 그 분야 안에서 수행하는 실제 직무다.
직무 기능은 해외영업·거래, 마케팅·홍보, 고객·파트너 응대, 구매·물류, 프로젝트 운영,
번역·로컬라이제이션, 대외협력·제휴의 대표 7개를 생성 UI에 노출한다.
대량 생성 계획은 각 수준 안의 일상·학업·직장 건수를 1:1:1로 유지하고, 직장 셀에서
대표 직무 7개가 순환하도록 계획 단계에서 검산한다.

### 3.2 strict Structured Outputs

현재 코어 생성은 다음 계약을 사용한다.

- strict JSON Schema (필수 필드는 생성계약 정본이 정의)
- 현재 모델·프롬프트 버전·코어 표면 해시는 **프롬프트·지문 관리 화면과
  `docs/research-trail/04_evidence_index.md`가 정본**이다.
  이 문서에 숫자를 복사해 두지 않는다.

strict 통과는 API·구조 호환성 확인이다. 중국어 자연성, 장면 타당성, 지시 대상, 화행 적절성은
규칙 기반 검사·프롬프트 통제 기반 검토·교수자 검수로 별도 확인한다.

### 3.3 저장과 provenance

저장 행은 최소 다음을 추적한다.

- generation run
- model/provider
- prompt version
- `prompt_snapshot_hash`
- schema version
- 생성 조건
- 규칙 기반 검사 결과

Edge가 계산한 hash를 프론트가 다시 계산하거나 변형하지 않는다.

### 3.4 HSK 3.0 참고 데이터 운영

`/admin/corpus`의 주목적은 내부 적재 구조를 전시하는 것이 아니라, HSK 어휘가 PRAGMA의
학습 콘텐츠 제작·검수에 어디에서 어떻게 쓰이는지를 설명하는 것이다.

- 화면의 첫 관계는 `PRAGMA 수준 → HSK 어휘 참고 범위 → 교수자 판단`이다. PRAGMA가 학습
  수준을 설계하고 HSK는 생성된 중국어의 어휘 난이도를 대조하는 외부 참고 기준이며, 자동 대조에서
  바로 확인되지 않은 항목의 최종 판단은 교수자가 한다. 세 요소를 독립 KPI처럼 표시하지 않는다.
- 한→중은 생성된 중국어 예시·선택지·참고안을, 중→한은 학습자에게 제시할 중국어 원문을
  수준별 누적 어휘 범위와 대조한다. 번역·통역 모드는 HSK 기준을 바꾸는 별도 적용축은 아니지만,
  실제 점검 사례를 식별하는 메타데이터로 수준·언어 방향·화행과 함께 표시한다.
- 화면명은 `HSK 3.0 어휘 기준·점검`으로 한다. `0 · 설계 기준` 메뉴의 정보 순서는
  `탑재 데이터와 PRAGMA 수준 대응 → HSK 점검 방식 → 가장 최근 실제 점검 기록`으로 한다. 최근
  기록은 결과 수치에 앞서 콘텐츠 제목·화행·수준·모드·언어 방향·건수를 식별한다.
- LOCK 전 층화 시험 30건은 장치 기능 검증 증거이므로 주 화면에서 제거하고 research trail에만
  보존한다. 폐기 예정 테스트 콘텐츠의 30/30 저장 결과나 평균 일치율을 실제 콘텐츠의 점검
  결과와 같은 화면에서 운영 지표처럼 표시하지 않는다. `PRAGMA 수준 선택 → HSK 누적 범위 대조 →
  검수 후보를 교수자에게 전달` 절차는 HSK 점검 방식 영역에서 설명한다.
- 운영 DB 영역은 페이지 첫 섹션에 두고 `PRAGMA 입문 = HSK 1–4급 누적 2,000개`,
  `PRAGMA 중급 = HSK 1–5급 누적 3,600개`, `PRAGMA 고급 = HSK 1–6급 누적 5,400개`를
  각각 같은 카드 안에서 직접 결합한다. 위치만으로 대응을 암시하지 않는다. 전체 DB 연결 수량
  11,000개는 헤더에 보존하되, 각 카드 하단에는 해당 단계의 신규 구성만 보조 설명으로 둔다
  (`1–4급 300·200·500·1,000`, `5급 1,600 추가`, `6급 1,800 추가`). 같은 대응을 다시 뒤집어
  보여 주던 HSK 구간 카드·상한 막대는 제거한다. 현재 사용하지 않는 7–9급 구간, 대표 어휘와
  펼치기는 기본 화면에서 제외한다.
- 원시 미일치 토큰은 corpus 현황에서 노출하지 않고 통합 검수 상세에서만 확인한다. 최근 기록이
  없을 때는 가짜 숫자 대신 향후 표시 필드와 통합 검수 연결을 보여 준다. 기본 본문 글자는
  논문 캡처 판독성을 위해 12px 미만으로 내리지 않는다.
- 결과 영역은 `가장 최근 점검 기록`으로 표기하고 실제 콘텐츠 제목과 `화행·PRAGMA 수준·모드·언어
  방향·학습 미션 1건`을 먼저 표시한다. 이어 `점검 대상 1건 → 문장부호·공백을 제외하고 중복을
  제거한 중국어 단어 단위 49개 → HSK 데이터셋에서 정확히 확인 35개·교수자 검수 후보 14개`를
  세 단계로 보여 준다. 35/49 비율 막대와 71%는 통과율로 오독돼 표시하지 않는다. 남은 14개는
  자동 오류가 아니며 고유명사·전문용어·분절 결과일 수 있음을 함께 표시한다.
- HSK 점검의 상세 계산 방식은 데이터와 최근 결과의 소유 화면인 `/admin/corpus`에 둔다. 중국어
  어휘 단위 추출, PRAGMA 수준별 누적 범위, DB 표제어 정확 일치, 결과·정책 버전 저장의 세 단계를
  보여 준다. 정확 일치는 재현 가능한 계산 방식일 뿐 목록 밖 어휘를 금지하는 허용 목록 규칙이나
  수준 적합 인증이 아니다. 콘텐츠 전체가 수준에 비해 너무 쉽거나 어려운지와 교체·재생성 필요
  여부는 이 검사에서 판정하지 않고 교수자 검수·승인에 남긴다.
- 공식 시험대강 title·publisher·발행/시행 version·URL은 페이지 최하단의 근거 줄에 둔다.
  현재 기능에 사용하지 않는 HSK 주제 427행은 기본 화면에서 제외하되 데이터와 연구 기록에는
  보존한다. manifest·hash 등 상세 provenance도 데이터 정본에서 유지한다.

schema·seed가 없거나 일부만 적용된 경우 데이터가 연결됐다고 표시하지 않는다. 코드에 audit 함수가
존재하는 것과 실제 생성 결과에 점검 기록이 남은 것도 구분한다. 검수 화면의 HSK 일치율과 범위 밖
후보는 참고 표시이며 rapid-review·reviewed 게이트를 바꾸지 않는다.

## 4. 배치 운영

### 4.1 층위

```text
243 구인셀 = 화행 9 × P 3 × D 3 × R 3
54 전달셀 = 화행 9 × 수준 3 × 모드 2
495 계획 = 243 구인셀을 채우면서 전달·편성 주변분포를 확보
```

서로 다른 층위를 곱해 총조합 수를 부풀리지 않는다.

### 4.2 실행 게이트

- blocking missing topic이 있으면 실행 버튼을 막는다.
- 계획 분포와 중복·멱등키를 확인한다.
- smoke → 확대 표본 → 본배치 순으로 진행한다.
- 본배치 전에 운영자 세션과 저장 권한을 확인한다.
- 저장 실패가 급증하면 즉시 중단한다.

### 4.3 금지

- 495/500 본배치를 임의 실행하지 않는다.
- 배치와 동시에 495개 Full Mission을 만들지 않는다.
- 프롬프트·strict schema·코어 hash가 바뀐 상태에서 이전 계열과 섞어 이어서 생성하지 않는다.

## 5. 라이브러리와 미션 조립

구 시나리오 브라우저는 라이브러리(`/admin/library`, 탐색)와 조립(`/admin/assembly`,
코어→미션 승격)으로 분리됐다. 라이브러리는 코어 뱅크의 분포와 준비 상태를 보는 운영 화면이다.

### 5.1 셀 그리드

- 화행 × 수준 셀의 콘텐츠 수와 상태를 확인한다.
- 방향, 모드, domain, theme/topic, P·D·R 등으로 좁힌다.
- 코어만 있는 행, 미션 생성 행, 검수 완료 행을 구분한다.

### 5.2 빈 셀에서 생성기로 이동

빈 셀은 막힌 화면이 아니라 생성 작업의 시작점이다.

- 셀의 화행과 수준을 query에 담는다.
- 가능한 경우 모드, domain, 방향, theme도 전달한다.
- `/admin/generator?from=mission-grid...`에서 유효값만 prefill한다.
- theme와 domain이 충돌하면 허용 domain을 우선해 안전하게 보정한다.

### 5.3 Full Mission 승격

- 선택한 코어 하나를 Edge `action:'mission'`으로 승격한다.
- 최신 승인 목표는 MJT5+DCT1이며 기능 순서는 `첫인상 판단 → 맥락 대비 판단 → 판단하고
  고쳐보기 → 이유 찾기 → 여러 초안 비교 → DCT`다.
- 현행 소스의 승격 결과는 `mission_v5`, 네이티브 MJT5+DCT1이다. 정확한 순서는
  `Scale4 → Judge3(독립 맥락 대비) → FixChoice(판단 뒤 수정안 3개 중 권장안 1개) →
  Reason(최초 판단 뒤 이유 3개 중 주원인 선택, 확신도 없음) → MultiJudge(후보 4개) → DCT`다.
  과거 `mission_v5` MJT4 행은 관리자 미리보기에서 계속 읽되 신규 생성 계약으로 취급하지 않는다.
- 생성 후 규칙 기반 검사와 프롬프트 통제 기반 검토를 거쳐 `generated`로 저장한다.
  **품질 점검이 실패하면 저장하지 않는다(fail-closed, 앱·Edge·DB 세 겹).**
- 조립 화면의 `미션 생성`은 목업이 아니라 실제 API·저장 경로다.

## 6. Full Mission 검수

### 6.1 상태

```text
core-only
→ generated
→ 교수자 검수·승인
→ reviewed
```

- `generated`: 생성과 저장에 성공한 상태
- `reviewed`: 관리자가 학습자 공개에 적합하다고 확인한 상태

AI 검토 `pass`만으로 reviewed 처리하지 않는다.

### 6.2 빠른 교수자 검수 큐

빠른 검수는 자동 승인이나 무검수 일괄 승인이 아니다. 다음 조건을 모두 통과한 행만 후보가 된다.

- `mission_status='generated'`
- 코어 규칙 기반 검사 `pass`
- 미션 AI 검토 `pass`
- generation run 존재
- prompt hash 존재
- 현재 prompt hash와 일치
- target feature와 version 존재
- mission content 존재

mission_v5 교수자 검수에는 다음을 추가한다.

- Scale4가 해당 target feature의 `counter_rule_ko`가 경계하는 소박한 규칙을 깨는 적절한 반례이며 같은 적절성 방향 두 응답과 대표 정도 하나를 가지는가
- Judge3가 DCT 앵커와 같은 P·D·R의 다른 사건에서 맥락 대비를 독립 판단하게 하는가
- FixChoice가 별도 사건의 최초 판단을 잠근 뒤 권장안 1개와 일부 조정이 필요한 경계안 2개를
  제시하며, 세 표현이 문법·의미 오류가 아닌 화용적 선택으로 변별되는가
- Reason의 주원인이 하나이며(이유 3개 = 주원인·화용 오개념·의미/문법/맥락 각 1, R4) 다른 두 이유가 동등하게 방어되지 않는가. 동시에 두 오답이 황당한 문법 주장이나 무관한 절대 규칙으로 너무 쉽게 제거되지는 않는가
- 현행 `contrast_plan_v1`의 MultiJudge가 적정 2·조정 필요 2의 네 후보와 각 표현에 맞는 근거를
  가지는가. BEST/WORST 선택 이름 때문에 같은 범주 안의 유일한 순위를 요구하지 않는가.
  후보 길이·형식이 정답 단서가 아닌가. 후보 교체 뒤 해설·참고 표현·인용도 최종 문장과 일치하는가
- 현행 native MJT5와 DCT의 `preceding_turn`이 null이고, 응답 화행에 필요한 선행 사건이
  `situation_ko`에 자연스럽게 요약돼 self-contained한가
- P·D·R이 140자 이내의 정확히 두 문장 상황문에서 자연스럽게 확인되며, 풀어 쓴 학습자용
  P/D/R 칩과 충돌하지 않는가
- **통역 셀 추가 검수(2026-08-06 확정)**: 원발화자 A·학습자 통역사·청자 B가 서로 다른
  세 참여자로 유일하게 결속되는가 / `학습자`가 A·B를 가리키는 데 쓰이지 않았는가 /
  학습자가 화행의 수행자·수신자가 아닌가 / A의 1인칭 서술이 없는가 / P·D·R이 A↔B
  관계인가 / 상황문과 원문의 사건·행위자·대상이 일치하는가(감사·사과류는 대상 행위
  명사까지) — 규칙 기반 검사는 경고까지만, 이 판정은 교수자 몫이다(생성계약 2026-08-06 절)
- FixChoice·Reason은 DCT와 같은 앵커 PDR의 다른 사건인가
- MultiJudge는 P·D·R 중 한 축만 바꾼 대비 사건인가
- 메신저·이메일·대면·전화 UI 메타가 실제 장면과 일치하는가

운영 방식:

- 최대 25건까지 후보 목록을 만든다.
- 관리자가 항목별 내용을 직접 확인한다.
- prompt 불일치, 품질 warning/fail, feature 누락은 빠른 큐에서 차단한다.
- 빠른 큐 통과는 검수 우선순위 자격이지 자동 reviewed 자격이 아니다.

### 6.3 검수 원칙 — 구조 통과 ≠ 콘텐츠 통과

- 생성·저장·재조회 성공(구조 확인)과 교수자 검수 통과(콘텐츠 확인)를 구분한다.
  근거 사례: v3 스모크의 `fix_choice` 초점 혼입, 2026-08-05 통역 역할 카나리의
  규칙 기반 검사·AI 검토 동시 통과 후 연구자 판정에서 결함 발견. **자동 통과를 실질 통과로 읽지 않는다.**
- 과거 버전 스모크 행을 현행 버전으로 변환하거나 reviewed로 승격하지 않는다.
- 프롬프트 버전별 배포·스모크 상태는 `docs/research-trail/04_evidence_index.md`와 관련 dev-log가 정본이다.

### 6.4 현재 콘텐츠 버전의 집중 검수와 선택적 독립 검토

기본 절차는 **규칙 검사 → 저장된 품질점검 연결 → 교수자 최종 확정**이다. 승인 정책은
`focused_v1`이며, 의미·화용 검수 기준과 선택적 모델 프롬프트는 `content_review_v2`를 유지한다.

- 현재 미션의 생성 품질점검과 provenance의 콘텐츠 hash가 일치하고 결과가 완전하면 재사용한다.
  재사용 증거는 `generation_quality`에 저장하며 새 OpenAI 응답이나 독립 검토로 꾸미지 않는다.
  재사용 가능한 기본 결과가 없을 때만 OpenAI 품질점검을 한 번 호출한다.
- 추가 모델 검토는 교수자가 선택하는 선택 절차다. 선택하면 Claude가 동일 원본·기준을 독립 검토하고,
  지적이 있을 때 OpenAI가 그 지적을 판정한다. 기존 결과·기각된 지적은 삭제하지 않는다.
- 교수자는 중대 지적(`fail`)과 `needs_professor` 쟁점에 수정 필요·수정 없이 사용 가능·보류 및 근거를
  저장한다. 이미 교수자 판단이 저장된 항목도 계속 확인한다. 일반 경고는 전문을 보존하고 전체
  수업 사용 판단에 포함하되 모든 경고에 별도 결정을 요구하지 않는다.
- 수정 필요·보류는 승인을 막는다. 전체 사용 근거와 명시적 교수자 확인이 필요하며 AI는 승인하거나
  학생에게 공개하지 않는다. 생성 critic의 중대 지적을 수정 없이 채택할 때 필요한 기존 개별 override는 유지한다.
- 미션은 편성 전, 주차 자료는 편성 후 검수한다. 주차 승인에는 현재 편성 미션의 승인이 필요하다.
  원본·기준이 바뀌면 새 버전을 검사하고, 그 버전의 생성 품질점검을 우선 연결한다. 추가 모델 전수 검토를 반복하지 않는다.
- 승인 경계의 현재 DB 원본 hash, 관리자 권한, 확정된 증거의 불변성, 미션 최종화의 원자적 저장을 유지한다.
  생성 provenance hash는 품질점검 재사용의 근거이며 DB 승인 경계 hash를 대체하지 않는다.
- 체험 감수는 교수자가 필요한 부분을 확인하는 도구다. 기본 승인에 전 문항 체험 기록을 필수화하지 않는다.
  이미 저장된 체험 기록의 미확인·수정 요청·보류는 계속 승인을 막는다.
- 기존 승인 행은 `multimodel_v2` 정책과 증거를 보존한다. 미승인 행은 현재 버전에서 경량 정책으로
  연결할 수 있고, 기존 모델 결과와 교수자 판단을 지우지 않는다. 모델 일치를 내용 타당도나 학습효과로 해석하지 않는다.
- 규칙 오류·호출 실패·실행 중 버전 변경은 보류한다. 성공한 호출의 반복, 자동 재시도, 자동 승인,
  학습자 미편성 콘텐츠의 자동 공개를 하지 않는다. 실제 운영 상태는
  `docs/dev-log/2026-09-06-focused-content-review.md`에 기록한다.

### 6.5 체험 감수 (2026-09-05 사용자 결정 · 운영 반영)

- `/admin/review`는 현재 검수 스냅샷을 학습자의 공통 렌더러로 표시한다. 장면 도입, MJT5,
  문항별 핵심, DCT를 자유롭게 이동하고 직접 풀기 또는 참고 판정·해설 바로 보기를 선택한다.
- 구성요소별 확인·수정 요청·보류와 메모를 현재 검수 행에 저장한다. 승인자와 별도로 감수 기록의
  저장자·시각을 남기고, 감수 시간은 탭이 활성화된 시간의 근사값으로만 기록한다.
- 체험 감수 기록이 있는 미션은 미확인·수정 요청·보류가 남으면 UI와 DB에서 최종화를 차단한다.
  focused_v1의 중대·판단 필요 지적별 결정, 생성 critic override와 현재 버전 검증도 유지한다.
- 문항별 ✗는 수정 요청 기록이다. AI 수리 완료나 전체 미션 기각으로 표시하지 않는다. 원본 수정은
  기존 수정 도구에서 저장·재검사하며 이전 감수는 새 버전에 승계하지 않는다.
- 체험 중 답안은 학습자 수행·사건 기록에 저장하지 않는다. DCT 제출은 참고 표현을 표시하고
  실시간 AI 피드백을 생성하지 않는다. 통역의 음성 재생·전사는 사용자가 해당 버튼을 누를 때
  기존 서비스를 사용한다. 정적 콘텐츠 감수와 실시간 피드백·음성 품질의 검증 범위를 구분한다.
- 표본 수·배치 승인·미검수 콘텐츠 자동 공개는 이번 단계에 포함하지 않는다. 연구자의 검수 부담
  경험은 설계 개선의 관찰 근거이며 감소 효과나 콘텐츠 무결함의 입증으로 쓰지 않는다.

## 7. 프롬프트 정본과 출처 표시

### 7.1 실행 정본

프로덕션 프롬프트 실행 정본은 Edge 소스다. `prompt_templates` 테이블이나 별도 편집 화면이 현재 production active prompt를 자동으로 바꾸지 않는다.

### 7.2 AI 생성 콘텐츠 품질관리

`/admin/prompt-harness`는 자동 점검 방식과 최종 운영 권한을 다음 세 층으로 구분해 읽기 전용으로
보여 준다.

- `규칙 기반 검사`: 같은 입력에 같은 결과를 내는 좁고 재현 가능한 검사. HSK 어휘 참고 범위
  점검과 R1–R29 규칙이 여기에 속한다. HSK의 상세 계산 방식과 최근 결과는 `/admin/corpus`가
  소유하며 이 화면에서는 역할과 이동 경로만 표시한다.
- `프롬프트 통제 기반 검토`: 생성과 분리된 AI가 버전이 관리되는 지시문에 따라 의미·자연성·후보
  자격을 검토한다. 실제 지시문, 모델 설정, 출력 형식, 교정 규칙, 버전과 지문을 함께 관리해
  검토 경로를 재현할 수 있게 한다.
- `교수자 검수·승인`: 자동 검사와 AI 검토가 제시한 근거를 보고 더 쉽게 또는 더 도전적으로
  조정할지와 학습자 공개 여부를 결정한다. 앞의 두 자동 점검 방식은 이 권한을 갖지 않는다.

`프롬프트·지문 관리` 영역은 다음을 보여 준다.

- Edge 소스에서 자동 생성한 프롬프트 스냅샷
- 모델·temperature·response format
- prompt snapshot hash
- 저장된 시나리오가 현재 정본과 일치하는지
- 다른 지문 또는 지문 없는 과거 행

과거 프롬프트 지문은 증거를 삭제하지 않되, 반복 경고가 현재 품질관리 구조를 화면 아래로 밀지
않도록 합계와 종류 수를 먼저 표시하고 세부 이력은 접어 둔다.

화면 문구는 다음을 구분해야 한다.

- 현재 저장소 정본
- DB에 등록된 참고 템플릿
- 실제 배포 active 여부

DB 문서를 “프로덕션 정본”으로 오인하게 만드는 표현을 사용하지 않는다.

### 7.3 변경 규칙

- 프롬프트를 바꾸면 스냅샷을 재생성한다.
- dirty worktree의 임시 hash를 정본처럼 기록하지 않는다.
- 배포본과 저장소판의 지문을 확인한다.
- 코어·미션·비평 프롬프트 버전을 서로 구분한다.
- 현재 활성 프롬프트 버전과 배포 active 여부는 Prompt Harness·`docs/research-trail/04_evidence_index.md`에서 확인한다.
  이 문서에 버전 문자열을 복사해 두지 않는다.

## 8. 화행 목표와 진단용 target feature 관리

실행 정본은 코드 카탈로그다.

수업 편성의 학습목표 단위는 `speech_act`다. 아래 target feature 카탈로그는 문항 생성·진단·
피드백·근거 귀속을 위한 내부 기준이며, 주차나 완전한 미션 하나의 목표로 사용하지 않는다.

- 9화행 기본 자동 승격 feature 9개
- 칭찬하기·칭찬 대응을 분리한 승인 feature 총 10개
- 10개 기능 전부 한→중(ko_zh)·중→한(zh_ko) 방향 변형 보유 (zh_ko 오답 시드는 일부 화행만 존재 — 확대는 설계 판정 대기)
- 화행별 band schema
- learner label, counter rule과 기능별 `handoff_summary`
- 모든 band는 연구자 캘리브레이션 전 `proposed`

현재 하지 않는 것:

- AI가 새 target feature를 자유 생성
- 코드와 분리된 관리자 입력값을 production 정본으로 사용
- 학술 검토 없이 validated 지위 부여
- 7월에 신규 feature package 테이블 3종을 다시 신설
- 단일 target feature의 충족을 주차·미션 완료나 화행 숙달로 표시

## 9. 15주 교과목 설계

### 9.1 한 화면의 교과목 설정·강의 계획·미션 편성

- 관리자 메뉴와 정식 진입점은 `AI 15주 교과목 설계`(`/admin/composer`) 하나다.
- Composer의 작업 캔버스는 큰 화면에서도 최대 960px로 제한해 필드와 카드가 브라우저 끝까지
  늘어나지 않게 한다. 여백은 미사용 공간이 아니라 읽기 폭과 과업 집중을 위한 경계다.
- 화면 상단은 `교과목 설정 → AI 자동 편성 → 주차별 조정`의 세 단계를 전체 네이비 상단선을
  공유하는 하나의 PRAGMA 브랜드 단계 바로 보여 준다. 단계 제목은 설명보다 한 단계 크게 하고,
  보충 문구는 명사형으로 축약한다. 서로 다른 색의 카드 세 개로 단계를 분절하지 않는다.
- 기존 편성기의 프리셋, 네 축 조절, 자동 채우기, 주차별 교체, 저장 기능을 중심 작업대로 유지한다.
- `새 강좌`는 제목·수준·언어방향만 받는 빠른 생성 모드다. 표준 15주안(중간 8주·기말 15주·
  기본 미션 2개)은 자동 생성하고 곧바로 편성 작업대로 돌아온다.
- `주차 계획 수정`은 기존 편성 작업대와 겹쳐 보이지 않는 별도 편집 모드다. 강좌명·상태와
  표준안의 예외 주차만 필요할 때 수정한다.
- 기본 주차 편집 항목은 주차 유형·제목·수업 초점 화행·미션 수다. 학습자 화면에서 실제 사용하는
  선택 Can-do는 `학습자 화면 세부 설정` 안에 보존한다. 구 복습 공개 스위치는 사용하지 않는다.
  P·D·R·채널·도메인·산업·부하 밴드·역량 초점은 매주 수동 입력하는 기본 항목으로 두지 않는다.
- 화행 학습 주차는 하나의 `speech_act`와 완전한 MJT5+DCT1 미션 두 개를 기본·필수 구조로
  사용한다. 두 미션은 같은 수준·언어방향을 따르며 수업시간, 주당 수업 횟수와 시간 배분
  필드는 만들지 않는다.
- 미션 2는 미션 1의 사실상 복제본이 아닌 새로운 상황이어야 한다. 표준 자동·수동 편성은 동일한
  상황문을 공백·문장부호만 바꾼 명백한 복제본을 제외하고, 그 밖의 의미상 복제 여부는 교수자가
  두 상황을 읽고 판단한다. 별도의 의미 유사도 시스템은 만들지 않는다.
- 표준 생성·검수·편성은 A/B 역할, `changed_context_axes`, pair 진단차원 coverage, pair-first 생성,
  pair lifecycle에 의존하지 않는다. 기존 `speech_act_ab_v1` 필드와 검사는 역사 데이터 호환용으로
  남길 수 있지만 새 표준 배정에는 작성하지 않는다.
- 수준·주제·강좌 수행모드·언어방향 네 축은 강좌의 자동 편성 정책으로 저장한다. 수행모드는
  `번역 / 통역 / 통번역`이며, `번역 중심 / 통역 중심`처럼 혼합을 암시하는 명칭은
  전용 강좌에 사용하지 않는다.
- 2026-09-06 승인 A안에 따라 표준 세 과목은 모두 통번역형이며, 화행 주차마다 번역 1개·통역
  1개를 요구한다. 전용 강좌는 각 유형의 두 미션을 사용한다. `통역 학습 주차 수` 선택과
  6/6·9/3 주수 표시는 제거하고 실제 편성 미션 수와 각 주차의 필요한 모드를 표시한다.
- 자동 채우기는 9개 화행 주차와 화행을 선택한 13주에 모드별 승인 미션을 하나씩 찾는다.
  한 모드가 부족하면 다른 모드 두 건으로 대체하지 않는다. 수동 편성은 아직 채우지 않은 모드만
  허용하고 번역·통역 순서로 저장한다. 일부 편성 초안은 허용하되 수업자료 승인·주차 완료로
  간주하지 않는다. 7·14주 메타화용 토론과 1·8·15주에는 새 미션을 배정하지 않는다.
- 네 축 제어는 캔버스 폭을 그대로 늘려 쓰지 않고 고정 폭의 개별 블록으로 구분한다. 주제 블록은
  복수 선택 수와 강의 맥락 다양화 기능을 함께 표시한다.
- AI 자동 편성은 이 화면의 핵심 자동화이므로 교과목 선택 스트립과 분리한 독립 패널로 둔다.
  네이비 헤더에 프리셋과 옐로우 `AI 자동 채우기` 행동을 결속하고, 네 축은 아래 본문에서 조정한다.
  교과목을 아직 선택하지 않은 최초 화면에서도 이 패널을 접거나 숨기지 않는다. 미선택 상태의
  `AI 편성 시작`은 빠른 교과목 생성으로 연결하고 현재 네 축을 새 교과목 정책의 초깃값으로 전달한다.
- 현행 모드 구성은 `course_mode`로 결정한다. 기존 `target_interpreting_ratio`와
  `target_interpreting_week_count`는 저장·과거 자료 호환용이며 현재 주차 배분에는 사용하지 않는다.
  기존 배정·검수·수행 기록은 자동 변환하거나 삭제하지 않는다. 과거 편성 중 모드 정원을
  초과한 주차는 임의 선택하여 노출하지 않고 교강사가 교체하도록 준비 상태로 둔다.
- 번역·통역 하나씩의 배분은 공통 학습 구조에 대한 설계 선택이며 시간·난도 균형이나
  교육적 최적성을 검증한 결과가 아니다. 역할·상황·P/D/R이 함께 달라지는 두 수행은 통제 비교쌍이 아니다.
- 수준별 제작 현황, 코어 수, DB 재조회 문구, RQ2 구현 단계명은 편성 판단을 바꾸지 않으므로
  주 화면에 상시 노출하지 않는다. 현재 선택 조건에서 실제 자동 편성 가능한 reviewed 미션 수만
  간단히 보여 주고 저장 성공·실패는 일시 알림으로 전달한다.
- 주차별 배정표는 넓은 화면에서 왼쪽 1~8주·오른쪽 9~15주인 열 우선 2단 목록으로 표시한다.
  1·2·3주가 가로로 번갈아 흐르는 행 우선 grid는 사용하지 않는다. 각 열 안에서는 아래로 읽고,
  작은 화면에서는 1~15주 한 열로 자연스럽게 이어진다. 두 목록 전체에만 외곽선을 두고 주차와
  배정 미션은 얇은 구분선으로 나눈다. 반복 화행 라벨과 0건 배정 표시는 숨기고 주차 번호의 대비를
  낮춘다. 미션 순서·모드·상황문을 기본 노출하며 긴 상황문은 두 줄로 접어 스캔 밀도를 높인다.
  변화축·pair coverage를 기본 정보로 노출하지 않고 단일 target feature를 주차 목표처럼 표시하지 않는다.
  reviewed-only는 후보와 저장 게이트가 강제하므로 모든 행에 같은 검토 상태를 반복하지 않는다.
- 중간·기말은 `평가 주차 · 미션 배정 없음` 한 줄로 표시하고 같은 범위 설명을 주차마다 반복하지 않는다.
- 7주는 `중간 메타화용 토론`, 14주는 `종합 메타화용 토론`이다. 두 주차는 실제 누적 수행자료를
  입력으로 쓰는 공통 skeleton이며, 자료가 없을 때는 빈 상태와 명시적으로 표시한 데모 자료만 사용한다.
- 13주는 `선택 화행 집중 보완`이다. 편성 행의 `화행 선택`에서 주차 설정을 열고 앞선 정규
  주차에 있는 화행 하나를 선택·저장한다. 같은 화행의 새 MJT5+DCT1 미션 두 건을 편성하며,
  미선정·다른 화행·세 건 이상 배정은 저장하지 않는다. 고부담 상황이나 특정 표현 전략을 요구하지 않는다.
  선택 전의 빈 초안과 기존 배정은 보존한다. 과거 배정이 선택한 화행과 충돌하면 교강사가 교체한다.
  번역·통역 전용 강좌에서는 해당 모드 두 건을, 통번역형에서는 번역·통역 각각 한 건을 편성한다.
- 편성·주차 설정·강의계획서·유인물은 두 글자 화행명과 `중심 질문`을 공통 안내로 표시한다.
  질문은 P·D·R, 실제 상황과 원문의 의도·태도에 맞게 수업에서 조정하는 대표 질문이며, 생성·검수
  통과 조건이나 평가 준거가 아니다. 특정 완화·선택권·이유·대안의 포함을 일률적으로 요구하지 않는다.
- 선택 주제로 채울 미션이 부족하면 자동으로 다른 주제를 섞지 않고 부족 주차를 표시한다.
  다른 주제 확대는 교강사가 별도 행동으로 명시적으로 승인한다.

학생 자유 검색·추천 풀이가 아니라 교강사가 편성한 수업 경로다.
하나의 outline은 저장 시점에 한 수준과 한 언어방향을 가진다. 한→중과 중→한 미션을 같은
outline에 섞지 않으며, 두 방향의 15주 강좌를 동시에 운영하려면 방향별 outline을 둔다.
수준·방향을 바꾼 뒤 기존 배정이 새 조건과 다르면 교체 전 저장을 차단한다. 교강사는 자동
채우기 결과를 출발점으로 삼되 주차별 미션을 직접 교체해 최종 구성을 결정한다.

### 9.2 Can-do 편집

`주차 계획 수정`에서 주차별 Can-do를 선택적으로 작성할 수 있다.

- 상황·참여자·목적 중심으로 작성
- 화행을 주차 목표로 유지하고, `target_feature`는 문항별 내부 진단 언어로만 사용
- 제안 삽입은 보조 기능이며 교수자가 최종 문구를 결정
- CEFR·ACTFL 공식 인증 기술자로 표시하지 않음

### 9.3 주차 수업자료와 출력 분리

- 순서: `교과목·주차 계획 → 미션 편성 → 그 미션에 맞춘 주차 수업자료`.
- Composer의 각 주차에서 `/admin/package?courseId=...&weekNo=...`로 이동한다.
- 미편성 때 페이지를 열 수 있는 것과 자료가 확정된 것은 다르다. 미션 편성 전에는 계획
  미리보기로 표시하고, 편성 후 실제 미션의 기본 상황·원문과 기존 설명을 공통 본문에 반영한다.
- 프로젝터는 공통 본문을 단계별로, 학생 유인물은 같은 내용을 연속 문서로 보여 준다.
  HTML은 프로젝터의 오프라인 사본이며 별도 생성 콘텐츠가 아니다.
- 교수자 전용 메모는 수업 지도 주의점과 **현재 배정된 미션**의 기존 MJT·DCT 해설을 제공하는
  관리자 별도 보기다. 프로젝터를 열거나 닫을 때 전용 메모가 다시 노출되지 않게 한다.
- 전용 메모·정답은 학생 유인물과 공용 HTML의 데이터·출력에서 제외한다. CSS 숨김으로 대체하지 않는다.
- 별도 교안 생성기·편집기·DB 저장 구조를 추가하지 않는다. 현재는 기존 주차 목표·검토 원리·편성
  상황과 원문을 조립하며, 상세 강의 내용 보강 및 교수자의 내용 적합성 확인을 자동 완료로 간주하지 않는다.
- 학생 예습·복습 자료를 따로 만들지 않는다. 기존 `review_released` 값과 학습 로그는 보존하고,
  유인물의 미션 완료 해금에는 사용하지 않는다. 접근 범위는 학습자 구조 정본을 따른다.

### 9.3.1 수업자료와 미션 도입의 역할 (2026-09-07 사용자 결정)

- 수업자료의 별도 hook·교수자 도입 화면과 고정 예문 카탈로그를 제거한다.
  사용자는 콘텐츠 품질과 실제 미션 도입과의 중복을 이유로 제거를 결정했다.
- 수업자료는 학습목표·중심 질문·핵심 설명·상황과 원문·편성 미션 연결에 집중한다.
  각 실제 미션의 3단 장면 도입과 MJT5+DCT1 수행은 유지한다.
- 새 주차 자료와 Edge 검수 원본에는 `opening`을 생성하지 않는다.
  과거 검수 스냅샷은 수정하지 않으며, 변경된 자료의 공개는 기존 현재 버전 검수·확정 절차를 따른다.
- 제거 결정과 배포 근거: `DEC-20260907-01`,
  `docs/dev-log/2026-09-07-remove-weekly-hook.md`.

### 9.4 편성 저장 안전장치


- 자동 채우기와 수동 후보는 `mission_status==='reviewed'`를 공통으로 강제한다.
- 같은 outline 안의 시나리오 중복을 차단한다.
- 자동 채우기·미션 저장·강좌 구조 저장은 같은 구조 호환성 검사를 사용한다.
- 현재 선택한 수준·언어방향, 주차 유형·화행·미션 수와 맞지 않는 기존 배정은 저장 전에 차단한다.
- 표준 자동 편성은 화행 학습 주차를 같은 화행·수준·언어방향과 유형별 모드 구성의 reviewed native MJT5
  두 건으로 완성할 수 없으면 부족 상태로 둔다. 수동 후보와 저장 검사는 같은 상황문의 명백한
  복제본을 차단한다.
  변화축·pair coverage는 저장 조건으로 검사하지 않는다.
- 13주는 두 미션이 교강사가 선택한 같은 기학습 화행이며 유형별 모드 구성에 맞는지 확인한다.
  고부담 맥락, 두 미션 사이 별도 연계 역할이나 coverage를 요구하지 않는다.
- 강좌 구조 저장은 기존 주차를 삭제·재삽입하지 않고 주차 번호별 upsert로 보존한다.
- 미션 편성 저장은 새 편성을 먼저 upsert한 뒤 사라진 기존 행만 삭제해, 삽입 실패 전에 기존
  편성 전체가 지워지는 순서를 사용하지 않는다.
- 저장 뒤 outline 메타와 주차별 배정을 DB에서 다시 읽어 실제 반영을 확인한다.
- 학습자 공개 게이트는 reviewed 원칙을 유지한다.

### 9.5 학기 PDR 배치표

주간 DCT는 같은 앵커 PDR의 새 사건을 쓰는 근접 전이 과제다. 관리자 편성은 이를 넓은 전이로
과장하지 않는다. P·D·R은 매주 교수자가 다시 고르는 기본 폼이 아니다. 후속 고급 보기에서는
실제 배정된 미션을 기준으로 학기 전체 분포를 점검하는 배치표로 제공한다.

배치표 최소 열:

```text
week
speech_act
mission_position
P / D / R
domain
mode
direction
transfer_type
```

- 주차별로 P·D·R 조건을 순환한다.
- 한 화행 주차의 두 미션은 같은 화행을 유지하되 사실상 같은 상황을 복제하지 않는다.
- 한 주의 MultiJudge는 앵커에서 한 축만 바꾼 대비를 제공한다.
- 중간·기말 통합 과제에는 P·D·R 중 하나 이상이 달라지는 문항을 포함한다.
- 배치표는 전이 기회를 설계하는 도구다. 수행 증거 없이 전이 효과를 주장하지 않는다.

### 9.6 수업 데이터 백업·복원

- `/admin/data-backup`은 관리자 전용 독립 화면이며 Composer 리다이렉트나 연구 데이터 export로
  대체하지 않는다.
- 백업 범위는 교과목 1건, 주차 편성, 주차별 미션 배정과 해당 미션 본문이다. 인증정보·검수자
  식별자·학습자 수행 기록은 포함하지 않는다.
- 복원 전 파일 형식·참조 무결성·비밀정보 의심 값을 검사하고, 대상 교과목의 현재 상태를 안전
  백업으로 먼저 내려받는다. 다른 교과목·공유 미션 본문·학습자 수행 기록은 삭제하지 않는다.
- 복원은 운영 데이터를 변경하는 관리자 동작이다. 화면 재배치와 별개로 실제 운영 canary와 현행
  스키마 호환성을 확인한 뒤 사용한다.
- 이 기능은 교과목 편성의 이동성과 운영 복구를 위한 것이며 연구 참여자의 수행 데이터 내보내기를
  대체하지 않는다.

## 10. 학습자·연구 접점

관리자 화면은 다음을 구분한다.

- 학습 접근 승인
- 연구 참여 동의
- 운영 기록
- 연구 분석 대상

연구 미동의 학생의 학습 접근을 막지 않는다. 수행 로그를 연구에 사용하려면 별도 기관 승인·동의·비식별화 절차를 따른다.

`/admin/export`는 학습 수행 기록 조회와 분리된 관리자 전용 연구자료 준비 화면이다. 기간 필터를
적용하고, 데이터 이용·가명 분석 동의와 동의 버전이 현재 이벤트에 일치하며 연구용 가명키가 있는
행만 JSON 또는 JSONL로 내보낸다. 직접 사용자 ID·이름·이메일은 반환하지 않고, 누가 언제 어떤
기간의 몇 행을 내보냈는지 감사 기록을 남긴다. 가명키는 원 DB에서 재연결 가능하므로 익명화로
표현하지 않는다.

Full Mission의 문항 선택은 기존 `learner_mission_logs.context_judgment`에 `mpj_response_v1` 비채점 trace로 저장한다. Scale4의 4점 원응답, FixChoice의 최초 Judge3와 교정 선택을 보존한다. v4 이후 Reason에는 확신도가 없다(확신도 입력은 legacy 미션에만 존재). Scale4의 적절/부적절 방향 일치와 매우/다소 차이를 분리해 보되, 참고 판정 일치율을 능력 점수로 표시하지 않는다.

분석 화면에서 다음을 하지 않는다.

- 시도 감소를 성장 점수로 표시
- AI 판정 동의를 능력 점수로 표시
- 라운지 활동을 미션 성취에 합산
- 코어 수를 학습 가능한 reviewed 미션 수처럼 표시

보고 계수는 최소 다음을 분리한다.

```text
코어 수
미션 생성 수
프롬프트 기반 AI 검토 수
교수자 승인 미션 수
학습자 실행 가능 수
```

## 11. 라운지 관리자 범위

라운지(`/learner/lounge`, 코너 3개)는 학습자 하단 탭에 노출된 실화면이며 main 배포에
포함돼 있다. 다만 백엔드가 없다.

- 라운지 전용 DB 없음 — 진행 상태는 localStorage만 사용
- 관리자 콘텐츠 관리 화면 없음
- 밈 제출·투표의 서버 저장 없음
- 생생극장 실제 영상 소스 연결 없음

따라서 라운지 테이블·신규 Edge action을 구현 완료로 쓰지 않는다. 라운지 활동은 미션
성취·연구 로그와 합산하지 않으며, 백엔드 추가는 학습 코어·연구 로그와 분리된 별도 제품
범위로 승인받는다. (논문 목차에서의 귀속은 논문 쪽 판정 사안)

## 12. 운영 승인 게이트

사전 보고·승인이 필요한 작업:

- DB schema·migration·RLS
- Edge·Railway production 배포
- prompt 또는 strict schema 변경
- core surface hash 변경
- 495/500 배치
- generated → reviewed 자동화
- AI 모델 간 독립 검토 배치 실행 (대상·규모·모델을 먼저 보고 — 계약 §10과 동일 게이트)
- target feature 지위·band 의미 변경
- 학습자 로그와 연구 분석 의미 변경

일반 프론트·검사·문서 수정은 위 계약을 바꾸지 않는 범위에서 수행할 수 있다.
