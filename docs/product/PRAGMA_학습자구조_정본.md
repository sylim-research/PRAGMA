## 1. 학습자 경험의 목적

PRAGMA의 학습자 화면은 검사 응시 화면이 아니라 수업과 연결된 학습 환경이다.

> 실제 상황에서 적절한 한·중 통번역 수행을 연습하고, 그 원리를 화용론적으로 이해하도록 돕는다.

정체성 기준(2026-08-06 확정, 정본 = 생성계약 §1 정체성 문장 2개): PRAGMA는 자유로운
외국어 화행 산출 도구가 아니라 **원문 제약 아래의 통번역 학습 워크플로우**다.
**2026-09-07 장면 서술 개정:** 번역은 주어진 원문을 읽고, 통역은 주어진 발화를 듣고
목표어로 옮기는 훈련이다. 두 모드 모두 나/저는 또는 구체적인 인물 역할로 상황을 제시한다.
별도 통역사 C의 역할 소개는 학생용 화면에서 생략한다. P·D·R은 원문 발화자와 상대의 관계이며
두 모드 모두 원문의 의미·의도·화용적 힘을 보존한다.

학습자에게는 상황과 Can-do 수행 목표를 먼저 보여준다.

**메타언어 노출 원칙 (2026-08-06 개정 — 「감춘다」에서 「시점을 통제한다」로):**

| 대상 | 규칙 |
|---|---|
| P·D·R 원시 저장 코드, 적절성 대역 코드, `target_feature` 정본명, 정답 방향 | **노출 금지.** 내부 코드와 판정값은 학습자용 설명이 아니며 정답 단서가 된다 |
| 학습자용 P/D/R 칩 (`상대 높음`·`아는 사이`·`부담 높음` 등) | **판단 전에도 노출.** 간결한 상황문을 보완하고 관계·거리·부담을 명시적으로 확인하는 교수 단서다 |
| 화행 명칭(요청·거절·감사…), 화용적 적절성 개념, 상황에 따라 표현이 달라지는 원리 | **명시적으로 가르친다.** 도입 아크·피드백·기록에서 학습자 언어로 노출한다 |

근거: 학습 설계가 이미 **귀납 후 명시**이고 도입 아크가 `장면 제시 → 차이 인식 → 원리
이해 → 적절성 판단`이다. 원리를 명시적으로 가르치기로 해 놓고 그 원리의 이름을 감추는
것은 모순이다. 주차 제목이 「요청 화행」·「감사 화행」·「초대 화행」으로 화행을 보여주고 있으므로
범주는 노출하면서 명칭만 감추는 상태이기도 했다. 대상 학습자는 중급 통번역 수업
수강생이다.

**단, `목표 화용 요소`라는 용어 자체는 학습자 화면에 쓰지 않는다.** 그 자리는 카탈로그의
학습자 라벨(예: `부탁을 부드럽게 말하기`)이 이미 맡고 있고, 내용은 도입 아크에서 명시적으로
가르치므로 용어를 덧붙일 필요가 없다. 화행 명칭·화용 개념의 첫 소개는 화면이 아니라
**1주차 오리엔테이션과 수업 자료**에서 한다.

## 3. 학습자 진입과 연구동의

### 3.1 학습 이용

- 승인된 학습자는 프로필 설정 후 수업 화면에 진입한다.
- 신규 프로필의 필수 입력은 **이름·소속/신분·주 사용 언어**다. 이메일은 인증 계정에서 가져온다.
- **학습 시작 수준, 최근 HSK 급수, 목표 언어 실제 사용 경험, 한중 통번역 학습·수행 경험**은
  수업 운영 참고용 선택 입력이다. HSK는 한국어·기타 언어 사용자가 선택적으로 입력하며,
  화용 능력이나 성취 수준으로 자동 환산하지 않는다.
- 프로필 배경은 학습자 이해를 돕는 운영 정보이며, 강좌·수준·피드백을 자동 배정하는 판정값이 아니다.
- 관리자 목록에는 소속/신분·언어 수준·통번역 경험처럼 교수자가 바로 참고할 정보만 표시한다.
  프로필 완료 여부는 미완료일 때만 예외로 알리고, 익명 식별자와 동의 정보는 상세의
  `연구·데이터 관리` 영역에서 분리해 확인한다.
- 학습 이용과 연구 참여는 별개다.
- 연구 미동의 상태라도 동일한 학습 기회를 가져야 한다.

### 3.2 연구동의

- 프로필 온보딩에서 간단한 필수 연구동의 팝업을 받지 않는다.
- 기관 승인 설명문, 자료 범위, 보관·철회 절차가 준비된 별도 동의 흐름을 사용한다.
- 기존 동의 컬럼과 관리자 조회는 호환을 위해 남아 있을 수 있으나, 신규 온보딩은 동의 값을 학습 접근 게이트로 쓰지 않는다.
- 운영 로그가 있다는 사실만으로 연구 분석에 사용할 수 없다.

## 4. 수업·주차 구조

### 4.1 수업연계형 단일 경로

PRAGMA의 공식 학습 경로는 교강사가 편성·게시한 15주 수업이다.

```text
교과목 선택
→ 15주 강의계획서에서 주차 펼치기
→ 배정 미션 선택
→ 장면 이해부터 학습
→ 기록
```

- 표준 디펜스 교과목은 `AI 한중 화용 통번역`(중급·한→중),
  `AI 중한 실전 통번역`(중급·중→한), `AI 한중 비즈니스 통번역`(고급·한→중) 세 과목이다.
  2026-09-06 승인 A안에 따라 세 과목 모두 통번역형으로 운영한다. 화행 학습 주차마다
  번역 1개·통역 1개를 수행하며, 과목은 수준·언어 방향·사용 맥락으로 구별한다.
  교과목 목록은 과거 번역 6주·통역 6주 또는 9주·3주 배분 대신 `통번역`으로 표시한다.
- 15주 강의계획서와 주차 상세는 한 화면의 아코디언으로 통합한다. 접힌 행은 주차·학습 주제를
  보여 주고, 한 주차를 펼치면 Can-do 한 줄·중심 질문·강의 유인물 링크·두 미션 카드가 나타난다.
  첫 방문은 첫 화행 학습 주차(표준 과목의 2주차)를 펼친다. 한 번에 한 주차만 열며 모두 접을
  수도 있다. 선택은 URL과 교과목별 브라우저 세션에 기억하고, 미션·유인물에서 같은 주차로 복귀한다.
  기존 주차 상세 주소는 통합 화면의 해당 주차로 연결한다.
  남색 면은 상단 브랜드 바에 집중하고, 교과목명은 배경 위의 단순한 제목으로 표시하며, 열린 주차는 옅은 노랑으로 강조한다. 미션은 짧은 상황 제목과 시작
  버튼으로 제시한다. 완료 수치·상태 배지·긴 안내문은 표시하지 않는다. 직접 진입에도
  교과목·주차·배정 식별자를 전달해 수행 귀속을 유지한다.
- 공통 필수 미션은 주차의 핵심 수행이다. 아직 편성되지 않았거나 현재 주차의 수행모드와
  일치하지 않는 과거 배정은 실행 미션으로 노출하지 않고 준비 상태로 표시한다. 기존 미션·배정·
  수행 기록은 삭제하지 않는다.
- 화행 학습 주차는 화행 하나를 중심으로 완전한 MJT5+DCT1 미션 두 개를 수행한다.
  수업시간, 주당 수업 횟수와 시간 배분은 학습자 구조와 연구 주장 범위에 포함하지 않는다.
- 강좌의 수행 유형은 번역·통역·통번역이다. 표준 세 과목의 통번역형은 2·3·4·5·6·9·10·11·12주와
  화행을 선택한 13주에 번역·통역 미션을 하나씩 편성한다. 각각 독립적인 MJT5+DCT1이며,
  번역은 문어 과제, 통역은 구어 과제로 자연스러운 훈련 상황·원문·조건을 구성한다.
  기존 번역·통역 전용 강좌는 각 유형의 두 미션을 유지한다. 일부 미션만 준비되거나 완료된
  상태를 해당 주차 전체의 완료로 표시하지 않는다.
- 7주와 14주는 누적 수행자료를 돌아보는 중간·종합 메타화용 토론이다. 실제 자료가 없을 때는
  빈 상태 또는 데모라고 명시한 자료만 보여 주며 가상 자료를 실제 학생 자료처럼 표시하지 않는다.
- 13주는 `선택 화행 집중 보완`이다. 교강사가 앞선 학급 수행을 참고해 기학습 화행 하나를
  선정하고, 같은 화행·수준·방향의 새 MJT5+DCT1 미션 두 건을 독립적으로 편성한다.
  통번역형의 13주도 번역 1개·통역 1개를 수행한다.
  P·D·R과 상황을 다양하게 구성하며 고부담으로 한정하지 않는다. 14주는 이 수행까지 돌아본다.
  화행 선정 전에는 준비 상태를 표시하며 과거의 서로 다른 화행 배정을 실행 목록에 섞지 않는다.
- 강의계획서의 주차 제목은 `요청 화행·감사 화행·칭찬 화행·초대 화행·거절 화행·사과 화행·제안 화행·반대 화행·불만 화행`으로 표시한다.
  학부 강의의 학습 주제임을 드러내는 화면 명칭이며, 기존 화행 범위나 내부 식별자를 바꾸지 않는다.
- 펼친 주차와 유인물에는 `중심 질문`을 명시하고, 접힌 행에서는 반복하지 않는다. 교강사는 P·D·R, 상황, 원문의 의도·태도와
  방향·모드에 맞춰 수업에서 질문을 구체화하거나 교체할 수 있다. 대표 질문의 별도 저장 필드는
  만들지 않으며 특정 전략·정답·평가 준거로 고정하지 않는다. 원문의 의미와 화행 목적은 보존한다.
  첫 미션의 내부 `target_feature`를 주차 전체 목표로 대신 표시하지 않는다.
- 선택 복습 미션이 있다면 교강사가 배정한 범위 안에서 제공한다.
- 학습자가 미검수 코어나 `generated` 미션을 직접 고르지 않는다.
- 학습자 실행 최소 조건은 `mission_status='reviewed'`다.

### 4.2 Can-do

Can-do는 상황·참여자·목적·수행·모드·상황 적절성 기준을 학습자 언어로 설명한다.

- 화행을 대체하지 않는다.
- 주차 Can-do는 특정 `target_feature` 하나의 습득이 아니라 해당 화행의 핵심 판단과 수행을
  복수 맥락에서 다루는 목표를 설명한다.
- 특정 완화 표현의 사용 자체를 성공 기준으로 고정하지 않는다.
- 입문·중급·고급을 CEFR·ACTFL 등급과 대응시키지 않는다.
- 교수자가 저장한 주차 Can-do를 우선 사용한다.
- 저장 Can-do가 없을 때만 결정론적 보조 가이드를 사용한다.

관련 원칙은 `docs/research/PRAGMA_CAN_DO_ALIGNMENT_PRINCIPLES_2026-07-28.md`를 따른다.

## 5. 주차 강의 유인물

경로:

```text
/learner/course/:courseId/week/:weekNo/note
```

기존 `/note` 주소를 유지하고 주차별 강의 유인물 한 개를 제공한다. 웹 열람과 브라우저 인쇄·PDF를
사용한다. 예습·복습 자료를 따로 생성하지 않으며, 개인 답안·피드백은 기존 수행 기록에서 확인한다.

### 5.1 공통 본문과 편성의 관계

- 구성 순서는 `교과목·주차 계획 → 학습 미션 편성 → 그 미션에 맞춘 주차 수업자료`다.
- 교과목·주차가 자료의 단위이며, 편성된 미션의 상황·원문이 구체적인 실습 내용의 기준이다.
- 주차 Can-do·맥락·기존 검토 원리 및 표현 자원과 현재 편성된 미션의 기본 상황·원문을 함께 사용한다.
- 같은 공통 본문을 관리자 프로젝터·오프라인 HTML·학생 유인물에서 재사용한다.
- 미편성·불완전 편성의 계획 미리보기는 관리자에게 제공한다. 학생 유인물은 현재 원본·편성과
  일치하는 교수자 승인 스냅샷만 열람·인쇄한다. 미승인·변경된 자료는 검수 대기로 표시한다.
- 기존 내용을 조립하고 기존 검수 스냅샷을 재사용한다. 별도 수업자료 생성기·편집기·저장소는 두지 않는다.
  문헌 검토에 따른 상세 강의 내용과 사례 보강은 별도 작업이다.

### 5.2 교수자 메모와 분리

- 내부 판정 정의·오개념·미션별 MJT·DCT 해설은 관리자용 교수자 전용 메모에서 확인한다.
- 학생 유인물과 프로젝터용 HTML에는 교수자 메모·미션 정답을 넣지 않는다. CSS로 감추는 대신
  공용 데이터 모델과 출력 본문에서 제외한다.

### 5.3 접근과 기존 기록 보존

- 기존 승인 학습자·공개 교과목 접근 조건은 유지한다.
- 유인물에 미션 완료 기반 예습·복습 해금을 적용하지 않는다.
- 유인물 검수 대기는 학습 미션이나 기존 수행 기록의 이용을 차단하지 않는다.
- 과거 `review_released` 값과 미션 수행 기록은 삭제하거나 갱신하지 않는다.
- 출력 구조의 로컬 구현과 운영 반영 상태는 구분한다. 검증·배포 근거는 관련 dev-log에서 확인한다.

## 6. Full Mission 학습 흐름

학습자 정본 경로:

```text
/learner/practice
```

### 6.1 승인된 Full Mission 목표 흐름

최신 승인 학습설계는 **MJT5 + DCT1**이다. 현행 소스·운영의 네이티브 MJT5 구조는 이 문항
순서에 동기화됐다. 과거에 추가된 `speech_act_ab_v1` 배정 필드는 기존 데이터 호환용이며,
새 표준 편성·학습 흐름은 A/B 역할·변화축·합산 coverage에 의존하지 않는다.

화행 학습 주차의 목표 단위는 특정 `target_feature`가 아니라 하나의 `speech_act`다. 한 주차의
미션 1과 미션 2는 각각 완전한 MJT5+DCT1이며, 같은 화행을 사실상 복제되지 않은 두 상황에서
다룬다. feature는 각 문항의 진단·피드백 태그로만 사용하며 두 미션 사이 coverage를 강제하지 않는다.

```text
장면 이해
  미션 1 최초 진입
    오늘의 장면 → 장면 속 단서 → 당신의 선택
  미션 2 최초 진입
    새로운 장면 → 장면 속 단서 → 이번 장면에서의 선택

표현 판단
  첫인상 판단
    Scale4 원응답 → 적절/부적절 방향 피드백
  → 맥락 대비 판단
    관계·거리·부담·채널이 달라진 장면에서 같은 단순 규칙이 항상 성립하지 않음을 판단
  → 판단하고 고쳐보기
    Judge3 1회 → 수정안 3개 중 이 장면의 권장안 1개 선택
    (권장안 1 + 일부 조정이 필요한 경계안 2)
  → 왜 문제일까
    최초 대역 판단 → 판단 잠금 → 가장 큰 이유 1개/3개 선택
    (주원인·화용 오개념·의미/문법/맥락 각 1 — R4)
  → 여러 초안 비교
    후보 4개를 한 화면에서 비교
    → 각 행의 태그로 BEST 1 + WORST 1 선택
    → 적정 2·조정 필요 2의 범주와 각 후보의 근거 공개
    → 중간 둘을 엄밀한 2위·3위 선형 서열로 해석하지 않음
  → 네 판단 정리
    문항에서 실제로 본 목표어 표현 1개와 그 표현을 가른 근거 1개를 짧게 연결
    화면 폭에 따라 줄바꿈하여 근거까지 모두 표시

직접 산출
  번역 또는 통역 산출

피드백
  의미 전달·문법 정확성·상황 적절성 확인

다듬기
  → 세 층 모두 통과: 현재 표현으로 완료 / 다른 표현 선택 시도
  → 수정 권고: 원문과 다른 수정안 작성 또는 이의 제기 근거를 남기고 최초안 유지 → 완료
```

- MJT 5개와 DCT 1회가 하나의 미션이다. 다섯 MJT는 `첫인상 판단 → 맥락 대비 판단 →
  판단하고 고쳐보기 → 이유 찾기 → 여러 초안 비교`의 서로 다른 기능을 맡는다.
- 1부 완료는 미션 완료가 아니다.
- 2단계에서는 판단을 반복하지 않고 곧바로 독립 산출한 뒤 피드백을 본다.
- 세 피드백 층을 모두 통과한 답안에는 수정을 강제하지 않는다. 그대로 완료하면 최초 산출을 최종 산출로 함께 보존한다.
- 다른 표현을 선택적으로 시도하거나 수정이 필요한 경우에는 최초 산출과 수정 산출을 구분해 보존한다.
- 수정 권고 판정에서 `수정안 확정`을 선택하면 앞뒤 공백만 다른 답을 포함해 원문과 실질적으로
  같은 답으로 완료할 수 없다. 다만 학습자는 AI 참고 판정을 보존한 채 이의 제기 근거를 남기고
  최초안을 최종안으로 유지할 수 있다.
- 여러 층이 동시에 실패하면 한 번의 수정 목표는 `의미 전달 → 목표 화용 축 → 문법 정확성` 순으로 정하되, 세 층의 독립 판정과 피드백은 모두 보여 준다.
- 콜드 오픈의 MJT 진입 행동은 `5개 장면으로 감 잡기`로 표시한다. 다섯 문항의 역할은 비슷한
  상황 반복이 아니라 판단의 깊이를 높이고 관계·부담이 달라지는 장면을 비교하는 것이다.
- 정규 개별 수행에서는 **미션 1과 미션 2를 모두 필수로 수행하고, 두 미션 모두 최초 진입 때
  3단 장면 도입을 거친다.** 미션 2는 `새로운 장면 → 장면 속 단서 → 이번 장면에서의 선택`을
  사용하며 미션 1과 사실상 같은 장면을 반복하지 않는다.
- 두 번째 카드는 현재 장면의 상대·관계·부담·채널처럼 판단에 필요한 관찰 가능한 사실만 보여 준다.
  원시 P·D·R 저장 코드, 적절성 판정, 필요한 완화·선택권처럼 정답 방향을 암시하는 평가는 넣지
  않는다. 풀어 쓴 P/D/R 칩은 관계·거리·부담을 확인하는 명시적 교수 단서로 계속 표시한다.
- 두 미션은 같은 화행·수준·언어방향·수행모드를 유지하지만, 변화축을 통제하거나 서로의 진단차원
  coverage를 보완해야 하는 실험쌍으로 구성하지 않는다.
- 3단 도입은 정규 개별 수행에서 새 사회적 맥락에 들어가 판단 기준을 조정하는 필수 학습 단계다.
  같은 미션을 다시 열 때는 한 장 요약으로 축약하거나 바로 과제로 돌아갈 수 있다. 수업시간에는
  교강사가 통역 DCT 실습만 지시할 수 있도록 통역 카드에 별도 바로가기를 둔다. 이 경로는 장면과
  원발화·산출 도구를 바로 제시하며, 건너뛴 MJT를 수행한 것으로 기록하지 않는다.
  현행 native MJT5와 DCT는 별도 `preceding_turn`을 표시하지 않고, 필요한 선행 사건을 두 문장
  `situation_ko` 안에 요약한다. 역사 native 값도 숨기며 legacy MJT4 응답 화행만 표시 호환한다.
- 피드백 상단은 `통과 수` 대신 `N개 안정 · N개 점검`으로 현재 상태를 요약한다. 개별 문법·
  화용 문제는 `수정 필요`로 명확히 표시하고 실제 수정 완료 조건과 연결한다.
- 상단에는 `장면 이해 → 표현 판단 → 직접 산출 → 피드백 → 다듬기`의 조용한 5단 horizontal
  macro progress를 사용한다. 다섯 MJT를 상단에서 동등한 단계로 펼치지 않고 본문에서
  `표현 판단 n/5`로 현재 위치를 표시한다. 스크롤 뒤에는 현재 단계 한 줄로 축약하고,
  자동 스크롤 목적지는 사이트 헤더·진행바 아래의 동일 여백에 맞춰 본문을 가리지 않는다.
- 첫 문항은 독립 Scale4다. 4점 원응답은 보존하되 적절/부적절 방향만 맞으면 인정하고, 매우/다소 차이는 참고 판정과 수업 토론에 사용한다.
- 독립 Judge3는 두 번째 MJT에서 맥락 대비를 판단한다. FixChoice는 다시 별도 Judge3 판단을 잠근 뒤
  수정안 3개를 공개해 `판단 → 권장 수정안 1개 선택` 순서를 보존한다.
- Reason은 부적절한 표현의 원인 세 가지 중 가장 큰 이유 하나를 바로 고른다. 모든 Reason 문항의
  참고 판정이 부적절로 고정된 상태에서 형식적인 적절/부적절 판단을 반복하지 않으며 확신도는 묻지 않는다.
- MultiJudge는 후보마다 Judge3를 반복하지 않는다. 네 후보를 한 화면에서 비교하면서 BEST와 WORST를
  하나씩 고른다. 현행 `contrast_plan_v1`은 적정 2·조정 필요 2이며 각 범주의 어느 후보든 선택할 수 있다.
  제출 뒤에는 범주와 개별 근거를 공개하며 유일한 1등·꼴등으로 표시하지 않는다. 과거 역할형 문항은 당시 해석을 보존한다.
- 선택지·후보 수는 수준별로 바꾸지 않는다.
- Judge3 선택지는 과소→적정→과잉의 의미 순서를 유지하며 무작위화하지 않는다. 세 선택지는
  제출 전 같은 시각적 무게를 사용하고, 가운데 `현재 상황에 맞음`에도 관계·거리·부담에 따른
  조절이라는 설명을 붙여 세 대역의 설명 밀도를 맞춘다.
- 완료 시 MJT에서 실제로 고른 선택은 비채점 trace로 수행 로그에 함께 보존한다. 네이티브 MJT5는
  `mpj_response_v2` 봉투에 두 번째 맥락 대비 판단을 포함한 다섯 문항 trace를 저장한다.
- FixChoice의 Judge3와 교정 선택은 같은 문항 응답으로 묶는다. Reason은 선택 이유 ID와 이유 유형을
  trace로 보존하며, 최초 대역 판단이나 확신도 값을 새로 만들거나 저장하지 않는다.
- 참고 판정과 일치하지 않았다는 사실만으로 오답 점수나 능력 점수를 만들지 않는다.
- 번역+통역 연계 방향은 `번역`, `통역`, `번역 우선 paired`, `통역 우선 paired`의 과목 설정형이다. 다만 저장 계약이 필요한 2차 범위이므로 현행 v5에는 한 가지 주 수행만 존재하며, 데모의 수행 방식 전환은 companion 학습 구현으로 간주하지 않는다.

### 6.2 legacy 호환

- 기존 `mission_v1/v2` MJT5, `mission_v3` MJT4, `mission_v4`는 계속 열 수 있다.
- `/learner/practice`의 샘플 데이터는 legacy 형식일 수 있어 신규 v5와 다르게 보일 수 있다.
- 샘플·데모의 수행 방식 전환 단축은 실제 학습자의 완료 계약으로 일반화하지 않는다.
- 대표 데모 `/demo/mission`의 **데모 답안 채워넣기**는 현재 문항의 참고 선택·저장된 산출 예시만 채운다.
  확인·제출은 직접 누르며 일반 학습 화면에는 노출하지 않는다. 첫 응답·기존 AI 피드백은 보존하고,
  데모 답안·이벤트는 학습 수행 기록으로 저장하지 않는다. 통역 예시에는 실제 녹음이 아님을 표시한다.

### 6.3 맥락과 전이

- P·D·R 원시 저장 코드는 학습자에게 그대로 노출하지 않는다. 풀어 쓴 학습자용 P/D/R 칩은
  판단 전에도 표시한다.
- 연구자용 역할·관계·부담 메타데이터 표를 나열하지 않는다. 세 개의 간결한 P/D/R 교수 칩은 예외다.
- 화행 명칭(요청·거절·감사…)은 노출한다 — 위 §1 메타언어 노출 원칙. 감추는 것은
  **원시 저장 코드·target feature 정본명·적절성 대역과 정답 방향**이지 화용 개념이나
  학습자용 P/D/R 교수 라벨이 아니다.
- 코드의 `target_feature`는 내부 진단 태그이며 주차·미션의 학습목표가 아니다. 학습자 화면의
  주 목표는 화행과 수행 행동으로 제시하고, feature 정본명·`화용 초점`·`목표 화용 축`을 쓰지 않는다.
  문항별 피드백에서 필요한 판단 기준은 학습자 언어로 풀어 쓸 수 있다.
- **번역 셀**의 상황문은 `나는 지금 누구에게 무엇을 하려 한다`는 1인칭 현재 장면으로 시작한다. 이어지는 문장에서 위계·권한, 접촉 이력·친밀도, 부탁이나 행위의 실제 부담이 자연스럽게 보여야 하며 문장마다 줄을 나눠 읽기 쉽게 표시한다.
- **중→한 번역 셀**도 같은 자기 발신 역할을 사용한다. 중국어 원문의 명제·화행 목적·태도·
  화용적 힘을 보존하면서 실제 관계·채널·장르에서 자연스러운 한국어 관계 실현을 선택한다.
  번역투 제거는 필요하지만 일반 한국어 교정, 존대 표현의 누적, 더 긴 산출을 화용적 우수성으로
  가르치지 않는다.
- **통역 셀**도 실제 인물 관계·용건·부담만 간결하게 서술한다. “학습자 통역사인 당신”·“한국인 원발화자”·“중국인 청자”·A/B/C 소개를 넣지 않으며 1인칭 훈련 시점을 허용한다. 과거 저장 문구의 알려진 역할 소개는 표시할 때 제거한다. 사건 자체를 화면에서 임의 교정하지 않으며 개연성 결함은 콘텐츠 수정·검수로 해결한다(DEC-20260907-02).
- **중→한 통역 셀**은 중국어 원발화를 화면에 쓰지 않고 듣기 버튼으로 제시한다. 학습자는 최대
  허용 횟수 안에서 원발화를 듣고 한국어로 통역해 녹음한다. 자동 전사 뒤에는 자신이 말한 한국어와
  같은지 직접 확인·수정해야 제출할 수 있다. 음성 파일은 저장하지 않고 확정 전사만 학습 기록과
  피드백에 사용하며, 번역용 어휘 힌트는 표시하지 않는다.
- 통역 원발화는 ElevenLabs 디자인 목소리를 언어별 1개로 고정한다(한국어 여성·중국어 남성).
  한국어는 수준과 무관하게 0.85배속, 중국어는 초·중급 0.70배속·고급 0.80배속을 적용한다.
  인물별 성별·연령 배정은 하지 않는다. 제공자 키 부재·장애 시에는 같은 언어의 OpenAI
  음성으로 대체하고 실제 제공자·모델·목소리를 응답 헤더로 구분한다. 대체 음성을 동일한
  목소리나 품질로 간주하지 않는다(DEC-20260907-03).
- `상대`에는 학습자가 마주한 상대의 역할·관계만 표시한다. 학습자 자신의 역할이나 `화자 → 상대` 도식은 함께 넣지 않는다.
- `첫인상 판단`은 소박한 규칙이 깨지는 적절한 대비 상황이다.
- `맥락 대비 판단`이 만든 Anchor A를 `판단하고 고쳐보기`와 `왜 문제일까`가 같은 상황문·관계로
  공유한다. 이 `A→A→A` 반복은 현행 topology 계약이며 문항 중복 결함으로 판정하지 않는다.
- `여러 초안 비교`는 P·D·R 중 한 축만 바꾼 대비 사건이다.
- DCT는 같은 PDR의 새 사건으로 근접 전이를 연습한다.

주간 두 미션만으로 화행 전체의 숙달이나 넓은 상황 전이를 달성했다고 표시하지 않는다.
두 미션은 핵심 화용 판단을 복수 맥락에서 다루는 수업 기회이며, 실제 전이와 학습효과는 학기
전체 PDR 순환과 통합 과제 수행 자료로 별도 확인한다.

## 7. 미션 화면과 스캐폴딩

### 7.1 상황 제시

- 관계와 장면은 자연어로 제시한다.
- `speaker_lower`·`acquaintance`·`high` 같은 P·D·R 원시 저장 코드는 노출하지 않는다. 대신
  `P · 상대 높음`, `D · 아는 사이`, `R · 부담 높음`처럼 풀어 쓴 칩은 판단 전에도 표시한다.
- 장면문은 상대·과업·접촉 이력·실제 부담처럼 학습자가 관찰할 수 있는 사실만 제시한다.
  기록 목적, 즉각 반응 요구 여부, 상대의 권리·의무·선택권, 필요한 완화·명료성처럼 답의
  방향을 알려 주는 평가 기준은 장면문에 노출하지 않는다.
- 상대 역할과 학습자와의 관계는 자연어 한 줄로 합쳐 보여 주며 `상대`와 `관계`를 연구자용
  분류표처럼 쪼개지 않는다. P/D/R 교수 칩은 이 관계 문장과 별도로 표시할 수 있다.
- 상황 카드에는 `지금, 이 장면`이라는 진입 신호와 문장 위계를 두되, 원시 메타데이터 표를 만들지 않는다.
- 메신저 장면은 대화형, 이메일은 문서 초안형, 대면·전화는 발화형 시각 문법을 사용한다.
- 현행 native MJT5의 MJT와 DCT는 target-language 선행 발화를 별도 카드로 표시하지 않는다.
  거절·반대 등 응답 화행에 필요한 앞선 사건도 `situation_ko`에 요약한다. legacy MJT4 응답 화행의
  저장·표시 호환만 유지한다.
- UI용 `channel`은 연구·난이도 축이 아니라 장면을 정확히 표현하기 위한 메타다.
- 통역은 듣기·녹음·전사 확인의 오디오 프레임을 사용한다.
- 미션 상단은 단일 target feature를 목표처럼 노출하지 않고 `화행 + 학습자가 수행할 행동 문장`으로
  풀어 쓴다. 이 주차 목표와 `장면 이해 → 표현 판단 → 직접 산출 → 피드백 → 다듬기`의 5단 macro
  progress는 사이트 헤더 아래에 고정해 긴 화면에서도 현재 위치를 유지한다.
- MJT 5개 뒤에는 직접 산출 전 one-point recap을 사용한다. 각 문항에서 실제로 본 목표어 표현 한
  조각과 그 표현을 가른 구체 근거 하나만 `표현 → 메모`로 짧게 연결한다. 화면 폭에 따라
  자연스럽게 줄바꿈하며 말줄임으로 판단 근거를 숨기지 않는다. 새 모범답안·추상적 교훈·일반
  흐름 문장은 만들지 않으며 MultiJudge도 적정 표현의 핵심 근거 한 점만 남긴다.
- 직접 번역·통역 단계는 recap 뒤에 상황과 산출 도구로 곧바로 진입하며, MJT 내용을 일반 설명문으로 다시 반복하지 않는다.
- MJT와 직접 표현 단계 모두 장면 카드와 실제 대화·산출 도구를 별도 패널로 분리한다. MJT 대화 패널은 `표현 비교`, 판단 대상 말풍선은 `AI 번역 초안` 또는 `AI 통역 초안`으로 표시한다. 번역 화면의 단계명은 `번역하기`, 장면 신호는 `지금, 직접 번역할 장면`, 메신저 상태는 `메시지 작성 중`으로 표시한다. 장면 카드는 고정 최소 높이를 두지 않고 공통 패딩·행간·문장 간격을 사용해 내용에 맞는 높이로 표시한다.
- 번역에서 막힐 때 여는 힌트는 입력 말풍선 바로 위 우측의 작은 보조 행동으로 둔다. 기본은 접힘 상태이며, 펼칠 때는 산출을 막는 비화용적 내용 어휘·고유명사·전문용어 두 개만 한 줄로 보여 준다. MJT에서 학습한 완화 표지나 정답 문장 구조는 제공하지 않고, 열람 여부와 최초 시각을 비채점 trace로 남긴다. 통역에는 힌트를 제공하지 않으며, 완성 답안은 제출 뒤에 공개한다.
- MJT의 장면·메신저는 판단 대상인 문제 영역으로 가볍게 유지하고, 선지 카드는 네이비 상단선으로 `여기서부터 응답`임을 구분한다.

### 7.2 판단과 피드백

- AI 판정은 현재 수업 기준의 참고 판정이며 절대적 판결로 표시하지 않는다.
- 의미, 명백한 문법 문제, 화용 초점을 분리한다.
- 의미층은 사실·조건·핵심 화행 내용의 보존을 확인하고, 강도·완화·선택권·명료성·범위 같은 목표 화용 자원의 변화는 상황 적절성 층에서만 다룬다. 이 경계는 요청·거절·감사·사과 등 화행에 관계없이 동일하다.
- “더 길게”, “더 완곡하게”를 일반 정답 규칙으로 가르치지 않는다.
- Reason은 적색 오류 경고 없이 `이 표현이 상황에 맞지 않는 이유가 무엇인지 고르세요`로
  단일 주원인만 묻는다.
- Reason의 오답도 실제 표현이나 인접한 화용 쟁점을 근거로 한 그럴듯한 설명으로 만들되, 주원인과 동등하게 방어 가능해서는 안 된다.
- 피드백 화면은 내 답을 가장 선명하게 보여 준 뒤 `의미 전달 / 문법 정확성 / 상황 적절성`을 동등한 세 기준으로 제시한다. 번호는 쓰지 않으며, 각 카드는 상단의 기준·상태와 하단의 구체적 피드백을 안정된 2단 위계로 보여 준다.
- `AI`는 피드백 주 제목에서 반복 강조하지 않고 하단 참고 고지에만 남겨, 학습 흐름과 생성 주체 투명성을 함께 지킨다.
- 세 층 모두 통과하면 `이 표현으로 완료`를 주 행동으로, `다른 표현도 시도해보기`를 보조 행동으로 제공한다. 하나라도
  수정이 권고되면 `한 번 다듬어보기`를 주 행동으로 연결한다. 학습자는 원문과 다른 수정안을
  확정하거나, 이의 제기에 맥락 판단 근거를 남긴 뒤 최초안을 최종안으로 유지할 수 있다.
- 이의 제기는 AI 참고 판정을 덮어쓰지 않는다. 최초안·최종안·AI 피드백·이의 조건과 이유·
  `retained_first_response` 또는 `revised_response` 최종 결정을 한 수행 안에 함께 보존한다.
- 참고 표현과 이의 제기는 유지하되, 상세 판정 근거는 학습자 주 흐름에 노출하지 않는다.
- 일반 `담화 전체 확인`은 세 기준과 구체 피드백을 반복하므로 학습자 주 흐름에 표시하지
  않는다. 실제 초점 이탈 경고가 있을 때만 `추가로 확인할 부분`을 조건부로 제시한다.
- 수정 화면은 `이번 수정 목표 → 수정 전 → 수정 후 입력` 순서다. 수정 목표는 AI 피드백 문단을 반복하지 않고 판정 결과에서 도출한 한 줄 행동으로 제시한다.
- 완료 화면은 수정 전후와 바뀐 부분, 해당 답안에 맞춘 한 줄 조언, 저장 상태와 다음 행동만 남긴다. 판정 결과가 없을 때만 일반 원칙 한 줄을 대체 문구로 사용하고, 예외 규칙·표현 목록·라운지 진입을 완료 단계에서 반복하지 않는다.

### 7.3 주장 경계

- **조언 문구는 처방이 아니라 선택지로 제시한다 (불변조건).** 완료 화면의 한 줄 조언과
  수정 목표는 하나의 정답 행동을 지시하지 않고, 학습자가 택할 수 있는 대안적 방식으로
  쓴다(`…해 보세요` 아닌 `…하는 방식도 시도해 볼 수 있어요` 계열). 근거: 상황이 달라지면
  적절한 표현도 달라지므로 단일 처방은 이 연구의 구인과 어긋난다. MJT가 후보 비교로
  단일 정답 인상을 피하는 것(`TRC-20260729-02`)과 같은 계열의 규칙이며, 화행별 조언
  10종 전부에 적용한다(`4e0c494`).
- 미션 점수 하나로 화용 능력 전체를 나타내지 않는다.
- 시도 횟수·힌트 감소를 성장 지표로 표시하지 않는다.
- 발음, 유창성, 성조 정확성을 채점하지 않는다.
- 실제 상호작용 능력이나 교육 효과를 자동으로 입증한다고 주장하지 않는다.
- 두 미션을 수행했다는 사실만으로 해당 화행의 모든 상황을 일반화하거나 숙달했다고 주장하지 않는다.

## 8. 독립형 정적 라운지와 비기록 경계

### 8.1 역할

라운지는 핵심 미션 밖에서 짧은 표현·번역·문화 사례를 둘러보는 저부담 선택 공간이다.
학습자 하단의 세 번째 탐색 경로이지만 연구 구인과 핵심 수직 흐름에는 포함하지 않는다.

- 미션과 무관
- 점수·감점 없음
- 연구·학습 수행 기록에 미반영
- 별도 탭과 별도 시각 언어
- 미션 완료를 입장 조건으로 사용하지 않음
- 강좌·주차·배정·미션 ID와 연결하지 않음

### 8.2 현행 경로와 모듈 설계

```text
/learner/lounge
/learner/lounge/decode
/learner/lounge/culture
/learner/lounge/literal
```

구 `decoder` 경로는 `decode`로, `theater`·`meme` 경로는 라운지 허브로 안전하게 돌린다.
구 라운지 소스는 현행 실행 경로에서 사용하지 않아 제거하고, 이력 확인은 삭제 전 커밋 `82c3abee5333079864f039ef5ef006cacc6c5987`에 보존한다:
[LoungeHome](https://github.com/sylim-research/PRAGMA/blob/82c3abee5333079864f039ef5ef006cacc6c5987/src/pages/learner/LoungeHome.tsx) ·
[LoungeCorner](https://github.com/sylim-research/PRAGMA/blob/82c3abee5333079864f039ef5ef006cacc6c5987/src/pages/learner/LoungeCorner.tsx) ·
[mockLounge](https://github.com/sylim-research/PRAGMA/blob/82c3abee5333079864f039ef5ef006cacc6c5987/src/lib/lounge/mockLounge.ts).

| 모듈 | 정적 사례 | 판단 초점 |
|---|---:|---|
| 해독실 | 10개 | 숫자·신조어·말투에 숨은 뜻과 태도 해독 |
| 문화코드 | 10개 | `春运`처럼 번역만으로 설명하기 어려운 관습·제도·사회 현상 이해 |
| 직역 함정 | 10개 | `발표→发表`처럼 단어·한자어·결합 관계의 기계적 대응 교정 |

문화코드에는 `520`·`YYDS`·`破防`처럼 해독실과 겹치는 숫자·인터넷 표현을 넣지 않는다.
직역 함정에는 관계·직접성·강도 판단처럼 핵심 미션과 겹치는 화용 문제를 넣지 않는다.

### 8.3 수준 정책

- 화면에서 입문·중급·고급 선택을 제공하지 않는다.
- 라운지는 하나로 열고 콘텐츠 안에서 표현 난도를 자연스럽게 변주한다.
- 현재 데이터에 난이도·수준 메타나 개인화 규칙을 두지 않는다.
- 프로필의 중국어 수준과 라운지를 자동 매핑하지 않는다.

### 8.4 현재 구현 범위

현행 구현은 TypeScript 정적 카탈로그 30개와 학습자 화면만 포함한다. 기존 관리자 자산의 오류
유형·표현 후보·원자료 분석에서 얻은 지식은 라운지 정의에 맞는 경우에만 일방향으로 재구성할 수
있지만, 핵심 미션의 문장·후보·해설을 그대로 공개하거나 런타임으로 자동 연동하지 않는다.

- 라운지 전용 DB·Edge·관리자 입력 화면 없음
- 앱 내부 AI 발굴·웹 수집·자동 게시 파이프라인 없음
- localStorage·sessionStorage를 포함한 완료·진행 저장 없음
- XP, 배지 경제, streak, 리더보드, 개인화 추천 없음
- 학습자가 접속할 때 즉석 생성하지 않음
- 모든 사례는 `source_checked`이며 운영 반영 후에도 사례별 연구자 최종 판정이 필요함

최상단은 PRAGMA의 남색·노랑 브랜드를 유지하고, 라운지 장면 카드에는 청록·인디고·코럴
솔리드 색을 사용한다. 허브는 카탈로그 수를 홍보하지 않고 화면 중앙에 밀도 있게 세 모듈만
제시한다. 모듈 화면은 데스크톱에서 `max-w-4xl`·330px 2열 카드로 줄이고 맥락·제목·질문을
짧게 제시한다. 선택 후 정답 선택지는 `✓`, 선택한 오답은 `×`로 표시하고 아래에는 `한 줄 포인트`
하나만 둔다. 문화코드의 긴 중국어 원문은 시나리오 열과 글자 크기를 조절해 한 줄로 유지한다.
상세 사실·맥락·출처 데이터는 보존하되 학습자 화면에 장문으로 반복하지 않으며, 모바일은 자연
스크롤을 허용한다.

세 모듈의 질문은 모두 잘된 번역을 고르는 긍정형으로 제시한다. 특히 직역 함정도 오류 표현을
찾게 하지 않고 가장 자연스러운 번역을 고르게 하며, 기계적 대응은 오답 보기로만 남긴다.
중국어 원문과 중국어 선택지는 프로젝트 표준 `Noto Serif SC` 클래스(`font-zh`)를 사용한다.

콘텐츠 작성 경계는 다음과 같다.

```text
기존 PRAGMA 지식 자산 또는 소규모 외부 조사
→ 핵심 미션과 동일 문장·후보·해설인지 오염 검사
→ 라운지용 독립 상황·선택지·짧은 해설로 재구성
→ 출처·내용 확인
→ 연구자 최종 판정
```

문화코드는 `확인된 사실`, `문화 맥락`, `번역 해석`을 별도 필드로 보존하며 출처 URL과 확인일을
갖는다. AI는 필요할 때 앱 밖의 조사 도구로 후보를 제시할 수 있으나 앱 기능이나 자동 게시자로
구현하지 않는다.

## 9. 기록

기록 화면은 학습자가 실제로 수행한 미션과 수정 이력을 확인하는 곳이다.

- 코어 수나 생성 성공 수를 학습 성취처럼 표시하지 않는다.
- 라운지 활동을 합산하지 않는다.
- 연구동의 상태를 학습 진행률로 표시하지 않는다.
- 기술적·탐색적 과정 자료와 학습자용 진행 표시를 구분한다.
