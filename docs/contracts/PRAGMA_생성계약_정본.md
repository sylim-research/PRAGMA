### 2026-09-04 중→한 번역·통역 방향 실현 계약

논문 버전의 정식 중→한 경로는 **번역과 통역을 모두** 지원한다. 번역에서 학습자는 제3자
번역자가 아니라 위 표의 자기 발신 상황 화자이며, 통역에서는 원발화자 A와 청자 B 사이의 별도
통역사 C다. 두 모드의 역할은 합치지 않고 기존 한→중 번역·통역 경로와 데이터도 유지한다.

- 코어·MJT5·DCT1의 모든 원문은 요청된 화행을 유지한다. 다른 화행의 사건으로 교체하거나
  보조 화행을 중심 목적으로 승격하지 않는다.
- 모든 한국어 판단 후보·수정안·참고안은 중국어 원문의 명제, 화행 목적, 태도와 화용적 힘을
  보존한다. 등가는 축자역이 아니므로 한국어의 관계·채널·장르에 맞춘 형식 조정은 허용한다.
- 자연성은 실제 한국어 담화에서 판단한다. 중국어 어순·불필요한 주어 반복·명사화·직역 결합이
  남은 번역투는 `unnatural_language`, 화행·의도·힘의 변경은 `gate1_violation` 또는
  `internal_inconsistency`, 대역 오판은 `band_mismatch`로 기존 코드 안에서 처리한다.
- 일반 한국어 문법 교정, 존대·사과·감사 표현의 누적, 문장의 길이는 화용적 우수성의 가산점이
  아니다. 더 길거나 더 공손한 산출을 자동으로 더 좋은 답으로 판정하지 않는다.
- 네이티브 구조 `scale4 → judge3 → fix_choice → reason → multi_judge → DCT`와
  `X→A→A→A→Y→C` topology는 방향 때문에 바꾸지 않는다.
- 중→한 통역 DCT는 중국어 원발화 텍스트를 화면에 노출하지 않고 TTS로 들려준다. 학습자는
  한국어로 통역해 녹음하고, STT가 만든 한국어 전사를 직접 확인·수정한 뒤 제출한다.
- 원발화 재생 횟수는 미션의 `replay_limit`을 따르고 기본값은 2회다. 통역에는 내용 어휘 힌트를
  제공하지 않는다. 녹음 음성은 STT 처리와 로컬 확인에만 사용하고 학습 기록에는 저장하지 않으며,
  학습자가 확정한 전사만 산출·피드백·완료 기록으로 사용한다.
- 통역의 한국어 산출도 중국어 원발화의 명제·화행 목적·태도·화용적 힘을 기능적으로 등가 재현한다.
  다만 참여자와 P·D·R의 준거는 자기 발신 번역이 아니라 기존 A↔B·통역사 C 계약을 따른다.

**통역 셀 역할 구조 (자연어 검사보다 먼저 구조로 고정):**

```text
A = 원발화자 (source speaker)      — 화행 목적의 소유자
B = 목표 청자 (target addressee)
C = 학습자 통역사 (interpreter only) — 언어적 실현자
pragmatic relation = A ↔ B
```

**구조값으로의 고정 (`context_spec.interpreter_role_contract`):** 위 역할 구조는 상황문의
자연어 표현에 맡기지 않고, 통역 셀에 한해 서버가 다음 필드를 주입해 고정한다.

```ts
interpreter_role_contract: {
  source_speaker:     "A",        // 원발화자
  target_addressee:   "B",        // 목표 청자
  learner_interpreter:"C",        // 학습자 통역사
  pdr_relation:       "A_to_B",   // P·D·R 준거
}
```

네 값은 모두 고정 리터럴이며 다른 값을 가질 수 없다. 번역 셀과 이 계약 이전의 기존
코어에는 이 필드가 없어도 된다(optional). 역할 비대칭이 문장 표현이 아니라 **데이터
구조로** 보장된다는 뜻이며, 자연어 검사는 그 위에 얹히는 2차 방어선이다.

**핵심 문장 (정본):** 통역 셀의 P·D·R은 원발화자 A와 청자 B의 관계를 나타낸다.
학습자 통역사 C는 이 관계의 당사자나 화행 목적의 소유자가 아니며, P·D·R을 근거로
A의 발화를 자의적으로 개선하는 것이 아니라 A의 의미·의도·화용적 힘을 B에게
기능적으로 등가하게 재현한다.

**등가 재현 ≠ 축자역:** 화용적 힘을 목표어로 등가하게 실현하기 위한 **형식 조정은
필수(허용)** 이고, A의 힘·태도·화행 목적의 **변경은 불허**다. 통역 셀에서 학습자의
화용 판단이 놓이는 자리는 이 등가 실현 수단의 선택이다.

**통역 셀 hard fail 조건:**

1. A 또는 B를 `학습자`라고 부름
2. 학습자가 원발화의 화행을 직접 수행함 (`학습자가 직접 요청·사과·불만을 말한다`)
3. 학습자가 목표 청자 역할을 겸함 (감사·사과 등을 받는 당사자)
4. 자기 발화를 자기가 통역함
5. P·D·R을 학습자와 B(또는 학습자와 A)의 관계로 계산함

**서술·문체 규칙:** 상황문은 학습자(통역사) 관점으로 서술하고, 원발화자 A의
1인칭(`저는`·`나는`) 서술을 금지한다. `직접`은 3단 처리 — hard fail(`학습자가 직접
[화행]한다`, `통역 없이 직접 대화한다`) / 경고(`A와 B가 직접 협의한다`류 모호 표현) /
허용(`학습자가 현장에서 직접 통역한다`). 생성 문체에서는 통역 상황문에 `직접`을
쓰지 않는 것을 기본으로 한다.

**검사 층위:** 동사 목록 정규식은 경고 보조 장치다(`듣는다` 자체는 금칙어가 아니다 —
원발화를 듣는 것은 통역사의 본질 행위이고, 화행의 수신 당사자가 되는 것이 결함이다).
결함 판정은 `누가 어떤 화행을 누구에게 하는가`의 논항 구조로 하며, 최종 의미 정합성은
카나리 사람 검수로 확인한다.

**규칙 대응 (저장 전 자동검사):**

| 규칙 | 층위 | 조건 |
|---|---|---|
| R25 | fail | 신규 통역 코어의 `context_spec`에 A/B/C 및 P·D·R=A↔B 역할 계약이 없음 |
| R16 | fail | 통역 셀인데 이중언어 화자·통역 개입 장면이 불명확함 (위 hard fail 5조건) |
| R16 | warning | 통역 역할에 사람 확인이 필요한 경계 사례 |

R16은 **확정 위반은 fail, 판단이 필요한 경계 사례는 warning**으로 2단 운용한다.
warning은 저장을 막지 않고 검수 큐에 표시한다. R25는 구조값 부재를 막으므로
자연어 검사(R16)가 통과하더라도 역할 계약이 없으면 저장되지 않는다.

PRAGMA는 교육 우선형 학습 플랫폼이며, 수업 과정에서 연구 가능한 자료를 남긴다. 생성·평가·저장 계약은 교육 경험을 검사 도구처럼 축소하기 위한 장치가 아니라 다음을 보장하기 위한 기술 계약이다.

- AI 생성물이 사람 검수 없이 학습자에게 공개되지 않는다.
- 상황 적절성, 의미 충실성, 문법·형식 문제를 서로 섞지 않는다.
- 생성물과 학습자 수행의 버전·출처·변경 이력을 식별할 수 있다.
- 현재 자료만으로 교육 효과나 실제 상호작용 능력을 인과적으로 주장하지 않는다.

허용되는 제품·논문 설명은 다음 범위다.

> 한·중 통번역 상황에서 맥락 단서를 해석하고, 화행별 핵심 특징을 판단·조절하여 표현으로 산출하는 능력을 지원하고 기록한다.

핵심 구성개념은 `상황 기반 화용적 의사결정 및 표현 조절 능력`이다. `전반적 화용 능력`이나 실제 상호작용 능력 전체를 측정한다고 주장하지 않는다.

**정체성 문장 (2026-08-06 확정 — 계약·학습자 구조·논문 공통 기준):**

> 1. PRAGMA는 학습자가 상황에 맞는 외국어 화행을 자유롭게 만들어 내도록 하는 도구가
>    아니라, 주어진 원발화의 의미와 의도를 보존하면서 특정 수신자와 상황에 적절한
>    목표어 표현을 판단·산출·수정하도록 지원하는 통번역 학습 워크플로우이다.
> 2. 번역 모드에서 학습자는 발신자 관점에서 주어진 원문을 읽고 목표어 텍스트로
>    옮기고(자기 발신 상황의 원문 제약형 번역), 통역 모드에서 학습자는 별도의
>    통역사로서 원발화자 A의 음성을 듣고 청자 B에게 목표어 발화로 옮긴다. 역할은
>    모드마다 다르지만, 두 모드 모두 원문 제약과 상황 제약을 동시에 만족해야 한다.

일반 L2 산출 교육과의 경계는 **원문 제약**이다 — "이 상황에서 무엇을 말할까"가 아니라
"이 원발화를 어떻게 옮길까"를 묻는다.

세부 정체성은 `docs/research/PRAGMA_PRODUCT_RESEARCH_IDENTITY_2026-07-28.md`를 따른다.

## 2. 데이터 층위

```text
scenario_core_v3
  └─ 선택한 코어만 Full Mission으로 승격
       ├─ 현행 소스 계약: mission_v5 네이티브 MJT5 + 미니 담화 DCT1
       └─ legacy 읽기 호환: 과거 mission_v5 MJT4 + 미니 담화 DCT1
            └─ 사람 검수 후 reviewed
                 └─ 학습자 수행과 feedback/revision 기록
```

### 2.1 코어

- JSON 스키마: `scenario_core_v3` (v2는 읽기 호환 — 분량 정책 `effective_chars_v1` 도입으로 v3)
- DB 외곽 `content_format='scenario_core_v1'`은 기존 행·RPC 호환을 위해 유지되는 이름이다.
- 코어는 상황, 관계, 출발문, 선행 발화와 요약 메타를 가진다.
- 코어에는 MJT 문항과 DCT 참고안이 없다.
- 495 본 배치는 코어만 생성한다. 495개를 Full Mission으로 일괄 승격하지 않는다.

### 2.2 Full Mission

- 현행 소스의 `mission_v5`는 네이티브 MJT5+DCT1이다. 다섯 MJT의 기능은 `첫인상 판단 →
  맥락 대비 판단 → 판단하고 고쳐보기 → 이유 찾기 → 여러 초안 비교`이며 정확한 유형 순서는
  `scale4 → judge3 → fix_choice → reason → multi_judge`다.
- 네이티브 `judge3`는 첫인상 장면과 다른 사건을 DCT 앵커 P·D·R에서 판단하게 해 맥락 대비를
  독립 수행한다. 과거 `mission_v5` MJT4 행은 삭제·백필하지 않고 읽기 호환한다.
- 런타임 피드백 schema는 `feedback_v1`을 유지한다.
- 현행 미션·피드백 `prompt_version` 문자열은 promptSnapshot·Prompt Harness가 정본이다.
  이 문서에 버전 문자열을 복사해 두지 않는다.
- 코어를 선택해 개별 승격하며, 생성 직후 상태는 `generated`다.
- `mission_v1/v2`는 legacy MJT5, `mission_v3`(2026-07-28 MJT4 기준선)·`mission_v4`는 열람·회귀 호환용으로 보존한다.
- 기존 v1~v4를 v5로 백필하거나 신규 v5와 같은 생성 계열로 취급하지 않는다.
- 생성·자동 품질 점검·교수자 검수의 단위는 완전한 MJT5+DCT1 미션 한 건이다. 화행 학습 주차에는
  같은 `speech_act`·수준·언어방향·수행모드의 승인 미션 두 건을 독립적으로 편성한다.
- 주차와 각 미션의 학습목표는 특정 `target_feature` 하나가 아니라 해당 화행의 핵심 화용 판단
  묶음이다. 단일 `target_feature` 필드는 현행·legacy 호환과 문항 진단에 사용할 수 있지만,
  그 값 하나로 미션의 교육 범위를 대표하거나 완료를 판정하지 않는다.
- 두 미션 사이 A/B 역할, 변화축, 합산 진단차원 coverage를 생성계약으로 만들지 않으며 pair-first
  생성이나 pair lifecycle을 사용하지 않는다. 기존 `speech_act_ab_v1` 배정 필드는 역사 데이터
  호환용으로 남길 수 있지만 표준 생성·검수·편성은 이를 작성하거나 요구하지 않는다.

### 2.3 수행 로그

- 학습자 수행은 기존 `learner_mission_logs` 계열을 사용한다.
- 최초 산출, 제공된 피드백, 수정 산출, 완료 상태와 미션 식별자를 연결한다.
- MJT 응답은 기존 `context_judgment` JSONB에 저장한다. 네이티브 MJT5는 `mpj_response_v2`,
  legacy 4문항 미션은 `mpj_response_v1` 봉투를 사용하며 별도 DB 컬럼은 추가하지 않는다.
- 봉투에는 `mission_schema_version`, 문항별 선택 trace, 선택적 `production_support`와 `learner_dissent`를 넣는다.
- Scale4는 4점 원응답을 남기되 적절/부적절 방향만 정오 판단에 사용한다. 독립 Judge3는 선택한
  대역을 별도 trace로 남기고, FixChoice는 최초 대역과 선택한 교정안 위치를 함께 남긴다.
  Reason은 주원인 선택만 남기며 v4 이후 확신도는 생성·노출·저장하지 않는다.
- MultiJudge는 후보별 Judge3를 반복하지 않고 `best_candidate_index`와 `worst_candidate_index`만 남긴다. 번역의 내용 어휘 힌트는 열람 여부와 최초 열람 시각을 `production_support`에 비채점 trace로 남기며, 통역에는 힌트 trace를 만들지 않는다.
- 이 trace는 응답 재구성과 문항 품질 점검을 위한 비채점 기록이다. AI 참고 판정과의 일치 여부를 학습자 점수로 자동 환산하지 않는다.
- 로그가 존재한다는 이유만으로 연구 이용 동의가 성립하지 않는다.
- 이후 새 로그 필드나 분석 의미 변경은 DB 스키마와 연구 주장 범위를 먼저 보고한다.

## 3. 생성 조건과 표본 층위

### 3.1 연구 구인행렬

```text
speech_act 9 × P 3 × D 3 × R 3 = 243셀
```

- `P`: 상대적 권력
- `D`: 사회적 거리
- `R`: 해당 화행의 상황 부담

중국어 화행 연구에서 직접 근거가 확인된 범위에 한해 R의 조작적 의미를 다음처럼 구체화한다.

- 요청: 상대에게 요구되는 노력·시간·자원과 요청 수행의 부담
- 사과: 잘못이 초래한 침해·피해의 심각도
- 제안: 상대 의향과의 충돌, 제안 수용의 난이도와 사안의 중대성

세 정의를 다른 여섯 화행에 기계적으로 일반화하지 않는다. R 필드·3단 수준·학습자 UI는 유지한다.

P·D·R은 상황 적절성 판단의 조건이다. 직접성과 공손성을 하나의 축으로 합치지 않는다.

### 3.2 전달 커버리지

```text
speech_act 9 × learner_level 3 × task_mode 2 = 54셀
```

- `learner_level`: 입문·중급·고급의 교육 지원 수준
- `task_mode`: `translation | stt_interpreting`

54셀은 교육용 전달 커버리지이며 243셀과 같은 연구 구인행렬이 아니다. PRAGMA 수준을 CEFR·ACTFL 등급에 직접 대응시키지 않는다.

### 3.3 편성·사건 메타

- `domain`: 일상·학업·직장
- `theme`: 강좌 편성 영역
- `topic`: 구체적 사건 시드
- `industry`: 직장 장면의 분야 메타
- `business_function`: 직장 장면에서 수행하는 실제 업무 기능 메타
- `context_spec`: P·D·R과 사건 시드의 내부 호환성 해결층

이 값들은 필요하지만 P·D·R과 같은 독립 화용 구인으로 과장하지 않는다.
도메인은 일상·학업·직장 3분류를 유지하며 `전문·학술`을 네 번째 도메인으로 만들지 않는다.
전문성은 수준·산업·직무·theme/topic의 조합으로 표현한다. 별도 근거가 생기기 전 배치 계획의
수준별 일상·학업·직장 주변분포는 1:1:1을 유지한다.

## 4. 화행 목표와 진단용 target feature

교육용 화행은 9종이다.

- 요청
- 거절
- 감사
- 사과
- 제안
- 초대
- 반대
- 칭찬
- 직접 불만

9화행 모두 사람이 작성한 진단용 `target_feature` 카탈로그를 가진다. 칭찬하기와 칭찬 대응은
분석상 구분된 feature로 보존하되, 현재 `compliment` 코어의 자동 승격 기본값은 칭찬하기
feature다. 이 기본값은 주차·미션의 학습목표가 아니라 생성·판정 호환을 위한 내부 기본값이다.

계약 원칙:

- `targetFeatures.ts`의 코드·version·band schema가 실행 정본이다.
- AI가 target feature, band code, learner label을 임의로 만들지 않는다.
- 모든 band는 인간 캘리브레이션 전 `proposed` 지위다.
- 표현 자원은 가능한 실현 수단이지 고정 정답 목록이 아니다.
- 한 화행에 복수의 기능적 head와 supportive move가 함께 나타날 수 있다.
- 상황 적절성, 직접성·공손성, 화행별 target feature를 분리해 해석한다.
- `请`·`谢谢`·`不好意思`·호칭·완화어의 개수나 중첩 자체를 적절성의 긍정 증거로 쓰지
  않는다. 관계·부담·화행 목적에 비해 과도한 누적은 더 좋은 답이 아니라 과잉 관계조정일 수
  있으며, 기존 AI 품질점검의 대역 정합 항목과 교수자 최종 검수에서 확인한다. 새 점수나 finding
  code를 만들지 않는다.
- 교육 목표의 우선 키는 `speech_act`다. `target_feature`는 문항별 주원인·대역·피드백과
  근거 귀속을 재현하기 위한 내부 진단 태그이며, 학습자에게 주차·미션 목표로 제시하지 않는다.
- 거절에서는 표면적 거절형만으로 상호작용 기능을 확정하지 않는다. 실제 최종 불수락과 상대의
  호의·비용을 인정하며 후속 수락 가능성을 남기는 의례적 1차 사양은 완충 대역의 강약이 아니라
  장면 전체의 순차 결과로 구분한다. 이 구분을 새 band·필드·자동 점수로 만들지 않고 교수자 검수와
  수업자료의 경계 질문으로만 사용한다.
- 요청에서는 문장 내부 완화, 외부 보조행위, 요청 본체의 담화상 앞뒤 배치를 서로 다른 실현
  층위로 확인한다. 특정 장치의 유무·개수나 직접성만으로 적절성을 자동 판정하지 않으며, 이 구분도
  새 점수·필드를 만들지 않고 교수자 수업자료의 점검 질문으로만 사용한다.
- 하나의 미션은 해당 화행에 관련된 명료성·관계 조정·부담·선택권·책임 범위 등 복수의 화용
  차원을 MJT와 DCT에 걸쳐 다룬다. 정확한 다차원 coverage 저장 형식은 구현 전에 별도 version으로
  확정하며, 기존 단일 필드에 복수 의미를 억지로 덮어쓰지 않는다.

### 4.1 `usable_facts` 폐쇄 목록

명제적 supportive move는 코어의 `usable_facts` 또는 출발문에 있는 사실만 사용할 수 있다.

- 최대 8개
- 목록 밖의 이유, 대안, 수리, 보상, 재발 방지 약속, 새 일정 추가 금지
- 사실의 유무를 MJT 정답 단서로 사용 금지
- 관습화된 사과·인사, 완화어, 호칭 같은 비명제적 자원은 폐쇄 목록 대상이 아니다.

### 5.4 현재 콘텐츠 버전의 다중 모델 검수 (2026-08-27 사용자 결정)

기존 코어만의 오프라인 독립 감사 정책을 다음 승인된 수업 콘텐츠 검수 흐름으로 대체한다.

1. **규칙 검사:** 현재 저장 원본에 기존 구조·형식 규칙을 적용한다. 치명적 오류가 있으면
   뒤의 API 호출을 차단하고 수정 후 진행한다. warning은 진행할 수 있다.
2. **OpenAI 품질 점검:** 코어·MJT5·DCT1 전체 또는 주차 공통 자료·교수자 고유 메모의 의미·화용·
   언어·수준·해설 일관성에서 문제 후보를 찾는다.
3. **Claude 독립 검토:** 동일 원본과 기준을 받되 OpenAI 판정은 받지 않는다. 대상 구성요소·문제
   유형·지적·근거·수정 방향·불확실성과 교수자 확인 필요 여부를 기록한다.
4. **OpenAI 지적별 판정:** 현재 콘텐츠·기준·Claude 지적만 받는다. OpenAI 1차 결과는 주지 않는다.
   Claude 지적마다 수용·보완·기각, 이유와 콘텐츠 근거를 남긴다. 불확실성은 판정과 별개의
   `needs_professor`로 표시한다. 원 지적은 보존한다.
5. **교수자 최종 확정:** 양쪽 결과와 원본을 확인하고 각 Claude 지적에 수정 필요·수정 없이 사용
   가능·판단 보류와 근거를 저장한다. 판단 저장은 승인이 아니다. 수정 필요·보류가 남으면 최종
   확정할 수 없으며, 모든 지적이 해소된 현재 버전에 전체 수업 사용 근거를 남겨 최종 확정한다.
   OpenAI 1차 점검의 `fail`이 남으면 별도의 명시적 사용 근거가 필요하다. 기존 생성 critic의
   `quality_check` override나 Claude 지적별 판단을 이 근거로 대신하지 않는다.

- 단위는 수업에 채택할 현재 콘텐츠 버전이다. 미션은 편성 전에, 주차 자료는 편성 후에 검수한다.
  같은 원본을 출력 형식마다 중복 검토하지 않는다. 재사용 미션 해설은 원 미션의 현재 승인에 연결한다.
- AI 단계에는 콘텐츠 수정·공개 권한이 없다. 수용·보완은 제안이며 기각은 지적 삭제가 아니다.
  무한 토론·자동 승인·판정 평균·다수결은 하지 않는다. 독립 검토와 지적별 판정을 세 번의 독립 검증으로
  주장하지 않으며 모델 일치를 내용 타당도나 학습효과로 해석하지 않는다.
- 원본·콘텐츠 hash, 기준/프롬프트 버전, 호출 모델·응답 ID·사용량, 결과·교수자 판단을 기록한다.
  콘텐츠가 달라지면 이전 결과는 보존하되 현행 승인에 사용하지 않고 새 버전에서 1~4단계를 다시
  거친다. ‘수정 후 수용’을 수정 전 승인으로 처리하지 않는다. 과거 버전·승인·학습 기록은 보존한다.
- 승인된 검수 증거·미션 본문은 DB에서 변경·삭제를 막는다. 신규 미션 최종화는 승인과 미션·이력
  저장을 한 트랜잭션으로 처리하고 이력의 `content_review_run_id`로 사용한 검수를 연결한다.
  QA 승인 경계는 DB의 현재 원본 hash이며, 생성 provenance의 `mission_content_hash`와는 구분한다.
- 관리자 작업대에서 단계별 또는 선택 미션의 미완료 AI 단계 연속 실행을 명시적으로 시작한다.
  실행 중 원본·콘텐츠 hash가 달라지면 이후 호출을 중단한다. 유료 호출·운영 DB 적용은 §10 승인 범위를 따른다.
  성공한 단계의 반복 호출·모델 자동 강등은 하지 않고 오류·잘림·근거 불일치는 표시한다.
- 교수자 체험 감수는 같은 검수 스냅샷을 학습자 화면으로 확인하는 방식이다. 구성요소별 확인·
  수정 요청·보류·메모는 해당 검수 버전에 귀속하고, 감수 기록에 미해결 항목이 있으면 최종화를
  차단한다. 기존 AI 지적별 교수자 결정·사용 근거·개별 미션 승인 계약은 유지한다.
  체험 중 답안을 학습 기록으로 저장하지 않으며 정적 참고 표현을 실시간 AI 피드백으로 제시하지 않는다.
- 기존 생성 모델·학습자 런타임 호출은 변경하지 않는다. 실시간 개인 피드백 전건의 다중 모델
  검토를 구현한 것이 아니다. 새 학습 콘텐츠 생성과 다중판단 BEST/WORST 선택은 별도 미결정 사안이다.
- 검수용 계약·프롬프트 버전은 `content_review_v2`다. 구현·운영 적용 상태는
  docs/dev-log/2026-08-27-content-review-workflow.md를 참조한다.

## 6. Full Mission 생성 계약

### 6.1 현행 mission_v5 네이티브 MJT5 계약

승인된 목표 순서는 `첫인상 판단 → 맥락 대비 판단 → 판단하고 고쳐보기 → 이유 찾기 →
여러 초안 비교 → DCT`다. 맥락 대비 판단은 소박한 규칙의 반례를 별도 MJT로 다루며,
현행 소스는 이 순서를 독립 5문항으로 생성·검사·실행한다. 각 새 미션의 최초 진입에는
3단 장면 도입이 선행하고, 장면문에는 관찰 가능한 사실만 사용하며 정답 방향을 누출하지 않는다.

MJT5라는 문항 형식의 다양성만으로 화행의 다차원 학습 범위나 학습효과가 자동으로 충족됐다고
간주하지 않는다. 각 미션의 문항 품질과 진단 근거는 독립적으로 검수한다. 개별 Reason 문항의
주원인을 하나로 제한하는 것은 문항 변별을 위한 규칙이며, 두 미션 사이 coverage 계약을 뜻하지 않는다.

아래 블록은 **현행 `mission_v5` 네이티브 MJT5 구조**다. 과거 4문항 `mission_v5`는
삭제·백필하지 않고 별도 legacy 스키마와 `mpj_response_v1`으로만 읽는다.

```text
1. Scale4
   매우 적절 / 다소 적절 / 다소 부적절 / 매우 부적절
   → 적절/부적절 방향이 맞으면 인정
   → reference_scale_code와의 정도 차이는 참고·수업 토론 자료

2. Judge3
   첫 장면과 다른 사건의 과소·적정·과잉 판단 1회
   → DCT 앵커와 같은 P·D·R에서 맥락 의존성 확인

3. FixChoice 3
   별도 사건의 과소·적정·과잉 판단 1회
   → 수정안 3개 중 이 장면의 권장안 1개 단일 선택
   → 권장안 1개 + 일부 조정이 필요한 경계안 2개

4. Reason 3
   과소·적정·과잉 최초 판단 1회 → 판단 잠금
   → 이유 3개 공개 → 가장 큰 이유 1개 선택
   → 확신도 없음

5. MultiJudge 4
   BEST 1 + 수용 가능한 중간 1 + 조정이 필요한 경계 중간 1 + WORST 1
   → 한 화면에서 BEST 1개와 WORST 1개 선택
   → 제출 뒤 네 초안의 역할과 개별 근거 공개
   → 중간 둘을 엄밀한 2위·3위 선형 서열로 해석하지 않음

6. DCT
   번역 또는 통역 산출 → 피드백
   → 세 층 모두 통과하면 현재 표현으로 완료 또는 선택적 재표현
   → 수정이 필요하면 원문과 다른 수정안을 작성한 뒤 완료
```

- `scale4`는 독립 첫인상 문항이다. `accepted_scale_codes`는 같은 방향의 두 코드이고, `reference_scale_code`는 그 안의 대표 정도 하나다.
- Scale4는 각 target feature 카탈로그의 `counter_rule_ko`가 경계하는 소박한 규칙에 대한 반례를 우선 배치한다. 특정 PDR에서는 직접성·강도·명료성·책임 범위 등 해당 자원의 다른 대역이 적절할 수 있음을 보여 주어, 더 간접적·길거나 강한 표현을 자동 상향하는 편향을 막는다.
- `judge3`가 DCT 앵커와 같은 P·D·R의 Anchor A를 독립 판단한다. `fix_choice`와 `reason`은
  같은 Anchor A 상황을 공유한다. `fix_choice`는 대역 판단을 잠근 뒤 권장안 1개와 경계안 2개를 공개하고 가장 알맞은 수정안 하나를
  고르게 한다. 복수 선택 배열형 trace는 역사 응답 호환을 위해 유지한다.
- `reason`은 이유 공개 전 `problem_band_code`와 같은 대역 체계로 최초 판단을 잠그고, 이유 3개와 단일 `accepted_reason_id` 중 하나를 고른다. 최초 판단과 이유 선택은 별도 trace로 남긴다.
- `multi_judge` 후보 수는 모든 수준에서 4개로 고정한다. 역할은 `BEST 1·middle 2·WORST 1`이고,
  middle은 적정 대역의 수용 가능한 안 1개와 비적정 대역의 경계안 1개다. 후보마다 Judge3를
  반복하지 않고 네 후보를 동시에 보면서 BEST와 WORST를 하나씩 고른다.
- 선택지 수를 수준 난이도로 사용하지 않는다. 난이도는 장면과 표현의 미묘함으로 조절한다.
- DCT는 MJT와 같은 `mission_id`, attempt와 `speech_act`에 속한다. 현행 호환용
  `target_feature`를 함께 보존할 수 있지만 이것을 미션 전체의 단일 학습목표로 해석하지 않는다.
  MJT 완료만으로 미션 완료 처리하지 않는다.
- 현행 v5의 `production_task.mode`는 번역 또는 통역 하나다. 번역·통역 연계는 과목 설정, 주 수행/보조 수행 구분, companion 로그 계약을 먼저 설계한 뒤 별도 버전에서 추가한다.

### 6.2 Reason·맥락·전이 게이트

Reason 단일 선택은 다음 조건에서만 허용한다.

- 문항마다 하나의 주된 화용 판단 원인이 명확하고, 내부 진단 feature와 연결할 수 있다.
- 이유 3개는 `primary` 1, `pragmatic_misconception` 1, `meaning_grammar_context` 1이다.
- 정답은 `primary` 하나뿐이다.
- 오답도 target에 실제로 보이는 표현이나 인접한 화용 쟁점을 근거로 한 그럴듯한 설명이어야 하며, 황당한 문법 주장이나 상황과 무관한 절대 규칙으로 쉽게 제거할 수 있어서는 안 된다.
- primary의 위치와 ID를 고정하지 않고 선택지 순서를 섞는다.
- 두 이유가 동등하게 방어 가능하면 생성 실패 또는 AI 품질검사 fail이다.
- 복수 head와 supportive move 자체를 금지하지 않는다. 다만 이 문항의 가장 큰 판정 원인은 하나여야 한다.

P·D·R 원시 저장 코드는 학생에게 보여 주지 않는다. 현행 학습자 화면은 `speaker_lower` 같은
원시값 대신 `상대 높음·아는 사이·부담 높음`처럼 풀어 쓴 P/D/R 칩을 판단 전에도 명시적 교수
단서로 보여 준다. 상황문 자체에서도 권한·접촉 이력·실제 부담의 구체적 근거를 확인할 수 있어야 한다.

- 현행 native MJT5와 DCT의 `situation_ko`는 140자 이내의 정확히 두 문장이다. 역할 메타데이터를
  나열하지 않고 첫 문장에서 원문 화행의 주체가 누구에게 무엇을 하려는지, 다음 문장에서 접촉
  이력과 상대가 감수할 실제 부담을 자연스럽게 잇는다. 번역 셀은 학습자 1인칭 과업으로 서술할 수
  있지만, 통역 셀은 원발화자 A와 청자 B 사이에서 학습자가 별도 통역사로 개입한다고 서술한다.
  기록 목적·즉시 반응 여부 같은 매체 속성을 연구 설명처럼 풀어 쓰거나, 상대의 권리·선택권·의무와
  답안에 포함할 표현 자원 같은 평가 기준을 학생용 상황문에 노출하지 않는다. 역사 장면은 저장값을
  바꾸지 않고 학습자 런타임에서 메타 문장을 제외한 최대 두 문장·140자로 투영한다.
- AI 품질검사의 `scene_underspecified`도 같은 경계를 사용한다. 상대·용건이 없거나 관계·접촉 이력과 실제 부담이 모두 빠져 P·D·R 판단이 실제로 갈릴 때만 보고하며, 문장이 짧거나 기록 목적·즉시 반응 여부가 설명되지 않았다는 이유만으로 결함을 만들지 않는다.
- `relation_ko`의 학습자 표시값은 상대 역할과 학습자와의 관계를 자연스럽게 한 줄로 합친다.
  두 역할의 병렬 나열, 화자 역할, `A → B`, P·D·R 원시 코드·라벨을 이 값에 섞지 않는다.
  별도의 학습자용 P/D/R 칩은 `pdr` 저장값을 풀어 쓴 표시 projection이므로 허용한다.
- 현행 native MJT5의 다섯 MJT와 DCT는 `preceding_turn=null`이다. 거절·반대처럼 앞선 요청·제안·
  의견이 필요한 화행과 감사·칭찬·사과·직접 불만의 선행 사건은 `situation_ko` 안에 요약해 장면을
  self-contained하게 만든다. 역사 native 행의 값도 학습자 런타임에서는 숨기며, legacy MJT4의
  응답 화행만 저장값과 표시 호환을 유지한다.
- legacy 행에 화자와 상대가 함께 저장돼 있으면 러너 UI에서 오른쪽 상대 정보만 추출한다. 저장 원문과 관리자 검수 화면은 바꾸지 않는다.

각 미션 내부의 맥락 배치는 `앵커+대비`다.

- Scale4(MJT1): Anchor A에서 P/D/R 한 축만 바꾼 Contrast X
- Judge3·FixChoice·Reason(MJT2·3·4): DCT와 같은 앵커 PDR과 동일한 Anchor A 상황
- MultiJudge(MJT5): Anchor A에서 P/D/R 한 축만 바꾼 Contrast Y
- DCT: 같은 앵커 PDR의 New Event C로 근접 전이

서버는 MJT2가 생성한 Anchor A의 `situation_ko`·`relation_ko`·channel을 MJT3·4에 고정한다.
따라서 현행 상황 topology는 `X → A → A → A → Y → C`다. X/A/Y/C 사이의 완전 중복은
결정론적으로 차단하고, 의미적 차이·자연성·대비의 충분성은 AI critic과 교수자 검수가 판정한다.

화행 학습 주차에는 같은 `speech_act`·수준·언어방향의 완전한 MJT5+DCT1 미션 두 건을
편성한다. 미션 2는 미션 1의 사실상 복제본이 아닌 새로운 상황이어야 한다. 생성과 검수는 각 미션을
독립적으로 처리하고, 편성은 동일한 상황문을 공백·문장부호만 바꾼 명백한 복제본을 제외한다.
그 밖의 의미상 복제 여부는 교수자가 두 상황을 읽고 확인하며 변화축·pair coverage를 계산하지 않는다.

강좌 수행 유형은 `translation`(번역), `interpreting`(통역), `mixed`(통번역)로 구분한다.
2026-09-06 승인 A안은 표준 세 교과목 모두 통번역형으로, 9개 화행 학습 주차와 화행 선택 후의
13주에 `translation` 1개·`stt_interpreting` 1개를 편성한다. 각 미션은 기존 MJT5+DCT1 생성·
검수 계약을 독립적으로 충족한다. 번역의 입력·출력만 음성으로 바꾸어 통역 미션을 만들지 않으며,
발신자 관점의 문어 상황과 통역사 역할의 구어 상황에 맞는 원문·역할·수행 조건을 구성한다.
번역·통역 전용 강좌는 각 모드의 두 미션을 유지한다. 7·14주 클리닉과 1·8·15주에는 새 미션을
편성하지 않는다. `target_interpreting_week_count`·legacy 비율은 저장 호환용으로 보존하며
현행 배분에 사용하지 않는다. 과거 Scope Lock v1 배치 manifest의 수량·인덱스는 변경하지 않으며,
그 역사적 생성 quota를 현행 강좌 편성 정책이나 새로운 1:1 콘텐츠 확보 근거로 해석하지 않는다.

13주 `선택 화행 집중 보완`은 교강사가 앞선 학급 수행을 참고해 기학습 화행 하나를 선정하는
주차다. 같은 화행·수준·방향의 새 MJT5+DCT1 미션 두 건을 편성한다. 통번역형은 번역·통역
각각 한 건이며, 한 화행 주차의
기존 완전 미션 단위를 유지하며, P·D·R과 상황을 다양하게 구성하고 고부담으로 한정하지 않는다.
화행 선정 전 빈 초안은 허용하되 새 미션 편성은 화행 선택 후 진행한다. 이전의 서로 다른 화행
배정은 자동 변환·삭제하지 않고 교강사가 선택·교체한다.

주차별 `중심 질문`은 수업 안내 전용이며 생성 프롬프트·검수 통과 조건·평가 준거로 전환하지 않는다.
교강사는 상황·P·D·R과 원문의 의도·태도에 따라 질문을 구체화하거나 교체할 수 있다. 특정
완화·선택권·이유·대안이 항상 필요하다고 전제하지 않으며, 원문의 의미와 화행 목적을 보존한다.
주차 표시 명칭은 아홉 화행 모두 두 글자로 통일하되 내부 enum·생성 스키마·진단 태그는 유지한다.

한 주차의 두 DCT만으로 광범위한 전이나 화행 숙달을 주장하지 않는다. 학기 전체 PDR 배치표에서
주차별 조건을 순환하고, 중간·기말 통합 과제에는 P·D·R 중 하나 이상이 달라지는 전이 문항을 둔다.
배치 자체는 전이 학습의 기회이며, 실제 전이와 학습효과는 수행 자료로 별도 검증한다.

### 6.3 미션 모델과 형식

- 미션 승격 모델: `gpt-4o`
- 현재 미션 출력: JSON mode
- 미션 strict JSON Schema: 미구현
- 생성 후 결정론 검사
- 최초 완전 미션은 한 응답에서 생성한다. 결정론 검사 실패 중 허용된 문항·산출 필드만 국소
  repair하며, 허용되지 않은 필드와 기존 정상 문항은 동결한다.
- MJT3 `fix_choice`는 검증된 within 후보 1개를 lower·upper의 공통 기준으로 사용한다. MJT5
  `multi_judge`는 within A·B를 먼저 생성·검증하고 lower는 A, upper는 B와 상대적 최소대조로
  생성한다. 서버가 후보별 `intended_band`·교육적 역할·보존할 의미/발화 의도/화행 기능·조절 축·
  극단화 금지를 먼저 고정하며, 특정 최종 표현은 하드코딩하지 않는다.
- within 후보가 실패하면 경계 후보를 만들지 않고 해당 within 후보만 한 번 재생성한다. 최초
  재생성에서도 같은 의미 결함이 반복되면 중단하며 무한 재시도하지 않는다.
- AI 품질점검이 정확한 MJT3·MJT5 후보 경로를 `band_mismatch` 또는
  `implausible_distractor`로 지목하면 기존 표현을 repair하지 않고 동일 blueprint와 검증된 within
  기준으로 해당 후보만 새로 생성한다. 정상 후보·후보 순서·대역 metadata는 immutable하다.
- 후보 교체 뒤에는 변경 후보 검사와 기존 결정론적 최종 문항 검사만 수행한다. 그 결과는 대상
  후보의 판정만 해소하며, 기존 warning과 비대상 critical fail을 제거하거나 전체 미션을 자동
  pass로 완화하지 않는다. 그 밖의 단순 형식·표현 결함만 candidate-level repair 대상이다.
- critic의 명시적 자기모순만 counter-rule로 보정한다. 경계 판단이 불확실한 경우 warning으로
  남기며 자동 pass로 전환하지 않는다.
- 구조적으로 저장된 `generated` 초안도 current LOCK release·동일 fingerprint·결정론 검사·AI critical
  fail 제외·고유 content hash를 모두 만족해야 500 후보 집계에 포함된다.
- 별도 outline 파이프라인과 mission_v5 구조 변경은 사용하지 않는다.

### 6.4 R5 길이 단서 판정 해석 (2026-08-25 교차검증 개정)

R5는 `multi_judge` 후보의 길이가 목표 화용 판단을 우회하는 응답 단서로 작동하는 것을 통제한다. 판정 수준은 다음과 같이 해석한다.

- **warning(독립 의미 검수 신호)**: 모든 non-within 후보의 길이가 within 후보 구간의 한쪽
  밖에만 분포하는 완전 분리, 과잉안 유일 최장, 과소안 최단 집중, 최장/최단 비율 3 초과.
  길이 패턴만으로 저장을 차단하지 않는다.
- **AI·교수자 판정**: 필수 AI 품질점검은 실제 BEST/WORST 선택을 화용 판단 없이 식별하거나
  현저히 좁힐 수 있는 `answer_cue`인지 문장 내용과 함께 독립 판정한다. AI fail은 저장을 막고,
  warning은 교수자 검수에 남긴다.

2026-07-31의 9화행 파일럿에서 B2 프롬프트 보강(대역과 길이를 별개 축으로 명시하고 탈상관 조합을 요구)은 미션 생성 성공률과 일부 길이 구간 중첩을 개선했다. 다만 화행별 1표본이므로 길이 단서 문제가 일반적으로 해소되었다고 보지 않는다.

길이가 일부 target feature와 자연스럽게 관련될 수 있다는 사실과, 길이가 응답 단서로 작동한다는 사실은 동시에 참일 수 있다. 채점상 within이 아닌 모든 후보가 유효한 WORST이므로(`mpjSummary`의 방향 일치 판정), 학습자가 목표 화용 판단 없이 길이만으로 유효한 BEST/WORST를 식별하거나 선택지를 현저히 좁힐 수 있다면 수정 대상으로 판정한다. 반복 표본에서도 동일 경향이 지속되면 축별 생성 전략 또는 응답 판정 방식의 분화를 재검토한다(현재는 미도입·유보).

| R33 | 현행 native MJT5의 복수 진단차원·근거 위치 구조 | fail; 선언의 의미 타당성은 AI/사람 검수 |

## 7. 평가와 피드백 경계

### 7.1 분리 원칙

피드백은 최소 다음 층을 구분한다.

1. 의미·의도 충실성
2. 명백한 문법·형식 문제
3. 해당 target feature의 상황 적절성

직접성, 공손성, 의미 충실성을 하나의 총점으로 합치지 않는다. 더 길거나 더 완곡한 표현을 자동으로 더 좋은 답으로 판정하지 않는다.

MJT 5개가 끝나면 직접 산출 전 recap에서 문항마다 실제로 본 목표어 표현 한 조각과 그 표현을
가르는 구체 근거 하나만 `표현 → 메모` 형식의 한 줄로 보여 준다. 새 목표어 모범답안·추상적 교훈·
정답/오답 성적표를 만들지 않으며, MultiJudge도 BEST를 가른 한 점만 남긴다. 런타임 projection은
표현 조각을 최대 18자, 근거 메모를 최대 26자로 제한하고 중국어 조각에만 `Noto Serif SC`를 적용한다.

학습자 피드백 화면은 `내 답 → 의미 전달·문법 정확성·상황 적절성 판정 → 다음 행동`만 우선 노출한다. 세 판정은 상태 아이콘과 `통과/수정 필요`로 결과를 분명히 하고, 통과한 층에는 구체적인 긍정 문구를 제공한다. 세 층이 모두 통과하면 수정을 강제하지 않고 `이 표현으로 완료`를 주 행동으로 제공하며, `다른 표현도 시도해보기`는 선택 행동으로 둔다. 수정이 필요한 경우에만 `한 번 다듬어보기`로 연결하고, 원문과 실질적으로 다른 수정안을 작성해야 완료할 수 있다. 앞뒤 공백만 다른 답은 수정으로 인정하지 않되 내부 공백은 언어별 의미 가능성을 고려해 자동 정규화하지 않는다. 여러 층이 동시에 실패한 한 번의 수정 과업은 `의미 전달 → 이번 미션의 목표 화용 축 → 문법 정확성` 순서로 최종 수정 목표를 정한다. 세 층의 독립 판정과 상세 피드백은 그대로 보존한다. 이는 점수나 절대 정답 선언이 아니며 AI 참고 판정 고지는 유지한다. 판정 근거 전문은 관리자 검수·로그에 남기며 학습자에게 반복해 읽히지 않는다. 공통 피드백 프롬프트는 요청 화행을 기본값으로 삼지 않고, 의미층에서는 사실·조건·핵심 화행 내용만 확인하며 강도·완화·선택권·명료성·범위 등 목표 화용 자원의 변화는 화용층에서 판정한다. 다듬기 화면은 판정 결과에서 도출한 한 줄 수정 행동을 제시하고, 완료 화면은 수정 전·후, 바뀐 부분, 해당 답안에 맞춘 한 줄 조언, 저장 상태와 다음 행동만 남긴다. 판정 결과가 없을 때만 일반 원칙 한 줄을 대체 문구로 사용한다.

DCT 산출 화면에서는 장면 설명과 실제 수행 도구를 한 카드에 붙이지 않는다. 번역은 `지금, 직접 번역할 장면`과 메신저 입력 화면을 분리하고, 통역은 장면 카드와 듣기·녹음 프레임을 분리한다. 두 장면 카드는 고정 최소 높이를 두지 않고 같은 패딩·행간·문장 간격을 사용해 내용 길이에 맞게 줄어든다. 번역에는 산출을 막는 비화용적 내용 어휘·고유명사·전문용어만 정확히 2개 제공하며, 기본 접힘 상태에서 학습자가 요청할 때 한 줄 패널로 펼친다. target feature의 완화 표지, 문장 구조와 완성 답안은 힌트로 제공하지 않는다. 통역에는 첫 수행과 재도전을 포함해 힌트를 제공하지 않는다.

### 7.2 사람 검수

상태 흐름:

```text
core-only
→ generated
→ AI/결정론 검사
→ 사람 검수
→ reviewed
```

- 일반 학습자 공개 최소 조건: `mission_status='reviewed'`
- 연구 분반에서 band를 측정 주장에 사용할 경우: `reviewed`와 별도의 인간 캘리브레이션 상태가 필요하다.
- `generated`는 생성 성공이지 교육적 승인 상태가 아니다.

## 8. provenance와 재현성

코어와 미션은 최소 다음을 식별할 수 있어야 한다.

- model
- provider
- prompt version
- prompt snapshot hash 또는 mission content hash
- generated_at
- generation attempt
- schema version
- language direction

Edge가 계산한 `prompt_snapshot_hash`를 클라이언트가 변형하거나 로컬 코드로 재계산하지 않는다. 프롬프트 정본 화면은 배포 Edge 소스에서 생성된 저장소 스냅샷과 저장 행의 지문을 대조한다.

### 8.1 HSK 3.0 참고 데이터와 lexical audit

HSK 3.0은 PRAGMA 학습 지원 수준의 숙달도 등가표나 인증 기준이 아니다. 생성된 중국어를
검토할 때 사용하는 **누적 어휘 참고 상한**이다.

| PRAGMA 수준 | 중국어 어휘 참고 상한 | 누적 항목 수 |
|---|---:|---:|
| 입문 | HSK 1–4급 | 2,000 |
| 중급 | HSK 1–5급 | 3,600 |
| 고급 | HSK 1–6급 | 5,400 |

공식 PDF→추출 CSV→결정론 파생→연구자 mapping→DB seed의 각 층은 source ID·공식 URL·
SHA-256·변환 version으로 식별한다. 공식 L1/L2/L3 주제와 연구자 코딩은 같은 진실값으로
취급하지 않는다. 원 코더·시점·지침이 확인되지 않은 과거 코딩은
`legacy_imported_unverified`이며 PRAGMA 장면 채택 여부로 자동 변환하지 않는다.

생성 계약은 다음을 강제한다.

- 무작위 HSK 어휘 목록을 prompt에 주입하지 않는다.
- 중→한은 중국어 source를, 한→중은 mission의 중국어 target·참고안을 감사한다.
- 감사 결과는 `hsk_lexical_audit`에 policy/source ID, 참고 상한, token 수, 참고 일치율,
  범위 밖 검토 후보와 상태를 기록한다.
- lookup 실패는 `unavailable`로 기록하고 생성·저장을 막지 않는다.
- 범위 밖 후보는 고유명사·전문용어·분절 단위·상위/사전 밖 어휘일 수 있다. 자동 삭제·
  재작성·승인 차단에 쓰지 않고 사람 검수의 참고 자료로만 사용한다.
- lexical audit는 중국어 자연성·화용 적절성·숙달도를 판정하지 않는다.

§5.4 AI 모델 간 독립 검토를 실행한 경우 검토 결과에 대해서도 최소 provider·model·prompt
version·실행 시각·대상 행의 식별자를 남긴다. 이 기록은 생성 행의 provenance를 덮어쓰지
않고 별도로 보존한다.

## 10. 운영 금지와 승인 게이트

- 495/500 대량 배치를 임의 실행하지 않는다.
- core hash 변경 전 영향 범위와 새 생성 계열 분리 방식을 보고한다.
- 생성·평가·저장 계약, DB schema, RLS, prompt hash에 영향이 있으면 먼저 범위를 보고한다.
- migration 적용, Edge 배포, Railway 배포는 사용자 승인 없이 실행하지 않는다.
- `generated`를 `reviewed`로 자동 승격하지 않는다.
- AI 모델 간 독립 검토 배치를 임의 실행하지 않는다. 대상 표본·규모·모델을 먼저 보고한다.
- target feature의 학술적 지위를 코드 구현만으로 validated라고 부르지 않는다.
- 라운지 활동은 이 계약의 학습 수행·연구 로그에 포함하지 않는다.
