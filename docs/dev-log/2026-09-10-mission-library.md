# 학습 미션 라이브러리와 수업 편성 연결

- 요청: 시나리오 재료보다 실제 수업에 쓸 미션을 중심으로 기존 라이브러리를 전환한다. 사용자가 제안 후 `오케이`로 승인했다.
- 분류: `[단독 진행 적합]`. 기존 승인·편성 규칙을 재사용하는 관리자 탐색·인계 변경이다.
- 기준: `codex/admin-takeover-2026-09-10`, 시작 커밋 `ac5c9720`. 기본 복구 폴더와 Claude 작업공간은 수정하지 않았다.

## 변경과 근거

- `/admin/library`를 **학습 미션 라이브러리**로 바꾸고 교수자 최종 승인 다음에 배치했다.
  기본은 편성 가능 미션이며 승인 전·전체 미션·시나리오 재료를 별도 보기로 제공한다.
- 단순 `reviewed` 건수 대신 편성 화면의 현행 release·승인 상태·네이티브 5문항 조건을 재사용한다.
  기존 `released`도 포함한다. 과거 승인본은 전체 미션에서 확인할 수 있다.
- 보기·속성 필터에 따라 화행×수준 격자와 목록을 함께 바꾸고 미리보기·편성 건수·미션별 검토 링크를 연결했다.
  빈 격자를 눌러도 생성 화면으로 보내지 않는다. 조회 실패·로딩 중에는 확정 수치를 표시하지 않는다.
- 라이브러리와 편성 후보 조회를 페이지 단위로 읽어 API 기본 상한 1,000행 이후도 포함한다.
- `scenarioId`를 편성 화면과 수업 선택·새로고침 후에도 보존한다. 기존 수업 조건에 맞는 주차만 제시하고,
  명시적 주차 추가와 기존 편성 저장을 거쳐 반영한다. 편성 건수는 학생 공개 여부를 뜻하지 않는다.
- 특정 미션의 조립 링크는 수정 요청 상태도 조회하도록 했다. 일반 조립 대기열 조건은 유지한다.

## 검증

- `npm.cmd run typecheck`: 통과.
- 전체 Vitest: **142파일·901개 통과, 3파일·9개 건너뜀**. 새 라이브러리 회귀 검사 4개 포함.
  기존 내비게이션 기대값 한 곳을 새 메뉴 순서로 수정했다.
- `npm.cmd run build`: 통과, 1,994 modules. 기존 CSS 파싱·큰 청크·Browserslist 경고는 남았다.
  빌드가 갱신한 생성 스냅샷 두 파일의 커밋·시각 메타데이터는 원복했다.
- `scripts/manual-checks/mission-library-smoke.mjs`: 합성 API와 실제 로컬 Edge 브라우저로 12항목 통과.
  1,000행 이후 조회, 승인 범위, 미션 ID 유지, 수업 조건 불일치 제외, 추가→저장→재조회,
  편성 건수, released 미리보기, 390·768·1280px 문서 넘침, 후속 페이지 오류 표시를 확인했다.
  최초 화면 검사에서 기존 현지화 문구에 맞게 검사 선택자를 고쳤다.
- 증거: 이 작업공간 `.tmp/mission-library-smoke/`의 `result.json`, `desktop.png`, `composer.png`, `mobile.png`.
  전체 검사·빌드 로그는 `.tmp/mission-library-tests.log`, `.tmp/mission-library-build.log`다.
- Node v24.18.0에서 실행했다. CI의 Node 22·실제 운영 DB·운영 배포·실제 학습효과를 검증한 결과는 아니다.
  사용자의 검증 최소화 지시에 따라 진행 중이던 검사 결과를 수집한 뒤 반복 검사를 추가하지 않았다.
