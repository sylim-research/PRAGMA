## 사용자 피드백과 확인 사실

1. **주차의 미션 카드가 DCT 과제 설명처럼 보이고 너무 길다.**
   - `LearnerCourseWeek.tsx`는 `scenario.situation_ko`를 카드 본문에 그대로 표시한다.
   - `composer.ts` → `learnerCourse.ts`를 추적하면 원천은 `core_content.situation_ko`다.
   - 시작 버튼은 `/learner/practice/:scenarioId`의 `CanonicalMissionRun`으로 연결된다.
     카드는 DCT 전용 미션을 뜻하지 않으며, 전체 MPJ5+DCT1 흐름을 안내하는 표현이 부족하다.
   - 캡처의 미션 1에는 상대가 교수님인지 학사 담당자·조교인지 혼재한다. 실제 콘텐츠 검토
     대상으로 남기며, 요약 문구로 모순을 숨기거나 이 세션에서 원본을 고치지 않았다.
2. **주차 학습 노트는 기존 예습·복습 템플릿이며 Package와 별도 경로다.**
   - `learnerNote.ts`가 주차 Can-do와 `targetFeatures.ts` 카탈로그로 노트를 조립한다.
   - `operational_definition`을 `definition`으로 전달하고 `WeeklyLearningNote.tsx`가 그대로
     출력하므로 내부 band 코드와 생성·재생성 판정 문구가 학생용 본문에 노출된다.
   - 현재 카탈로그를 읽기 때문에 고정된 옛 문서라고 단정할 수는 없다. 핵심 원리와 반례는
     활용 가능하나 학생용 설명·구체적인 상황 및 통번역 사례로 가공하는 단계가 부족하다고 평가했다.
   - 예습은 먼저 열리고 복습은 교수자 공개 또는 해당 주차 필수 미션 전체 완료로 열린다.
3. **사용자는 수업자료의 기준을 교과목·주차 계획으로 정정했다.**
   - 요청: Composer에서 만든 교과목의 주차별 수업자료를 구성해야 하며, 승인 미션을 원천으로
     수업 전체를 역으로 구성하는 방식은 의도와 다르다.
   - 현행 `AdminTeachingMaterials.tsx`는 승인된 `mission_content`를 조회하고
     `buildInstructorMissionGuide`로 자료를 구성한다. 교과목·주차 수업자료 생성기는 아니다.
   - `AdminComposer.tsx`의 개별 수업자료 링크는 `/admin/package?mission=...` 형태다.
   - 원하는 관계: 교과목·주차 계획 → 주차별 수업자료 → 교수자 자료·교실 화면 / 학생용
     예습·복습 노트. 편성된 미션 1·2는 해당 수업의 실습 활동으로 연결한다.
   - 학습 노트의 구체적인 연결 방식은 진단에서 제안한 방향이다. 상세 UI·저장 구조·생성 방식의
     구현 승인을 받은 것으로 확대 해석하지 않는다. 안내 문구만 바꾸는 것으로 해결하지 않는다.

## 확인한 증거와 한계

- 운영 `/admin/package`와 `/admin/composer`를 브라우저에서 읽기 전용으로 확인했다.
  Package의 승인 미션 선택 구조와 Composer의 교과목·주차 편성 구조를 확인했다.
- 학습자 화면은 사용자가 제공한 다음 캡처와 소스를 대조했다. 미션 실행·학습 기록 저장은 하지 않았다.
  - `~\OneDrive\사진\스크린샷\스크린샷 2026-08-27 152152.png`
  - 같은 폴더의 `스크린샷 2026-08-27 152227.png`, `152235.png`, `152255.png`
- 이전 기록 `2026-08-25-instructor-teaching-materials.md`와
  `2026-08-26-classroom-output-integration.md`에도 승인 미션 기반 자료 구성이 명시돼 있다.
- 테스트·typecheck·build는 재실행하지 않았다. 기존 CI의 537 pass·9 skip 및 typecheck·build 성공은
  직전 인계에서 전달된 결과이며, 이번 진단의 신규 검증 결과가 아니다.
- 앱 코드·DB·학습 콘텐츠·프롬프트·운영 배포는 변경하지 않았다. 이 메모만 작성했다.

## 후속 협의 · 학생 유인물 1개와 교수자 전용 메모

- 아래는 최초 진단 이후 사용자가 구체화한 출력 방향이며, 위 예습·복습 분리 제안보다 우선한다.
  사용자는 이 구조의 구현 가능성을 확인해 달라고 했다. 앱 구현은 아직 시작하지 않았다.
- 교과목·주차 계획에 기반한 공통 학습 내용을 한 곳에서 관리한다. 학생용은 주차별 강의 유인물
  1개이며 별도 예습·복습 자료를 생성하지 않는다. 개인 미션 수행 기록은 기존 웹앱에 남긴다.
- 프로젝터 화면과 HTML은 수업 중 함께 보는 공통 내용을 사용한다. HTML은 해당 화면의
  오프라인 사본이며, 세 번째 내용을 따로 생성하는 것이 아니다.
- 교수자 전용 메모(치트시트)는 수업 지도 메모와 미션별 핵심 해설을 보여주는 관리자용 별도 보기다.
  미션 해설은 배정된 미션의 기존 MPJ·DCT 자료를 재사용하며 정답·판정 기준을 새로 만들지 않는다.
- 학생 유인물과 프로젝터용 HTML에는 교수자 전용 메모를 포함하지 않는다. 공통 수업 설명과
  공개할 사례 해설까지 모두 지우는 것이 아니라, 교수자 전용 정보와 분리하는 뜻이다.
- 별도 생성기·교안 편집기는 추가하지 않고 기존 화면·HTML 내보내기·인쇄 기능을 우선 재사용한다.
- 추가 소스 확인: `InstructorMissionGuide.tsx`에는 이미 audience 및 document/projector 구분이
  있고, `WeeklyLearningNote.tsx`에는 브라우저 인쇄 기능이 있다. 다만 모델 자체는 여전히 미션 중심이다.
- 주의: 현재 `instructorGuideHtml.ts`는 해설을 HTML 안에 넣고 CSS로 숨기며 인쇄 시 표시한다.
  기존 문서에도 교수자용 파일이라고 명시돼 있다. 새 프로젝터용 HTML에서 교수자 전용 정보를
  제외하려면 화면에서 숨기는 것만으로는 부족하고, 출력할 데이터·HTML 구성에서 실제로 빼야 한다.
- 확인한 `curriculum_weeks` 타입에는 주차 목표·편성 정보가 있으나 수업자료 본문·교수자 메모의
  저장 필드는 없다. 기존 기능을 재사용할 수 있다는 것과 공통 주차 자료 원본이 이미 존재한다는
  것은 다르다. 원본 보관 방식은 최소 구현 설계에서 정하며, DB 변경 불필요를 미리 확약하지 않는다.
- 검증: 관련 소스·타입·기존 HTML 개발 기록을 읽어 재사용 지점과 분리 필요를 확인했다.
  테스트·build·자료 생성·운영 변경은 하지 않았다. 이 후속 협의만 기존 인계 메모에 추가했다.

### 변경

- `weeklyMaterials.ts`와 `WeeklyMaterialDocument.tsx`에서 공통 본문을 한 번 구성·렌더링한다.
  주차 목표·맥락·기존 원리/표현 자원에 현재 편성의 기본 상황·원문을 반영한다. 원문은 코어의
  기본 원문이며 DCT의 참고 답안으로 표시하지 않는다. 미션 교체 시 해당 본문도 바뀐다.
- 미편성·부분 편성은 계획 미리보기로 표시한다. 편성 정보가 있다는 이유만으로 상세 교안 작성이나
  교수자 검토가 완료됐다고 간주하지 않는다. OT·평가·메타화용 주차도 계획 안내임을 명시한다.
- `/admin/package`는 교과목·주차를 선택하며 Composer의 각 주차 링크로 진입한다. 승인 미션 단독
  선택/시간 프리셋 중심 화면을 대체했다. 기존 `?mission=` 주소는 주차 선택 안내로 처리한다.
- 교수자 메모는 현재 주차의 공개 가능한 미션만 조회해 기존 MPJ·DCT 해설을 재사용한다.
  프로젝터 전환 시 전용 메모를 닫으며, 종료해도 메모를 자동으로 다시 노출하지 않는다.
- 프로젝터·학생 유인물·새 공용 HTML은 허용한 공개 필드만 렌더링한다. 교수자 전용 메모를
  CSS로 숨긴 사본을 배포하지 않는다. 예전 teacher-only HTML 함수는 호환용으로 남되 새 화면에서 호출하지 않는다.
- 기존 `/note`는 한 개의 강의 유인물로 연결한다. 완료 상태 조회·예습/복습 해금과 편집기의

- 주차 카드의 상황문은 첫 문장 요약·두 줄 표시로 줄이고 MPJ5+DCT1 구성임을 명시한다.
