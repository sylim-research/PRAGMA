## 2. 진단
- 개요 프롬프트(`buildOutlineSystemPrompt`)에도 `SCENE_GROUNDING_RULE`이 들어가 있었다 → 「규칙을 몰라서」가 아니라 앞단이 상대·이력·부담을 장면에 사실로 쓰지 않는 것이 문제.

## 4. 수정 (가) — 계획표
- `scenarioTopics.ts`: 관계가 주제에 내장된 시드 10개에 허용 P·D 기입(이웃 소음·소음 사과·동호회·물건 빌리기·친구 모임·환불·병원·콘텐츠 2차 사용 = 대등, 약속 지각·호스트 가족 = 아는 사이·친한 사이 등).
- 첫 시도 후 감사: 일상 domain의 「초대·불만 × 내가 낮음/높음」 24칸에 시드 없음 → 계획 생성 자체가 예외로 멈춤.
- `batchPlan.ts`: 배정 domain에 맞는 시드가 없으면 다른 domain으로 넘기는 `domainFallbackOrder` 추가. 감사(`auditTopicCompatibility`)도 「어느 domain에서도 못 채우는 칸」만 공백으로 센다 → 공백 0.
- 부작용 실측: domain 1:1:1이 깨짐. 처음엔 넘어가는 칸이 전부 학업으로 몰림(일상:학업:직장 ≈ 43:59:51) → seq로 학업·직장을 번갈아 받게 해 ≈ 28%:36%:36%로 완화. 테스트 기준을 「1:1:1」에서 「각 domain 25% 이상」으로 바꾸고, 대등 전용 시드가 대등 칸에만 배정되는지 확인하는 테스트 추가.
- 조별 과제 시드: 「학생들 사이에서」 → 「조원 또는 과제를 지도·평가하는 교수·조교와」(아래 (나)의 「상대 특정 시드는 바꾸지 않는다」 규칙과 충돌하지 않게).

## 5. 수정 (나) — 장면 사전 검토
