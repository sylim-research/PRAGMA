# 2026-09-07 · 미션 3개 모델 비교

## 결론

GPT-6 Astra와 Claude Fable의 운영 일괄 전환을 이번 결과만으로 진행하지 않는다.
Astra의 장면·원문 생성은 유망하지만 완전한 MJT5+DCT1 생성 응답을 확보하지 못했다.

## 독립 검수와 직접 확인

완성된 기존 요청·거절 초안 2건을 Opus와 Fable에 동일한 프롬프트·입력으로 독립 검수시켰다.
둘 다 `medium`, 출력 상한 16,000을 사용했다. 기존 운영의 Claude 7,000토큰/130초 설정을
그대로 평가한 실험은 아니다. 요청 최초 Fable 호출에는 생성 모델·기존 검사 메타데이터가
남아 있어 비교에서 제외하고, 해당 정보를 제거한 입력으로 한 번 다시 검수했다.
원래 응답은 보존했고 비용 합계에는 포함했다. 최종 두 검수 쌍의 입력 hash 일치를 확인했다.

| 동일 초안 | Fable | Opus |
| --- | --- | --- |
| 요청 | fail · 약 110초 · $0.527 | fail · 약 71초 · $0.220 |
| 거절 | fail · 약 135초 · $0.641 | fail · 약 90초 · $0.245 |

아래는 단순 fail 개수와 별개로 원문에서 직접 대조한 문제다.

- 요청 MJT5: 부하 직원이 상사에게 휴가 승인을 요청하는데 `pdr.p=speaker_higher`.
  Fable과 Opus가 모두 지적했다.
- 요청 DCT: 참고 산출에는 조건절이 없는데 해설이 조건절 사용을 설명한다. 두 모델이 모두 지적했다.
- 요청 MJT4: 세 이유가 선택권 부족·높은 직접성·추가 완화 필요라는 같은 결론으로 겹친다.
  Fable의 추가 지적으로 확인했으며 Opus의 해당 응답에는 없었다.
- 거절 MJT2~4: 관계가 `나는 나의 상사이다`로 표시되고, 상사에게 말하는 상황에 `p=equal`.
  두 모델이 모두 지적했다. 정상적인 생성 완료·warning을 내용 타당성으로 간주할 수 없다.
- 거절 MJT5: 원문에 없는 `다음에 꼭 갈게요`라는 약속을 추가했는데 적절 후보로 제시한다.
  두 모델이 모두 지적했다.
- Fable과 Opus의 모든 수정 제안을 채택하지 않았다. 예를 들어 메신저 연락처가 있는 이웃은
  반드시 더 친밀한 관계로 써야 한다는 지적은 현재 장면만으로 필연적이지 않다. 중국어 `批准一下`
  같은 결합의 일률적 부자연성 판정, 한국어·중국어의 공손성 정도는 교수자 판단이 필요하다.
  두 검토에 남은 과거 `within 2·조정 2` 언급도 현행 BEST/WORST 화면 운영과 대조해야 한다.

Fable은 일부 추가 결함을 찾았지만 두 건 검수 비용은 Opus의 약 2.5배, 응답시간도 더 길었다.
정상·허용 가능한 예시에서 오탐을 얼마나 내는지는 별도 측정하지 않아 정확도·재현율을 제시하지 않는다.
