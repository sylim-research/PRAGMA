# AI 콘텐츠 제작 자동화 유지와 배치 작업 화면 완성

- 사용자 보정: 지도교수 방침이 AI 콘텐츠 제작 자동화이므로 배치 생성 기능을 경량화하지 말고
  화면을 완성도 있게 만들라고 요청했다. 수업 편성의 규칙 기반 자동 채우기와 AI 콘텐츠 생성을 구별한다.
- 분류: `[단독 진행 적합]`. main `e7d3794e`에서
  `codex/batch-generation-workspace-2026-09-10` 브랜치로 시작했다.

## 변경

- 생성 조건, 생성 계획·분포, 실행·재개 패널을 한 흐름으로 연결했다. 실행 패널은 넓은 화면에서
  계획 옆에 두고 자체 스크롤을 지원한다. 모바일에는 실행 영역으로 가는 링크가 있다.
- 화행당 번역 입력, 수준별 번역·통역 합계와 총량을 표시했다. 통역 배율은 전체 비중이 아님을 설명한다.
- 기본 72건, 495건 본배치, 중→한 30건 검증, 모든 분포, 전체·선택 생성, 기존 ID 재개·새 ID 생성,
  생성 중단과 AI 비평 기능을 유지했다. 과거 495 계획과 별도 최종 corpus 수량을 이번 작업에서 재설계하지 않았다.
- 항목 목록에서 장면 시드를 확인하고 페이지를 넘기며 선택할 수 있다. 선택은 원래 계획 번호로 실행기에 전달한다.
- 실행 준비 시점부터 중복 요청을 막고, 조회·생성·비평 오류 뒤 제어 상태를 복구한다.
  조건 변경 때 이전 결과와 선택을 초기화해 다른 계획의 결과가 섞여 보이지 않게 했다.
- 저장·재사용·경고·실패 집계, 실패 항목 선택, 재료 라이브러리·미션 조립 연결을 제공한다.
- 생성 계획 함수, 모델·프롬프트·계약·DB·실제 생성기 및 교수자 승인 조건은 수정하지 않았다.

  선택 항목의 원래 번호·재개 ID·저장 목록 전달, 중복 요청 방지, 권한·연결 오류 복구,
  중단 신호와 AI 비평 유지가 포함된다.
- 처음 Vitest가 샌드박스 경로 읽기로 시작하지 못해 같은 명령만 승격했다.
  환경값이 없는 관리자 세션 검사 1파일은 CI용 가짜 Supabase 환경값으로 재실행해 통과했다.
- 로컬 실제 브라우저: 72·495·30 계획 표시, 여러 페이지 선택, 프리셋 전환의 선택 초기화,
  1440·1280·1024·390px 가로 넘침 없음, 모바일 실행 링크와 캡처 확인.
- 재실행: `scripts/manual-checks/batch-generation-workspace-smoke.mjs`.
  화면·결과는 `.tmp/batch-generation-workspace/`에 보존한다.
- 실제 AI 생성·DB 쓰기는 실행하지 않았다. 모델 콘텐츠 품질이나 운영 재개 종단을 새로 검증한 결과는 아니다.
- 타입 검사·운영용 빌드 통과. 기존 큰 청크 등의 빌드 경고는 유지됐다.
  생성 시각·커밋 메타데이터만 변한 자동 생성 스냅샷 두 파일은 원복했다.
  전체 테스트 반복·운영 배포는 이 단계의 범위가 아니다.

## 후속 화면 정리와 과거 프리셋 확인

- 사용자 요청으로 실행 패널 하단의 저장·승인 안내문과 재료 라이브러리·미션 조립 링크 두 개를 삭제했다.
  상단 제작 흐름의 미션 조립 링크는 유지한다.
- 공용 관리자 사이드바를 화면 상단에 고정하고, 긴 메뉴는 내부 스크롤로 마지막 항목까지 접근하게 했다.
- 기존 로컬 브라우저 확인 스크립트에 삭제 확인, 본문 스크롤 전후 사이드바 위치 유지,
  마지막 메뉴 접근을 반영해 통과했다. 작은 문구·CSS 수정으로 전체 테스트·빌드를 반복하지 않았다.
- 질문 조사: `295333c9` 및 `docs/dev-log/2026-08-05-zh-ko-nine-act-pilot.md`에서 중→한 30건이
  3화행×3수준×2모드 18건 + 확장 6화행×중급×2모드 12건의 파일럿임을 확인했다.
  당시 실제 실행·재개 결과는 최초 생성 30회, 저장 24건이며 이 기록을 현재 운영 DB 상태로 해석하지 않는다.
- `FULL_BATCH_QUOTA_495`는 7월 말에 도입된 한→중 번역 378·통역 117의 대량 생성 계획이다.
  현행 `batchPlan.ts`는 이를 과거 배치 재현·재개 호환용으로 설명하며, 별도의 최종 corpus 코드는
  504건 계획을 사용한다. 현재 학기 수업에 필요한 생성량을 이 과거 수치로 확정하지 않는다.
- 판단: 자동화 유지와 과거 실험 프리셋의 기본 노출은 구별해야 한다. 이번에는 요청한 하단·사이드바만
  수정했으며, 30·495 프리셋의 위치·실행 조건 변경은 아직 적용하지 않았다.
- 단순 UI 수정과 과거 기록 확인으로 research-trail 추가 없음. 논문 영향은 관리자 메뉴 고정·하단 표시 변경이며
  생성 수량·모델·프롬프트·계약·운영 배포는 동일하다.

## 승인 후속 · 과거 프리셋과 중복 안내 제거

- 사용자가 두 과거 프리셋을 기본 제작 화면에서 제외하도록 승인했다. 이어 상단 제작 흐름 안내 띠도
  아래의 생성 조건·계획·실행 제목과 중복되므로 링크·실행 바로가기와 함께 제거했다.
- 한→중·중→한 모두 일반 계획 함수로 수준별 번역 수량·통역 배율을 입력하게 했다. 방향 전환은
  입력 수량을 유지하고 결과·선택을 초기화한다. 기본 72건 초기화도 선택한 방향을 유지한다.
- 495 프리셋 버튼뿐 아니라 일반 제작에서 400건 이상을 정확히 495건 및 특정 분포에 묶던 실행 조건을
  제거했다. 분포 표시와 실제 생성기의 점검·관리자 세션·재개·교수자 승인 경계는 유지한다.
- 과거 재현용 `batchPlan.ts` 함수·상수와 역사적 기록은 보존했다. 실제 생성·DB 쓰기나 연구 표본 확정은 없다.
- 검증: 관련 2파일 21 tests 통과(화면 7·기존 계획 14). 중→한 81건 계획의 합성 실행 전달,
  방향 전환, 504건 입력의 버튼 활성화, 선택·재개·중복 요청·오류 복구·중단·AI 비평을 확인했다.
  첫 타입 검사에서 테스트의 지원하지 않는 `exact` 옵션을 발견해 제거하고 재검사했다.
- 로컬 브라우저 스크립트 통과: 안내·과거 버튼 삭제, 양방향 수량 입력·여러 페이지 선택,
  사이드바 고정·마지막 메뉴 접근, 1440·1280·1024·390px 가로 넘침 없음. 최신 PC 캡처를 확인했다.
  테스트 선택자만 수정한 뒤 브라우저·전체 테스트·운영 빌드는 반복하지 않는다.
- 관리자 정본 §4.4, DEC-20260910-05, EVD-20260910-05를 갱신했다. 사용자 확인 필요 항목 없음.
