# Astra 미션 생성의 비동기 완료 회수

- 기준: main `f75d7034`; 작업 branch `codex/astra-background-generation-2026-09-07`.
- 목적: 기존 3사례 실험에서 135초 안에 얻지 못한 완성 미션을 회수한다. 과거 콘텐츠 소급 교정이나 모델 전면 교체는 하지 않는다.
- 모델: 개발의 구조 판단은 High 유지. 앱의 실험 호출은 `gpt-6-astra`, reasoning `medium` 유지. 기존 기본 생성·검수 모델은 그대로다.

## 구현과 경계

Responses `background:true, store:true`로 접수하고 응답 ID를 저장한다. 기존 장면 구성→전체 미션→후보 검사 흐름을 재사용하며 전체 미션 본문을 추가로 분할하지 않았다. 각 짧은 Edge 호출은 완료된 호출을 재사용하고 아직 끝나지 않은 응답만 조회한다.

`generation_jobs`에는 요청·버전·제공자 응답·완료 결과·처리권을 저장한다. 관리자만 조회/실행하며 브라우저 직접 쓰기는 금지한다. 분당 서버 스케줄러가 최대 3개 작업을 처리하므로 창을 닫아도 회수한다. 90초 배타적 처리권과 요청 중복 방지, 호출별 고정 ledger ID를 사용한다. 접수 여부가 불명확한 POST는 자동 반복하지 않는다. 일시적 실패는 이미 저장한 응답을 유지하며 명시적으로 재개할 수 있다.

관리자 미션 조립에 선택형 Astra 경로와 작업 이어받기를 연결했다. **서버의 생성 완료는 품질검사·교수자 승인 완료가 아니다.** 이어받은 결과는 기존 규칙검사·AI 점검·수리·초안 저장 경로를 따른다. 창을 닫은 동안 서버가 수행하는 범위는 생성과 결과 보존까지다.

- 각 사례는 Astra 장면 구성·전체 미션·후보 호출과 기존 GPT-4.1 후보 검사를 포함한다. 생성 총액 추정 $1.731은 독립 코드 리뷰 비용·세금 등을 제외한다.
- 시간은 polling·통신 지연을 포함한다. 거절·사과의 긴 본문 호출이 135초를 넘겨도 완성 결과를 회수했다.
- 결정론 검사의 fail은 없고 길이 단서 및 공유 Anchor의 중복 경고가 남았다. 의미 품질 검수·교수자 승인·학습효과는 검증하지 않았다.
- 이전 정합성 수정이 반영된 프롬프트이므로 과거 파일럿과 통제된 모델 품질 비교는 아니다. Astra의 우월성을 확정하지 않는다.

## 검증·독립 검토

- 관련 Vitest 37개, 작업 DB/RLS/배타적 처리권 PGlite 3개, typecheck 통과. 운영용 build 통과. 전체 회귀와 최종 build는 PR 필수 CI에서 수행한다.
- 새 DB·RLS 경계에 대해 Opus의 제한된 읽기 전용 검토를 수행했다. 복구 불가 상태·스케줄 처리량·호출 한도 지적을 수용했고, 이미 구현된 인증 설정과 handler 분리에 대한 가정은 코드로 반증했다. 최초 응답은 출력 한도 때문에 결론이 없어 검토 완료로 세지 않았고, 두 번째 완성 응답의 판정과 조치를 기록했다.
- 증거: `docs/evidence/2026-09-07-astra-background/`. API 키·로그인 토큰·학생 기록은 포함하지 않는다.
- 운영 DB/Edge/Railway 적용과 스케줄 회수 smoke는 main 통합 후 별도 배포 영수증에 기록한다. 이 문서의 실험만으로 운영 배포 완료를 주장하지 않는다.

## 운영 확인에서 발견한 확장 기본 권한

실제 서버 회수는 완료됐고 관리자 요청 200·비로그인/잘못된 worker token 401을 확인했다.
그 뒤 권한 조회에서 pg_net의 `net.http_request_queue`가 PUBLIC 읽기를 허용함을 확인했다.
큐에는 서버 인증 헤더가 잠시 들어가므로 해당 큐의 PUBLIC/anon/authenticated 권한을 회수하고
worker token을 회전하는 추가 migration을 적용한다. 실제 외부 유출을 관찰했다는 뜻은 아니다.
같은 PUBLIC 기본 권한을 재현한 회귀 검사 1개를 추가해 작업 DB 검사는 총 4개다.
일반 생성 입력은 처음부터 DB에 저장된다. 로컬 파일럿을 격리 DB 행으로 옮긴 smoke에서는
JSONB 키 순서 때문에 처음 일치 검사가 중단됐으며, 입력 의미 동일성을 확인한 뒤 검증 행의
대응 해시만 정렬해 재개했다. 새 유료 호출 없이 생성 본문을 회수했고 내용 차이는 없었다.
생성 시각·그에 따른 provenance hash는 재실행 시 달라진다.
