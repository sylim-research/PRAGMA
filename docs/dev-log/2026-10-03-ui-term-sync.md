# 2026-10-03 화면 문구 용어 정합 (공개·학습자·교수자 화면)

배포본(`pragma.up.railway.app`, `0477084f`)의 공개 화면, 대표 미션 시연 전 과정, 학습자 교과목·주차·미션 안내·내 기록을 논문 용어 기준과 대조해 발견한 문구만 고쳤다. 같은 날 교수자(관리자) 화면도 점검해 이어서 고쳤다.

## 바뀐 것

- **DCT 상태명**: 화면의 「최종안」 → 「확정안」(미션 안내 「확정안을 내가 결정하기」, 안내문, 재검토 제목·입력란 이름, 완료 문구). 재검토의 확정 버튼은 「이 번역(통역)으로 확정하기」로 통일. 데모 기록의 「최초안·최종안」 → 화면 이름 「최초 번역·최종 번역」. 「내 판단으로 최초안을 확정」 → 「초안을 그대로 확정」.
- **세 검토 기준**: AI 피드백 칸 「의미 충실성·문법 정확성」 → 「의미적 충실성·문법적 정확성」.
- **관계·상황 조건 표시**(`CanonicalMissionRun` 안내): 「상대적 지위·친숙도·부담」 → 「상대적 권력·사회적 거리·행위 부담도」.
- **MJT 결과**: 「맞았습니다」 → 「기준 판단과 같습니다」. 판단과 이유 문항의 「가능한 수정 예시」 → 「참고 표현」.
- **전체 구조**(`/architecture`): 「PRAGMA · 통합 워크플로우」 → 「PRAGMA 워크플로우」, 「DCT형 통번역 산출」 → 「DCT형 통번역 과제」, MJT 활동명을 화면 표시명(단일 표현 판단·판단과 이유·복수 표현 비교·수정안 선택·직접 수정)으로, 「의미·언어·화용 3층」 → 「의미·문법·화용 기준」, 「이견 제기」 → 「학습자 의견」, 「최초안·최종 산출」 → 「초안·확정안」, 「관문」 → 「승인 단계/승인된 미션」, 「승인 미션」 → 「승인된 미션」, 「교수자 검토」 → 「교수자 감수」, 「연구 데이터」 → 「연구 자료」.
- **그 밖**: 첫 화면·내 기록 「화행 목적」 → 「화행목적」, 주차 화면 「학습목표 · …상황과 상대에 맞게」 → 「학습 목표 · …관계와 상황에 맞게」(요청 주차 기본 문구), 주차 수업자료 「교수자 검수 후 공개」 → 「교수자 최종 승인 후 공개」, 교과목 카드 보조 라벨 「수행모드」 → 「수행 방식」, 개인정보처리방침의 「판단 과제 응답·이의·검수·연구윤리」 → 「MJT 응답·학습자 의견·AI 검토·연구 윤리」.

## 관리자 화면

- **생성계약·운영 프롬프트**: 프롬프트 이름표의 「지시문」 → 「프롬프트」, 「요청서」 → 「요청 프롬프트」(`scripts/snapshot-prompts.mjs`의 이름표·설명만 바꾸고 스냅숏을 다시 생성. 프롬프트 본문과 `core_surface_hash`는 그대로). 설명문의 「선행 발화」 → 「선행발화」, 「정답 단서 제거」 → 「답 방향 단서 제거」, 「적정·부족·과함」 → 「과소·적정·과잉」, 「화용 대역」 → 「적절성 범주」, 「원문 충실성」 → 「의미적 충실성」, OpenAI 재검토의 「수용·보완·기각 의견」 → 「재검토 분류값」, 「MJT 5문항」 → 「MJT 판단 문항 5개」.
- **MJT 문항 이름**: 교수자 최종 승인 체크리스트·미션 미리보기·제작 작업대·학습 미션 제작 안내·학습 수행 기록 상세를 화면 표시명(단일 표현 판단·판단과 이유·수정안 선택·직접 수정·복수 표현 비교)으로 통일. 기록 상세는 v6 미션이면 저장된 `short_label` 대신 문항 ID로 활동명을 고른다(데이터는 그대로).
- **DCT 상태명**: 학습 수행 기록·학급 응답 분포의 「최초 산출/최종 산출/최초 산출 유지」 → 「초안/확정안/초안 유지」. 기록 상세의 「상황과 출발텍스트」 → 「관계·상황과 원문」, 「출발텍스트」 → 「원문」.
- **그 밖**: 「언어 방향」 → 「언어방향」(대시보드·생성·배치·제작·실제 자료·학습 유형 선택), 「목표 화행」 → 「목표화행」, P·D·R 영문 보조 표기 「Imposition」 → 「Ranking of imposition」, 연구용 기록 내보내기의 「형식 1판」 → 「형식 버전 1」·「학습 데이터(연구 자료)」 → 「연구 자료」, 강의계획서 DCT 진행 문구 정리.

## 바뀌지 않은 것

- 학습 흐름, 판정 로직, 저장 구조, DB 데이터. 내부 식별자·주석.
- DB에 저장된 문자열(미션 제목 「번역 학습 미션」, 학습자 의견 안의 내부 꼬리표)은 데이터라 손대지 않았다.
- 복수 표현 비교의 「허용 판단」 꼬리표 표시 방식은 의미 판단이 필요해 보류했다.

## 후속 (같은 날, 연구자 승인)

- **복수 표현 비교 꼬리표**: 표현마다 인정하는 판단에 「허용 판단」 대신 「기준 판단」을 붙인다. 이 문항 데이터에는 기준값과 인접 허용값의 구분이 없고 인정 목록(`accepted_band_codes`)만 있기 때문이다. 용어대장 「MJT 결과 꼬리표」 절에 같은 규칙을 추가했다. 판정 로직·데이터는 그대로.
- **주차 이름**: 학습자 화면의 주차 제목 규칙을 `weekDisplayTitle`(`weekGuidance.ts`)로 옮겨 학급 응답 분포·수업자료 생성의 주차 칩도 같은 이름(「칭찬 화행」 등)을 쓰게 했다. DB에 저장된 옛 주차 제목(「칭찬하기」·「사과 · 수리」 등)은 그대로 둔다. 15주 수업 편성 화면의 7·14주 「전반부/종합 성찰·정리」를 학습자 화면과 같은 「중간/종합 메타화용 토론」으로 맞췄다.
- **대표 미션 메뉴 제목**: 현행 대표 미션(요약 「옆집 이웃에게 택배 보관을 부탁하는 글 메시지」)이 메뉴 제목 표에 없어 「번역 학습 미션」으로 대체되던 것을 「이웃에게 택배 부탁」으로 표시한다.
- **보류 — 중심 질문 안내문**(「관계(P)·거리(D)·부담(R), 상황과 원문」): 주차 수업자료 기본 문안에 들어가 content-review Edge 묶음()에도 포함된다. 고치면 Edge 재배포가 필요해 이번에는 바꾸지 않았다.
