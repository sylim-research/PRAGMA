# 2026-09-19 관리자 대시보드 숫자 정합

## 문제

- 상단 「품질 점검 대기 183」과 규칙 검사 칸 184가 할 일처럼 보였으나, 실측 결과 183은 현재 기준 검수를 받은 적 없는 mission_v5(179)와 옛 기준(content_review_v2)으로만 검수된 v5(4)였다. v5는 검수 대신 v6로 전환하므로 처리할 대기가 아니다. 실제 대기는 규칙 불통과 v6 1건과 교수자 승인 88건뿐이었다.
- 검수 단계 카드가 대기 기준이라 1~4단계가 거의 0으로 보여 흐름이 드러나지 않았다. v6는 생성 시 규칙 검사와 OpenAI 품질 점검을 함께 받으므로 1·2단계 대기는 구조적으로 0에 가깝다.
- 라이브러리 「편성 가능 미션」(`libraryMissionIsReady`)이 mission_v5만 인정해, 편성기(`composer.ts` `is_native_mpj5`, v5·v6)와 달랐다. 교수자 승인된 v6 15건이 빠져 60으로 보였다(실제 75).
- 대시보드 첫 칸 「시나리오 재료 366」(전체 코어)과 라이브러리 탭 「시나리오 재료 1」(미션 미생성)이 같은 이름으로 다른 집합을 가리켰다.

## 변경

- 대시보드 대기 수에서 「현재 기준 run이 없는 mission_v5」를 뺀다(`countUnconvertedV5Missions`). 화면에 별도 숫자로 두지 않는다.
- 검수 단계 카드 숫자 = 그 단계를 마친 서로 다른 미션 수(누적). 대기 수는 툴팁 「지금 대기 N개」. 실측: 규칙 167 · OpenAI 167 · Claude 29 · 재검토 25 · 교수자 승인 77.
- 선택 단계(3·4)는 점선 틀 「선택 검토」 하나로 묶는다.
- 라이브러리 편성 가능 판정에 mission_v6 포함(편성기와 동일 기준).
- 첫 칸 이름 「상황 시나리오」. 사이드바 5번 「학습 기록·연구 활용」. 대시보드 보조 회색 글자 대비 한 단계 상향.
- 검토 후 기각: 누적 생성 수(보관 포함 1,836) 병기, 「v5 미전환 N」 표시, 「DB 실시간」 배지 1회화, 카드별 「선택 단계」 태그.

## 정합 (2026-09-19 실측)

상황 시나리오 366 = 전체 미션 365 + 미션 미생성 재료 1 · 전체 미션 365 = 승인 전 275 + 승인됨 90 · 승인 전 275 = 검수·승인 중 89 + v5 미전환 183 + 수정 요청 3 · 승인됨 90 = 편성 가능 75 + 편성 대상 아님 15(옛 4문항 v5 13 + 옛 배포본 2) · 교수자 승인 완료 77 = 편성 가능 75 + 옛 배포본 2.

## 남은 것

- 품질 점검 화면(`/admin/ai-review`)과 라이브러리 「승인 전 미션」은 v5 미전환 183건을 그대로 포함한다(대시보드와 차이).

## 후속 (같은 날) — 관리자 메뉴 순차 점검

- 생성 계약·프롬프트: 런타임 미사용 Legacy 문서 보관함 화면 제거(DB 테이블 유지), 프롬프트·지문 관리 박스 제거(지문 기록은 DB에 유지), 카드 이름·한 줄 설명을 현행 용어로 윤문(지시문 본문·지문 불변), 품질 관리 구조 문구 윤문.
- HSK 3.0 어휘 코퍼스: 고정값 「현재 점검에 적용 5,400개」 삭제(수준별 기준이 다름), 제목의 작업용 꼬리표(`[v6 변환]`)를 화면에서만 제거, 옛 용어·개발용 코드 줄 정리, 초록 계열을 브랜드 색으로, 보조 설명 윤문. 수준별 어휘 수는 DB 실측과 일치 확인(1급 300·2급 200·3급 500·4급 1,000·5급 1,600·6급 1,800·7–9급 5,600).
- 실제 자료 활용 분석: 최근 분석 1건 기본 펼침, 주황·갈색을 브랜드 색으로, 이모지 제거, 「상황 시나리오 만들기」·「버리기」, 출처·메모 입력 칸 제거, 「보관함」 → 「분석 기록」. 오른쪽 칸에 기록을 옮기는 레이아웃은 시도 후 원복.
- 주장 경계(실측): 실제 자료 분석 1건·후보 3개, 생성기로 넘어간 후보 0건, 실제 자료에서 출발한 현행 상황 시나리오 0건.
