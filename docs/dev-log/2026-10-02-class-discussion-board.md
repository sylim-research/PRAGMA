# 2026-10-02 학급 응답 분포 탭 → 토론 보드 재구성

대상: `/admin/decision-traces?tab=class` (학습 수행 기록 › 학급 응답 분포). 논문 5.2.2 「판단 분포 → 근거 비교 → 토론 질문」이 화면에서도 이어지도록 재구성했다. 설계안은 2026-10-02 Codex 검토 의견을 그대로 따랐다.

## 바뀐 것

- **첫 화면**: 교과목 선택과 주차 칩을 한 줄로 줄이고, 그 아래에 선택한 미션 요약(화행·번역/통역·방향·학습 초점) + 응답 현황(집계 학습자·응답 있는 문항·이견 제시) + MJT 판단 문항 5개의 작은 분포 카드(학습자 제시 순서 1→2→5→3→4) + 선택 문항 상세 + DCT형 통번역 과제 + 토론 관점을 둔다.
- **문항별 시각화** (`src/lib/mission/classDiscussion.ts`, `src/components/admin/ClassDiscussionBoard.tsx`)
  - MJT1 단일 표현 판단: 4점 척도 가로 누적 막대(척도 순서 고정, 0건도 표시).
  - MJT2 판단과 이유: 척도 분포 + **판단 × 선택 이유 교차표** + 「이유를 본 뒤 판단을 바꾼 응답」 건수. 분포는 최초 판단(`scale_code`) 기준이며 `revised_scale_code`로 덮어쓰지 않는다.
  - MJT5 복수 표현 비교: 후보별 적절성 범주(과잉·적정·과소) 누적 막대를 나란히.
  - MJT3 수정안 선택: 수정안 전문 + 선택 막대.
  - MJT4 직접 수정: 원래 표현과 익명 수정문 카드(같은 문장은 건수만 묶음, 분류하지 않음).
  - v6 이전 형식(judge3·reason 등)은 기존 축별 분포로 그대로.
- **DCT형 통번역 과제**: 「학급 전체」(최종 결정 유지/수정 · 이견 제시 · AI 1차 화용 판정 분포)와 「사례 비교」(익명 응답을 2개까지 골라 원문 → 최초 산출 → AI 피드백 → 이견·근거 → 최종 산출을 나란히). **수정 여부와 이견 여부는 따로 센다.** 「이견 사례 열기」는 이견 사례 2건을 비교 칸에 올린다.
- **토론 관점 3개**(복수의 적절한 선택 가능성 · 판단 근거의 차이 · 콘텐츠의 불명확성)는 교수자가 검토하는 관점으로 제시한다. 시스템은 원인을 확정하지 않는다.
- **데모 응답** (`src/lib/demo/virtualClassRows.ts`): 선택한 v6 미션의 실제 문항·선택지·참고 표현에서 가상 학급 20명의 응답 행을 조립하고, 운영 화면과 같은 `buildClassDiscussion`으로 집계한다. 상단에 「데모 · 가상 학급 20명 · 실제 학습자 자료 아님」을 표시하고, 「실제 응답 / 데모 응답」을 명시적으로 전환하며(`?demo=1`), 응답이 없는 운영 화면에는 「데모로 살펴보기」 입구를 둔다. 데모에서는 마감·공개 운영 단계를 숨긴다. 운영 DB에 저장하지 않는다.
  - 중국어 문장을 지어내지 않는다: MJT4 수정문은 그 문항의 `reference_alternatives`·`contrast.target`(+대표 미션이면 2026-09-28 연구자 실제 수정문), DCT 산출과 AI 피드백은 대표 미션의 기록된 실제 수행(`representativeDemoFeedback`: A·B 초안과 gpt-4.1-mini 피드백 원문)만 쓴다. 다른 미션은 참고 표현을 최종 산출로 두고 피드백 기록 없이 둔다.
  - 이견 사유(한국어 4건)만 가상 학급 구성의 일부로 작성했다.
  - 분포: MJT1 3·7·8·2(제5장 가상 분포와 동일) / MJT2 2·6·9·3, 이유 6·10·4, 판단 변경 2 / MJT5 첫 후보 13·6·1로 갈림 / MJT3 5·12·3 / DCT 유지 10·수정 10·이견 4(수정하면서 이견 1 포함).
- **개발용 도판 경로** `/dev/class-discussion-demo` (`src/pages/dev/ClassDiscussionDemo.tsx`, DEV 번들만): 대표 미션(95209155) + 가상 학급 20명을 로그인 없이 연다. `?item=2`로 문항, `?dct=cases`로 사례 비교를 바로 연다. 논문 캡처 후보 = ① `?item=2`(MJT 분포 + 판단 × 이유 교차표) ② `?dct=cases`(DCT 이견 사례 비교).
- 조회: `fetchMissionClassRows`(`classResponseFetch.ts`)가 `first_response`·`revised_response`·`target_feature_observed`를 함께 읽는다. 마감(`closeClassResponses`)에 넘기는 `pattern`은 종전과 같은 `aggregateMissionResponses` 결과다.

## 바뀌지 않은 것

- 응답 수집 → 분포 고정 → 학습자 공개 흐름과 RPC. 학습자에게 공개되는 것은 종전과 같은 `pattern`(건수)뿐이며 산출·수정문·이견 사유는 학습자에게 가지 않는다.
- 집계 대상(수업 기록 공유에 동의한 학습자만), 학습자별 최신 완료 1건 규칙, 「많이 고른 응답이 정답을 뜻하지 않는다」 문구.
- 학습자 화면, DB, 에지 함수. `ClassResponseDashboard`·`/dev/virtual-response-demo`(제5장 MJT1 도판)는 그대로 둔다.

## 주의

- 토론 보드는 항상 현재 저장된 행에서 집계한다. 분포 고정 뒤에도 보드는 살아 있는 행을 보여 주며, 고정된 `pattern`은 학습자 공개 화면에서만 쓰인다.
- 개별 수행 기록에서 이미 교수자가 보는 산출·수정문·이견 사유를 이 탭에서는 익명 번호(응답 n)로만 보인다. 프로필 ID·이름은 뷰 모델에 넣지 않는다.
- 요청 화행은 콘텐츠·응답이 가운데 범주를 `appropriate`로, AI 피드백은 `within_band`로 적는다 — `normalizeBand`로 한 범주로 읽는다.

## 같은 날 후속 — 밀집 완화와 시각화 다양화(연구자 피드백)

- 밀집 완화(P0): 막대 안에 비율, 범례는 색점·이름·건수만 · 요약 카드 높이 통일(MJT5는 후보 4개 미니 막대 가로 배열) · 교차표 머리글 「이유 n · n건」+전문은 표 아래 목록 · 사례 비교의 원문은 한 번만, 응답 칩은 이견 제시만 기본(「전체 응답 보기」로 펼침).
- 시각화 다양화(차트 라이브러리 없이 SVG·CSS로): MJT1·MJT2 = **도넛 + 척도 스펙트럼 띠**(매우 적절→매우 부적절 축 위에 척도별 비율을 원의 크기·숫자로) · MJT2 교차표 = **히트맵**(행 척도색의 농도 = 건수) · MJT5 = **발산형 막대**(적정 범주를 축 가운데에, 과소는 왼쪽·과잉은 오른쪽, 1% = 폭 0.5%로 넘침 방지) · MJT3 = 가로 막대 · MJT4 = 수정문 카드 · DCT 학급 전체 = 작은 도넛 2개(수정 비율·이견 비율) + AI 판정 누적 막대.
- 평균·점수는 만들지 않는다(척도 위 분포만). `Donut`·`SpectrumStrip`·`DivergingBar`는 보드 파일 안의 로컬 컴포넌트다.

## 같은 날 후속 2 — 학습자 「내 기록」 시각화(연구자 지시: 흐름·위치·변화 세 가지)

대상 `/learner/records`. 원칙은 그대로다 — 점수·정오·유형·고친 건수를 만들지 않고, 참고 답(accepted codes)을 읽지 않는다.

1. **이번 수행의 흐름**(`FlowStrip`): 수행마다 판단 다섯 단계(학습자 제시 순서 1→2→5→3→4)와 통번역 최종 결정을 3×2 격자로. 각 칸에는 내가 고른 것만 — 척도는 색점+이름, MJT2는 이유를 본 뒤 바꾼 판단을 화살표로, 복수 표현 비교는 표현 4개의 범주 색점, 통번역은 수정/유지와 「내 의견」 배지.
2. **학급 속 내 위치**(`ClassPositionPanel`): 교수자가 학급 분포를 「학습자 공개」한 미션에만, 단일 표현 판단·판단과 이유의 척도 스펙트럼 띠 위에 「나」 표식. 공개 전(수집 중·고정·최소 인원 미달)에는 칸 자체를 숨긴다. 기존 학습자 RPC `learner_get_peer_responses`를 그대로 쓴다(새 DB·RPC 없음). 공개 분포에는 v6 복수 표현 비교의 후보별 범주가 없어 척도 두 문항만 그린다.
3. **표현 변화 지도**(`ChangeFlow`): 최초 → AI 피드백 → 최종을 세로 흐름으로. 바뀐 구절은 최초에서 지우고 최종에서 밑줄(기존 diff 재사용). AI 피드백 칸에 화용 판정 범주 배지·다시 볼 곳·설명(3줄, 더 보기), 그 아래 「내 의견」(이견 조건·사유). 「자세히 보기」 접기는 없앴다.

- 차트 `Donut`·`SpectrumStrip`·`DivergingBar`·`StackedBar`는 `src/components/charts/responseCharts.tsx`로 옮겨 학급 보드와 함께 쓴다. `SpectrumStrip`에 `mine`(「나」 표식) 추가.
- 모델: `src/lib/learner/recordFlow.ts`(흐름·변화·공개 분포 → 내 위치).
- **데모**: `?demo=1` 또는 개발용 `/dev/learner-records-demo`(로그인 불필요). 학급 보드 데모의 「응답 5」(이견을 남기고 수정한 학습자)를 「나」로 삼아 같은 20행에서 나온다 — 학급 보드와 묶음 도판이 된다. 운영 기록·RPC를 읽지 않으며 「데모 · 가상 학급 20명 중 한 명 · 실제 학습자 자료 아님」 배지를 단다.
- 검증: typecheck, `LearnerRecords.test.tsx` 15건(흐름 띠·공개 후에만 위치 표시·데모 3건 추가, 접기 테스트는 변화 지도 테스트로 교체) 통과. 1366px에서 데모 화면 캡처 확인.

## 같은 날 후속 3 — 데모 학습자 = 공개 시연 미션의 시연 답안(연구자 지시)

- 가상 학급의 **응답 1**(`DEMO_LEARNER_ROW = 0`)을 `/demo/mission`의 시연 답안과 글자까지 같게 고정했다: MJT1 기준 판단(매우 적절) · MJT2 다소 적절+「요청 내용과 시점이 분명」(이유를 본 뒤 바꾸지 않음) · MJT3 기준 수정안(2번) · MJT4 연구자 실제 수정문 · MJT5 [너무 직접적·알맞음·알맞음·너무 직접적] · DCT 최초안 A → AI too_direct → 최종안 B(수정, 이견 없음). 값을 바꾸지 않고 다른 자리와 맞바꿔 20명 분포는 그대로다(`classDiscussion.test.ts`에 고정 검사 추가). 「내 기록」 데모의 「나」도 이 사람이다 — 논문 4.3 미션 캡처·「내 기록」·학급 보드가 한 사람의 같은 수행을 가리킨다.
- 「내 기록」 단순화(학부생 기준): 카드 순서를 흐름 → 변화 지도 → 「우리 반은 어떻게 판단했을까」로 바꿈 · 흐름 띠에 「이번 미션에서 내가 고른 것」 한 줄과 범주 색 범례, 복수 표현 비교는 번호 든 색 동그라미 · 최초 번역은 그대로 보이고 최종 번역에만 밑줄(「밑줄 = 처음과 달라진 부분」) · AI 설명은 접지 않음.
- 학급 보드 데모의 「사례 비교」 기본 선택 = 응답 1(시연 답안 학습자, 수정·이견 없음) + 첫 이견 사례(응답 4, 같은 최초 산출·같은 AI 피드백에 관계 근거 이견·유지). 데모에서 사례 비교 탭을 처음 열 때와 `/dev/class-discussion-demo?dct=cases`에 적용(`defaultDemoCompare`). 실제 응답에서는 교수자가 고른다.
- 「내 기록」에서 「이번 미션에서 내가 고른 것」 흐름 띠와 수행별 「수정/유지」 배지를 삭제했다(연구자 판단: 학생에게 주는 정보가 없고 「수정」이 무엇을 뜻하는지 혼선). 날짜는 연도까지(「2026년 9월 30일」). 흐름 모델(`buildMissionFlow`)도 함께 지웠다. 남은 구성 = 원문 → 날짜 → 최초 번역·AI 피드백·최종 번역 → 우리 반은 어떻게 판단했을까.

## 같은 날 후속 4 — 「내 기록」 최종 UX·워딩 정합화(HIGH-RISK GATE 판정 반영)

판정: ① 개인 해석은 문항 단위 사실 비교만(경향·유형·강약점·여러 문항 합산 요약 없음) ② 데모 분포 MJT1 3·7·8·2 유지(제5장 도판과 같음) ③ 학급 비교는 집계가 있는 수정안 선택(MJT3)까지, 직접 수정 제외, 복수 표현 비교는 RPC 확장이 필요해 보류.

- 흐름: 화행별 학습 기록 → 최초 번역 → AI 피드백 → 최종 번역 → **우리 반의 판단**(단일 표현 판단·판단과 이유 척도 띠 + 수정안 선택 막대, 「나」 표식) → **판단 비교**(활동 / 내 선택 / 반에서 가장 많이 고른 선택 / 기준 판단) → **핵심 정리**(같은 콘텐츠 판본의 lesson_points를 그대로) → 다시 생각해 볼 질문.
- 기준 판단·핵심 정리는 수행 기록의 `content_hash`와 미션 본문 `provenance.mission_content_hash`가 같을 때만 보인다(학습자용 `fetchMissionByScenario` 재사용, 지문 없는 옛 기록은 조회하지 않음). 학급 분포가 공개되지 않았으면 판단 비교는 없고, 핵심 정리는 판단 문항(1·2·3)만 보인다. 새 RPC·DB·AI 호출 없음.
- 문구: 학습 미션·교과목·「화행별 학습 기록」·「수행한 화행 n/9 · 화행을 선택하면 해당 기록만 볼 수 있습니다」·「다시 살펴볼 점」·「밑줄: 처음 번역(통역)에서 바뀐 부분」·「최초 번역을 그대로 유지했습니다.」·「저장된 AI 피드백이 없습니다.」·「우리 반의 판단」·「다시 생각해 볼 질문」(메타 설명 삭제)·「최종 표현에서도 원문의 의미와 화행 목적이 유지되었나요?」·빈 상태 「아직 완료한 학습 미션이 없습니다.」 「학습 미션을 마치면 내 번역과 최종 결정이 여기에 기록됩니다.」 「이번 주 학습 미션으로 →」·데모 배지 「데모 · 가상 학급 20명 · 실제 학습자 자료가 아닙니다」.
- 주석 정정: 학습자 재검토 = 4.3.5·5.2.2(37차). `LearnerRecords.tsx`·`recordFlow.ts`의 「5.2.3」을 고쳤다.

## 같은 날 후속 5 — 「내 기록」 감산 정리(학생 학습 도움 중심)

- 구조를 미션 카드 안 4단으로: **내 수행**(최초 번역 → AI 피드백 → 최종 번역, 바뀐 부분 밑줄) → **우리 반의 판단**(분포·「나」·「많이 고른 쪽이 정답은 아닙니다」) → **핵심 정리** → **생각해 보기**(한 줄).
- 삭제: 「판단 비교」 표(그래프와 중복) → 각 활동 카드 머리에 「기준 판단: …」 라벨 하나로 대체(같은 판본일 때만). 페이지 맨 아래 상시 2문항 상자 → 카드 끝 한 줄 「생각해 보기 · 최종 번역에서도 원문의 의미와 화행 목적이 유지되었나요?」(번역/통역에 따라 표기).
- 축소: 핵심 정리를 제목+본문 두 줄 블록에서 점 목록 한 덩이(굵은 제목 + 같은 줄 본문)로. lesson_point 문장은 승인된 콘텐츠라 글자를 바꾸지 않았다(세 항목 모두 이미 2문장 이하).
- 모델에서 `judgmentComparisons`를 지웠다. 새 AI·RPC·DB 없음.
