## 이 작업을 시작한 최초 취지

이번 UX 개편의 중심 원리는 **최종 수행 장면(End State)에서 역설계하는 것**이다.
학습자가 설명을 읽고 연습을 시작하는 것이 아니라, 먼저 자신이 해결해야 할 실제
의사소통 장면에 들어간 뒤 그 장면을 성공시키기 위해 MPJ 4개를 리허설하게 한다.

의도한 전체 경험은 다음과 같다.

```text
최종 DCT 장면에 들어감
→ 이 장면을 해결하기 위해 MPJ 4개로 표현 감각을 익힘
→ 실제 번역·통역 수행
→ 의미·문법·화용 3층 피드백
→ 필요 시 수정
→ Take 1·Take 2로 변화 확인
→ 내가 완성한 결과를 소유
→ 나의 수정 노트에서 다시 발견
```

핵심 문장은 다음과 같다.

> 공부를 하기 위해 장면을 보는 것이 아니라, 이 장면을 해결하기 위해 공부한다.

따라서 콜드 오픈은 독립적인 장식이나 학습 설명이 아니라, 뒤이어 나오는 MPJ를
`독립 퀴즈`에서 `실전 직전 워밍업`으로 재해석시키는 장치여야 한다.

## 절대 보존할 연구·데이터 불변조건

- `intro → MPJ → 산출 → 3층 피드백 → 필요 시 수정 → 완료` 순서는 유지한다.
- MPJ 4문항, 후보, 판정 방식은 변경하지 않는다.
- `first_response`는 피드백 전 최초 산출, `revised_response`는 수정 후 최종 산출이라는
  의미를 유지한다.
- 실제 수정 여부는 `first_response !== revised_response`로만 판정한다.
- 상대 반응 추가 생성, 3회차 응답, 점수·언락 기능은 추가하지 않는다.
- DB·스키마·프롬프트·생성 콘텐츠·평가·`policy_ver`는 이번 표시 반복에서 변경하지 않는다.
- 콘텐츠 재생성은 하지 않는다. 전체 UX가 확정된 뒤 `policy_ver`를 한 번만 올리고 동결한다.

## 현재까지 고정된 제품 방향

1. 콜드 오픈은 최종 `production_task` 장면을 기준으로 한다.
2. 최신 합의 기준으로 학습 초점과 진행 레일은 콜드 오픈에서도 유지한다. 레일은 설명문이
   아니라 현재 위치와 안정감을 주는 뼈대다.
3. 콜드 오픈은 자동 타이머 없이 학습자가 직접 넘기는 두 박자
   (`장면/딜레마 → 상대의 신호 또는 내 차례`)를 유지한다.
4. `preceding_turn`이 실제로 있으면 그 발화를 사용한다. 없으면 개시형으로 보여 주고,
   응답 화행인데 선행 턴이 결측이면 내용을 만들지 않는 중립 폴백을 사용한다.
5. MPJ는 번역·통역 및 raw channel과 무관하게 DM형 대화 관찰·비교 표면을 쓴다.
6. 번역 DCT는 정적인 이메일형 작성기, 통역 DCT는 정적인 구두 수행 콘솔을 사용한다.
7. 따라서 콜드 오픈 두 번째 화면이 MPJ의 DM UI를 그대로 모사하면 안 된다. 콜드 오픈은
   `사건 발생`, MPJ는 `대화 관찰·표현 비교`, DCT는 `최종 수행`으로 시각 문법이 달라야 한다.
8. 완료 화면은 방금 만든 레퍼토리 카드, `나의 수정 노트`는 누적 보관소다. 이 구현은 이미
   운영 배포됐으며 이번 콜드 오픈 시각 재설계에서 되돌리지 않는다.

## 2026-08-02 시각 반복과 기각 이유

오늘의 콜드 오픈 세부 시각안은 **사용자 승인에 도달하지 못했다**. 다음 시도를 완료안으로
간주하지 않는다.

1. 초기 2페이지 장면 설명형
   - `오늘의 장면`, `장면 열기`, 안내문, 상황문, 관계 태그, `당신 차례`, 노란 설명 카드가
     같은 사실을 반복했다.
   - 결과: 사건보다 안내를 읽어야 해 콜드 오픈의 임팩트와 즉시성이 약했다.
2. 한 화면 사건 카드·레일 숨김 실험
   - 중복은 줄었으나 레일을 숨기면 위치감과 안정감이 사라졌다.
   - 결과: 레일 숨김은 최신 합의에서 기각됐다.
3. 전체 폭 인물 사이드카드 + 대형 대화 캔버스
   - 빈 공간을 채우기 위해 첫 화면을 큰 제목/우측 인물 카드로 나누고, 두 번째 화면을 큰
     메신저 캔버스로 만들었다.
   - 결과: 첫 화면은 발표 슬라이드처럼 비례가 무너졌고, 두 번째 화면은 여전히 비어 보였다.
     결정적으로 바로 다음 MPJ의 DM UI와 중복됐다.
4. 마지막 로컬 compact 장면 카드 + 어두운 수신 사건 카드
   - 대형 인물 카드와 메신저 입력창을 제거하고 MPJ와 다른 알림형 표면을 시도했다.
   - 자동·시각 검증은 했지만 사용자 승인 전에 작업 종료가 결정됐다. **채택안이 아니다.**

## 다음 설계자가 지켜야 할 재설계 기준

- 화면을 크게 만들거나 빈 공간을 장식으로 채우는 것을 몰입으로 간주하지 않는다.
- 정보량을 줄이되 DCT 장면의 사람, 내 목표, 상대의 부담 또는 관계 단서는 보존한다.
- 첫 화면은 보고서·프레젠테이션·분석표처럼 보이지 않아야 한다.
- 두 번째 화면은 거대한 빈 메신저 창, 답장 입력창, 전송 버튼을 사용하지 않는다. 이것은
  MPJ와 역할이 겹친다.
- 사건의 즉시성과 결정 압력은 실제 `preceding_turn`, 명확한 행동 CTA, 짧은 전환으로 만든다.
  `방금`, 읽음 상태, 타이머처럼 데이터에 없는 사실은 만들지 않는다.
- 데스크톱의 전체 실루엣을 먼저 정적 목업으로 비교한 뒤 코드에 옮긴다. 모바일 적응은 그
  다음 검증한다. 큰 코드를 반복 수정하기 전에 2~3개의 저비용 시각 대안을 먼저 비교한다.
- 사용자 승인 전에는 커밋·PR·배포·`policy_ver` 인상·콘텐츠 재생성을 하지 않는다.
