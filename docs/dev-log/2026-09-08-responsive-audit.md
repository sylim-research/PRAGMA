# 교수자 PC·학습자 모바일 반응형 점검

## 요청과 판정

- 사용자 요청: 교수자는 PC로 시연·수업 운영을 하고, 학습자는 노트북과 이동 중 휴대폰으로 접근할 수 있어야 하므로 현재 반응형 적용 상태를 점검한다.
- [단독 진행 적합]. 구현 변경 없이 코드와 실제 렌더링을 대조하는 점검이다.
- **판정: 기본 반응형 구조는 있으나 모바일 대응 완료로 볼 수 없다.** 대표 학습 경로에서 가로 넘침·핵심 내용 잘림·과도한 글자 줄바꿈을 재현했다.
- 기준: `codex/class-response-display-2026-09-08`, HEAD `c0051564a4c67af4aad99a0252a13583389d0e1f`. 점검 시작 시 tracked 변경 없음. `origin/main`의 `5886310bc0eb8a9f5febbd586d6edd40af695b11`과 파일 트리가 같음을 확인했다. 운영 URL은 `https://pragma.up.railway.app`.
- `docs/CANONICAL.md`, 현행 생성계약·학습자 구조·관리자 구조, 관련 dev-log와 evidence index를 확인했다. 논문 작업공간 정본목록의 세 경로와 일치한다.

## 방법과 범위

- Codex in-app 브라우저에서 CSS 뷰포트 360×800, 390×844와 PC 1280×720·1280×900을 사용했다. 각 단계의 실제 `innerWidth`·`innerHeight`, 문서 `clientWidth`·`scrollWidth`를 확인하고 화면 캡처와 버튼 조작을 함께 확인했다.
- 세로 스크롤바로 가용 폭이 15px 줄어든 경우가 있다. 가로 넘침은 `scrollWidth > clientWidth`로 구분했다. 문서 폭이 같아도 말줄임표로 내용이 가려지는 문제는 별도로 확인했다.
- 운영의 기존 교과목·학습 기록을 조회했다. 학습 미션은 저장을 억제하는 `/demo/mission`에서 합성 선택만 했다. 번역 입력 후 AI 제출은 실행하지 않았다.
- 피드백·이의 제기 입력·수정·완료는 같은 코드 트리의 로컬 DEV preview(`/learner/practice?preview=v5&step=A-FEEDBACK&preset=direct`)로 확인했다. 실제 서버 판정·저장 검증으로 해석하지 않는다.
- 통역은 기존 `InterpretingConsole`과 `LearnerJourneyShell`을 사용하는 일회성 로컬 fixture로 화면과 전사 확인·제출 콜백을 확인했다. 합성 전사와 로컬 상태 콜백만 사용했고 원발화 재생·마이크 녹음·음성 인식은 실행하지 않았다. fixture는 점검 후 제거했다.
- 측정 명칭과 실제 폭이 불일치한 태블릿 시도는 태블릿 검증 결과에서 제외했다. 아래 표의 폭은 실제 측정값이다. 모든 라우트·모든 콘텐츠 길이를 전수 검증한 결과는 아니다.

## 재현한 문제와 우선순위

### RWD-01 · 지금 반드시 해결 · MJT3 수정안의 가로 넘침

- `/demo/mission`에서 도입과 MJT1·2를 진행한 뒤 MJT3의 최초 판단을 확인하면 긴 중국어 수정안 3개가 나타난다.
- 360px 폭에서 수정안 표시 시 문서 `clientWidth=345`, `scrollWidth=373`으로 28px 넘쳤다.
- 긴 수정안을 선택하고 확인한 390px 화면에서는 `clientWidth=375`, `scrollWidth=483`으로 108px 넘쳤다. 선택·권장 배지가 추가되면서 내용이 오른쪽으로 밀렸다. 클릭 후 가로 이동으로 왼쪽 헤더까지 잘려 보이는 장면도 확인했다.
- 근거: `src/pages/learner/CanonicalMissionRun.tsx:99`, `:103`, `:754`. grid 안의 선택 버튼에 `break-keep`이 있고, 내부 가로 flex의 문장과 `shrink-0` 배지에 좁은 화면 대응이 부족하다.
- 수정 방향: 선택지의 최소 폭과 긴 중국어 줄바꿈을 제어하고 휴대폰에서는 배지를 문장 아래로 배치한다. 선택 전·선택 후·확인 후를 모두 다시 검증한다. 문장 내용을 줄여 해결하지 않는다.

### RWD-02 · 지금 반드시 해결 · 산출 전 요약의 판단 근거 잘림

- MJT5 확인 후 표시되는 ‘문항별 핵심 5가지’를 390px에서 확인했다. 여러 행이 중국어 표현 뒤에서 말줄임되어 화살표 뒤 판단 근거를 읽을 수 없었다. 전체 문장을 펼치는 조작도 없다.
- 근거: `src/pages/learner/CanonicalMissionRun.tsx:1762`의 무조건 적용된 `truncate`.
- 수정 방향: 핵심 문장을 여러 줄로 표시하거나 전체 내용을 열 수 있게 한다. 레이아웃 폭 검사만으로 통과시키지 않고 실제 판단 근거가 보이는지 확인한다.

### RWD-03 · 완성 전 해결 권장 · 학습 기록의 3열 카드 밀도

- 360px의 ‘9개 화행 학습 지도’에서 ‘요청’, ‘사과’, ‘감사’ 등이 한 글자씩 두 줄로 나뉘었다. 주차·수행 건수도 여러 줄로 흩어졌다. 가로 넘침은 없지만 한눈에 읽기 어렵다.
- 근거: `src/pages/learner/LearnerRecords.tsx:318`의 고정 `grid-cols-3`, `:333`의 카드 좌우 여백, `:350`의 제목 오른쪽 여백.
- 수정 방향: 휴대폰에서는 2열로 바꾸거나 카드 내부 여백을 줄여 제목이 한 줄로 읽히게 한다. PC의 3열 구성은 유지할 수 있다.

## 모바일 완료 판정 전에 남은 확인

- 실제 iPhone Safari·Android Chrome의 로그인, 중국어 키보드 입력, 키보드를 연 상태의 제출 버튼 접근성, 하단 내비게이션과 화면 안전 영역을 확인해야 한다. 현재 코드의 하단 내비게이션에는 별도 safe-area inset 처리가 없으나 실제 기기에서 겹침을 재현한 것은 아니다.
- 통역의 마이크 권한 허용·거부, 녹음·전사·수정·제출·재조회 종단은 실제 기기로 확인해야 한다. 이번 합성 전사 UI 점검은 음성 입출력 호환성의 증거가 아니다.
- 승인·공개된 학생 유인물 본문, 태블릿·가로 회전, 브라우저 확대 상태는 추가 확인 대상이다. 신규 기능 추가보다 위 세 결함 수정과 대표 실제 기기 흐름 확인을 우선한다.

## 변경·기록 경계

- 앱 소스·프롬프트·계약·DB·배포는 변경하지 않았다. 유료 생성·평가 호출, 실제 수행 제출, 콘텐츠 승인도 하지 않았다.
- 점검 문서와 `docs/research-trail/04_evidence_index.md`의 EVD-20260908-05만 추가했다. 아직 설계 변경을 채택·구현한 작업이 아니므로 decision·iteration·traceability는 갱신하지 않는다.
- 코드 변경이 없어 typecheck·전체 테스트·production build를 다시 실행하지 않았다. 기존 CI 통과를 모바일 렌더링 완료의 근거로 사용하지 않는다.
- 논문 영향: 테스트 수·버전·배포 상태 변화 없음. 모바일 사용 가능성을 주장하기 전에 세 화면의 수정 후 캡처와 실제 기기 검증이 필요하다. 프롬프트·계약 동결본 재발행 필요 없음.
