# Cross-check: Chinese expression review (DeepSeek) — 2026-10-20

Purpose: implement DEC-20261010-01 — an optional Chinese expression review inside the existing opt-in cross-check of content quality review. It runs after the comprehensive (Claude) review and before adjudication. The professor still makes every final decision.

Changes (branch `claude/deepseek-cross-review-2026-10-20`)
- `supabase/functions/_shared/contentReview.ts`: new stage `deepseek` with three stored states — not run (`null`), `failed` (with cause), `completed` (zero findings included). `crossReviewFindings` = Claude + completed DeepSeek findings; adjudication, professor findings and `nextReviewStage` use it. `deepseekPending` skips records that were adjudicated or finalized before the stage existed. `canRetryDeepseek` allows a retry of a failed run until the professor starts deciding. New operating prompt: Chinese expression scope only (lexis, collocation, grammar, register, address, speech-act realization) judged against the given situation, relation and source intent; stored appropriateness categories of MJT candidates are read as the intended category, so intentionally inappropriate candidates and preserved source text are not "corrected"; each finding is labelled as a production defect or as needing intent confirmation (deferred to the professor); suggested fixes are not presented as the single answer. Adjudication receives Claude and DeepSeek findings, judged by the same criteria without model weighting or majority vote; with no completed DeepSeek review its input is unchanged.
- `supabase/functions/_shared/contentReviewProvider.ts`: DeepSeek branch (OpenAI-compatible chat completions, `response_format: json_object`, schema in the prompt, 130 s timeout, empty-content guard). Output goes through the same evidence grounding and validation as other reviewers.
- `supabase/functions/content-review/index.ts`: actions `deepseek` and `deepseek_retry`. Key `DEEPSEEK_API_KEY`; model from `DEEPSEEK_REVIEW_MODEL` (default `deepseek-v4-pro`; `deepseek-chat` was retired 2026-07-24). A missing key or provider error is saved as `failed` and the flow continues. Only the content snapshot is sent — no learner records and no earlier model opinions. A successful retry that adds findings after a Claude-only adjudication reopens adjudication.
- Migration `20261020120000_deepseek_cross_review.sql`: `deepseek_review` jsonb column (status check), `running_stage` allows `deepseek`, `content_review_required_findings` and `validate_content_review_outputs` include completed DeepSeek findings (adjudication must decide Claude and DeepSeek findings exactly once; a failed run must record its cause), readiness requires adjudication when only DeepSeek has findings, gate rebind copies the column. No data change; not-run and failed never block approval.
- Admin UI: stage names follow the thesis terms — "교차 검토 · 종합" (Claude) and new "교차 검토 · 중국어 표현" (DeepSeek); the cross-check button reads "교차 검토 실행". The panel shows the DeepSeek row with model, result, a failed state with its cause and a "다시 실행" button, and each cross-check opinion's source (Claude/DeepSeek) on the decision card. Dashboard: six stage cards, three in the optional group; cumulative DeepSeek count counts completed runs only.

## Prompt v2 (same day, after comparing with the manual review history)

The manual DeepSeek web-chat reviews of 2026-09-18 to 10-10 (about 23 runs, provisional count; prompts and results kept outside the repo) were compared with the first prompt, and the researcher adopted the following:
- Explicit review standard: actual usage in Mainland Putonghua for the given relation and situation. No native-speaker identity or accuracy claim.
- For intentionally inappropriate expressions: ask whether the intended flaw actually reads as that flaw, and separately whether an unintended language error also gives the answer away. A flaw that reads as intended is not reported.
- Judgment labels shared with the manual records: naturalness / register-scene mismatch / implicature-strength mismatch / unintended defect / intended flaw unclear / disagreement with the stored category, plus a problem type. The last two always go to the professor (`routeDeepseekJudgments`; the model's raw output stays in `raw_result`).
- zh→ko source utterances: check that the intended force (politeness, firmness, complaint, hesitation) is carried; Korean candidates are out of scope; preserved real-world source text is not rewritten.
- Minimal fixes only for unintended defects, keeping the kind and strength of the intended flaw; when the intended flaw does not read, no fix is fixed — redesign is the professor's call.
- Prompt revision is recorded as `stage_prompt_version: zh_expression_v2_20261020` (the DB pins `prompt_version` to criteria:stage). The first prompt never ran.

Validation: `npm run typecheck` 0 errors; targeted tests 111/111 including the three key cases and judgment routing; review bundle `--check` verified; `npm run build` passes.

## Migration fixes before applying (same day, after a read-only review)

- `deepseek_review` CHECK now coalesces a missing or null `status` to '' so `{}` and `{"status": null}` are refused; SQL NULL stays the only "not run" state.
- `content_review_required_findings` now includes, under the focused policy, findings the adjudication accepted or refined — the rule the admin UI has applied since 2026-09-19. Before, the UI asked for such a decision and the DB refused the save (count mismatch); the gap predated this stage.
- The adjudication error keeps its old prefix ("Adjudicate every Claude and DeepSeek finding exactly once").

Real SQL check: `scripts/content-review-db.test.mjs` (PGlite, no network) now applies this migration on top of the existing chain. 40/40 pass: the 32 existing approval tests unchanged (existing approvals, multimodel_v2, weekly materials, rebind) plus 8 new ones — unknown states refused, not-run and failed do not block while a failure must state its cause, DeepSeek-only opinions require adjudication and a professor decision, zero opinions need no adjudication, incomplete results and a cross-check without Claude refused, accepted/refined warnings save, rebind copies the column, and a missing definition anchor aborts the whole batch including earlier statements.

Rollback, if ever needed, is a new forward migration, not an undo: drop `deepseek_review` (this discards any stored DeepSeek results), restore `running_stage_check` without 'deepseek', drop `content_review_deepseek_findings`, and restore the previous definitions of four functions — `content_review_required_findings` (20260909230000), `validate_content_review_outputs` (20260906100000), `assert_content_review_base_ready` (current deployed definition minus the one replaced condition) and `rebind_content_review_gate` (20260912140000). Atomic abort on error relies on the migration running as one transaction (standard `supabase db push`); running its statements one by one could leave earlier ones applied.
