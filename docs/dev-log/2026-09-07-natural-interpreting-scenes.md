  이웃에게 병원 예약 변경을 맡기는 장면이 상식적으로 납득되지 않는다.
- 원인: 생성 프롬프트·서버 보정·R16이 세 인물 서술을 강제했고, 일상/P/D 조합의
  범용 역할 쌍이 병원 소재에도 이웃을 강제할 수 있었다.
- 운영 대상 28d87b8e-ac97-4749-a4a5-3581f8c833df를 읽기 전용 확인했다.
  reviewed 상태이며 MJT5에서 직접 병원 방문을 요구하면서 R low로 표시하는 문제도 있다.
- [교차검증 권고]: 생성·검수 기준 변경. 사용자의 확정 방향을 구현하며 중복 검토는 수행하지 않는다.

## 변경과 범위

- 학생에게는 짧은 훈련 상황을 제시하고 1인칭을 허용한다. 원문의 의미·의도·화용적 힘,
  원문 인물과 상대 사이의 P/D/R, MJT5+DCT1은 유지한다.
- 저장된 과거 콘텐츠의 정확한 역할 소개 템플릿과 A/B 표기는 화면 투영 시 정리한다.
  이 처리로 실제 사건의 개연성이 고쳐졌다고 간주하지 않는다.
- 소재별 역할이 없으면 범용 이웃·구성원을 강제하지 않는다. 인물·용건·권한·신뢰·채널의
  연결을 생성과 의미 검수에서 평가한다. core 16번째 축 scene_plausibility 및
  mission implausible_scene을 추가한다. 키워드 일괄 금지나 별도 R 수치 규칙이 아니다.
- 사용자 재확인: 개연성은 통역·요청 전용이 아니라 9개 화행, 번역·통역, 양방향,
  모든 수준·도메인의 코어·MJT·DCT에 공통 적용한다. 화행별 계기·책임·수혜·결정·평가
  연결을 기준에 명시하고 과거 개별·개요 번역 생성 경로에도 같은 기준을 넣었다.
- 현재 기준과 다른 과거 생성 품질점검을 새 기준의 점검으로 재사용하지 않는다.
  기존 검수·승인·수행 데이터는 보존한다.
- 운영 비밀 설정에는 ElevenLabs 키가 없고 OpenAI 키가 있다. 현재 TTS는 OpenAI 경로다.
  사용자 선택은 목소리 하나로 통일하며 ELEVENLABS_VOICE_ID가 이전 클라이언트 기본값보다
  우선한다. 선택 음성이 실패하면 다른 목소리로 자동 대체하지 않는다.
