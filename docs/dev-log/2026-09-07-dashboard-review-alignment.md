## 1. 교과목 카드 (신규)

「수업 운영·학습 수행 현황」 맨 앞. 큰 수 = `curriculum_outlines` 전체, 설명 = 배정이 있는 교과목 수와 편성 전 수
(`미션 편성 4개 · 편성 전 1개`). 두 수가 다르면 빈 교과목이 있다는 뜻이다. 교과목이 최상위 단위인 근거:
주차·미션 배정, 백업 단위, 학습자 진입, 삭제 시 CASCADE가 모두 교과목에서 갈린다(논문 4.3.4 「세 교과목의 9개
주차 → 54개 미션」). `summarizeDashboardAssignments`에 `courseCount`(distinct `outline_id`) 추가, 조회 1개 추가.

## 2. 🔴 검토 단계 계산이 앱의 실제 규칙과 어긋나 있었다 (논리 결함 수정)

`nextDashboardReviewStage`가 규칙 → OpenAI → **Claude → 재검토** → 교수자를 모두 필수로 계산했다.
그러나 앱의 `nextReviewStage`(`_shared/contentReview.ts`, 2026-09-06 경량 검수 `focused_v1`)는
규칙 → (재사용 가능한 생성 품질 결과가 없을 때만) AI 검토 1회 → 교수자이고, Claude 별도 검토와 그 의견의
재검토는 **교수자가 선택했을 때만** 거친다. 논문 4.3.3·4.6.3도 그렇게 서술한다.
→ 대시보드는 교수자에게 갈 수 있는 미션을 「AI 별도 검토 대기」로 잘못 세고 있었다.

수정: 조회에 `approval_policy · independent_review_requested · approved_at · generation_quality->>mission_content_hash ·
claude_review->result->findings->0->>id`를 더하고(값이 아니라 존재 여부만), 계산 규칙을 앱과 같게 맞췄다.
이전 정책(`multimodel_v2`) 행은 종전대로 네 단계를 거친다. 화면에서는 선택 단계 두 장을 점선으로 구분하고
설명에 「선택 시에만」을 적었다. 시험 8건 추가.

## 3. 생성 수가 더해지지 않던 문제

생성 완료 307 ≠ 검토 대상 225 + 승인 62. 나머지 20 = 「수정 필요」로 되돌아간 것 + 최종 승인 없이
reviewed/released로 남은 옛 항목. `pendingRevisionCount`를 만들어 생성 완료 카드 설명에 세 수를 함께 적는다
(`검토·승인 대기 225 · 승인 62 · 수정 필요·보류 20`). 읽는 사람이 더해 볼 때 맞아떨어진다.

## 7. 2차 검토 반영 — 「무엇을 센 수인가·전체와 부분·지금 할 일」

연구자 질문(왜 승인이 2인가, 67은 어디서 오나, 누구의 기록인가)과 외부 검토(원격 `main` 기준)를 판정해 반영했다.
「DB 실시간」 표기는 연구자 결정으로 유지.

**콘텐츠 제작 현황 — 4칸→5칸, 위계를 드러낸다.** 미션 재료 1713(설명: 그중 학습 미션 생성 307 — 두 수는 같은 표의
같은 행이며 307 ⊂ 1713) → 학습 미션 307(총수) → 그 총수를 나누는 세 상태: 검토·승인 대기 · **수정 필요·보류(독립 카드로 승격)** ·
교수자 승인 완료(수업 사용 후보). 세 상태는 정의상 서로 배타적(`generated` / `reviewed·released`+승인 / 나머지).

**검토·승인 진행 — 완료 실적이 아니라 대기 위치.** 절 제목을 「검토·승인 대기 N개 — 다음 처리 단계」로 바꾸고 한 줄 주석
(「각 미션을 다음에 처리할 단계 하나에만 셉니다. 승인 완료·수정 필요·보류는 제외」)을 붙였다. 위 카드의 62(승인 완료)와
아래 2(승인 **대기**)가 같은 이름이라 완료 수로 읽히던 문제. 단계 이름은 누가 무엇을 하는지 + 「대기」:
규칙 기반 검사 대기(그중 검사 실패 N — 실패는 재검사가 아니라 내용 수정) · OpenAI 1차 검토 대기 · Claude 독립 검토 대기(선택) ·
OpenAI 2차 검토 대기(선택 · Claude 의견 재검토) · 교수자 최종 승인 대기(감수한 뒤 결정 — 「클릭만」이 아니다).

**수업 운영·학습 수행.**
- 교과목 5 → 「공개 N · 비공개 M」(`status='published'`만 학습자에게 보임). 편성 여부는 공개 여부의 대체 정보가 아니라 뺐다.
- 「수업 편성 미션 67개」→ **「미션 배정 67건」** — 큰 수를 배정 건수(운영 단위)로. 설명에 서로 다른 미션 수와
  **승인 완료 수**(편성 ID ∩ 승인 ID — 산술이 아니라 집합 대조). 🔴 정정: 앞서 "승인 안 된 미션도 놓을 수 있다"고 쓴 것은
  현행 규칙이 아니다 — 새 편성은 `isCurrentMissionReleasedForLearner`(승인+현행 릴리스)로 제한된다. 승인 전 미션이 섞여
  있다면 게이트 이전의 옛 편성이다. 학습자 노출은 공개·릴리스·주차·접근 조건도 걸리므로 「보임/안 보임」은 화면에서 주장하지 않는다.
- 「수업 참여 승인」→ **「승인 학습자」**(계정 승인 · 전체 교과목 공통). 「수강생」은 교과목별 등록을 뜻하므로 쓰지 않는다.
- 「학습 수행 기록」→ **「미션 수행 기록」**, 설명 「전체 계정 · 전체 기간 누적」. 표 전체 행 수이며 역할·기간으로 거르지 않는다.
  계정 역할로 시험/실제를 나누는 것은 틀린 방법(학습자 계정으로도 시험한다) — 시험 계정 식별 근거는 연구자가 정해야 한다(3.1.4·5.4.2).
