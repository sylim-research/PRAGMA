# 교수자 최종 감수 화면 정리 — 필터 우선 배치와 이름 변경

- 시작: `origin/main` `3bde6b19`, 새 작업트리 `admin-declutter-2026-09-09`.
- PR [#119](https://github.com/sylim-research/PRAGMA/pull/119) → `main` `57208619`. CI(타입 검사·전체 시험·production build) 통과.
- 배경: 2026-09-08 외부 시연에서 관리자 화면의 편의성과 과설계 지적이 있었다. 2026-09-09 사용자 지시로 착수했다.

## 문제

승인 화면(`/admin/review` = `AdminAssembly`의 `reviewMode`)은 감수 대기열에 닿기까지 여섯 개 층을 지나야 했다.
제목·설명 → 파이프라인 5단계와 2문단·링크 3개 → 통계 카드 2개와 캡션 → 학습설계 4축 필터 → 고급 필터 → 선택 도구.
**승인하러 온 사람이 필터부터 만났다.**

실측으로 바로잡은 앞선 진단 두 가지가 있다.

- 「페이징 없음」은 사실이 아니었다. `LIST_CAP = 50` 기본 제한이 있었고, 문제는 「모두 표시」가
  **단방향**이라 한 번 펼치면 그 세션 내내 226행 높이가 유지되는 것이었다.
- 「고급 필터 반복 노출」은 PR #109에서 이미 접힘으로 처리돼 있었다.

전체 높이 11,556px 가운데 **목록이 10,851px(94%)**다. 행 하나가 216px이다. 상단 정리로 줄일 수 있는 몫은
그 나머지였고, 행 압축은 이번 범위에 넣지 않았다.

## 결정과 구현

- **필터를 맨 위에 두고 기본 펼침으로.** 조립·승인 모두 첫 동작이 「필요한 미션 찾기」다.
  그 앞에 있던 것은 제거했다.
  - 절차·권한 안내 문단 제거. 파이프라인과 권한 경계의 근거는 `content_review_runs`·승인자·승인 시각·
    상태 전이 같은 **기록 구조**에 있고 이 문단에 있지 않다(논문 4.3.3·4.3.4 서술과 대조 확인).
  - 상태 카드 4개(승인 화면에서는 2개) 제거.
- **상태를 필터의 한 축으로.** 카드가 유일한 상태 필터였으므로 칩 한 줄로 옮기고 건수를 함께 표시한다.
  칩의 건수는 **상태를 제외한 나머지 필터만** 적용해 센다. 카드는 필터 적용 후를 세어 지금 보고 있지 않은
  상태는 항상 0으로 보였다(승인 화면에서 「검토 완료」가 늘 0이었다). 지금은 79로 보인다.
- **목록 제한을 토글로.** 「전체 N개 모두 표시」 ↔ 「처음 50개만 보기」. 대기열 제목에 현재 표시 수를 적는다.
- **`프로필 초기화 테스트`를 개발 환경에서만 노출.** 로그인한 관리자 자신의 프로필을 미완료로 되돌리는
  시험용 조작이라 운영 대시보드에 둘 것이 아니다.
- **화면 이름 `콘텐츠 승인` → `교수자 최종 감수`**(사용자 결정). 이 화면의 주된 행위는 학습자 화면으로
  미션을 확인하고 판단하는 감수이고, 승인은 그 판단이 끝나는 지점이다. 주어에 교수자가 들어가 AI 검토에서
  사람의 결정으로 넘어가는 지점이 메뉴에서 보인다.
  - **화면 이름만 바꿨다.** 행위명은 그대로다 — 승인 패널 제목·버튼·대시보드 단계명은 `교수자 최종 승인`,
    페이지 설명도 `교수자가 … 감수한 뒤 최종 승인합니다`를 유지한다. 용어대장이 「교수자 감수」와
    「교수자 최종 승인」을 서로 다른 행위로 정의하고 「감수·승인」 고정 세트명을 금지하기 때문이다.
  - 이 화면을 가리키는 링크 문구도 함께 바꿨다(코퍼스·프롬프트·기준 보정·과거 검토 기록).

## 검증

  - 승인 화면 작업 앞 높이 **887px → 628px**.
  - 목록 펼침 49,794px → 되접기 11,556px(이전에는 되돌릴 수 없었다).

## 남은 것

- **화면 표제 `교수자 최종 감수`가 논문 용어대장에 없다.** `01_정본/00_용어대장.md`는 표제형으로
  `교수자 최종 승인`·`콘텐츠 승인`만 지정한다. 대장에 추가할지는 연구자 결정이며, 그전까지 논문 4장 서술·
  도판 캡션과 화면 이름이 어긋난다.
- `AdminFinalApproval.tsx`가 제목 `교수자 최종 승인`을 쓴다. `/prototype/mission-release` 개발 전용
  경로라 운영·메뉴에는 없어 이번에 손대지 않았다.
- **목록 행 216px 압축은 미착수.** 화면 길이의 94%가 여기다. 상황 전문·태그·버튼 구성을 줄이면
  한 화면에 8~10건이 들어온다. 보이던 정보가 줄어드는 변경이라 별도 판단이 필요하다.
- 관리자 화면은 admin 로그인이 필요해 배포본 확인은 연구자 몫이다.

### 대기열은 읽는 자리가 아니라 고르는 자리

행 하나가 216px에 상황 전문을 다 담고 있어 페이지가 11,479px, 한 화면에 3건이었다.
행은 미션을 갈라 보는 데 필요한 것만 남겼다 — 4축 배지와 한 줄 제목. 상황 전문과 맥락은
행을 펼치면 나오고, 접힌 상태에서는 툴팁에 있다.

**제목은 이미 데이터에 있었다.** `core_content.brief_note_ko`는 학습자 메뉴가 미션 제목으로
쓰는 필드다(`missionMenuTitle`). 표본 60건 전수 보유(60/60), 길이 13~48자의 명사구 요약이다.
AI 생성도 migration도 없고, 관리자 목록이 이 필드를 안 쓰고 있었을 뿐이다.
🔴 다만 저장된 값 일부는 명사구가 아니라 문장이다(「…요청한다.」). 생성 프롬프트 쪽 사안이라
이번 범위 밖으로 둔다.

### 색은 장식이 아니라 구분 장치

4축이 나란히 놓여도 서로 읽히도록 **축마다 다른 채널**을 쓴다. 같은 축 안에서만 비교하면 된다.

| 축 | 채널 |
|---|---|
| 화행 9개 | 저채도 색면 9종(요청 청회색·거절 로즈·사과 샌드·감사 세이지·제안 라벤더·초대 모브·반대 슬레이트·칭찬 청록·불만 테라코타) |
| 언어방향 2개 | 브랜드 한 쌍 — 금(한→중)·네이비(중→한)를 옅게 |
| 수준 3개 | 순서 있는 축이므로 색상 고정, 농도만 입문→고급으로 상승 |
| 모드 2개 | 색면이 아닌 테두리형 — 위 세 축과 층이 갈린다 |

⚠️ 1차 시안은 채도가 높아(#1D4ED8·#B91C1C 등) 연구자가 반려했다. 실측 배경값을 전부
RGB 220~250 구간으로 내려 크림·네이비 톤 안에 넣었다.

### 그 밖

- **필터가 화면을 이끈다.** 목록 제목과 건수는 제거했다 — 화면 제목이 이미 이름을 말하고
  건수는 상태 칩(전체·감수 대기·검토 완료)에 있다.
- **일괄 AI 검토는 행을 고른 뒤에만** 한 줄로 나타난다. 상시 박스와 그 설명 문단은 없앴다.
  🔴 기능을 지운 것이 아니다 — 이 화면의 유일한 일괄 검토 경로이며, 진행 상황은 예전부터
  `AdminShell`의 `ReviewPreparationStatus`가 모든 관리자 화면 상단에 보여 준다.
- **글자 크기**가 11~13px이라 226건을 훑기에 작았다. 제목 15px, 배지 12.5~13px,
  필터 13.5~14px로 올렸다.
- 표시 개수 50 → 20.
