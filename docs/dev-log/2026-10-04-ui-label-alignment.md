# 2026-10-04 화면 표시 정렬 4건

운영 화면을 처음부터 끝까지 따라가며 확인한 뒤, 표시 계층만 고쳤다. 승인 콘텐츠·저장된 수행 기록·프롬프트 본문·DB는 바꾸지 않았다.

| 항목 | 화면 | 변경 |
|---|---|---|
| 참고 표현 해설 | 학습 미션 완료 화면 | 해설 문자열의 강조 표시(백틱)가 그대로 보이던 것을, 다른 해설과 같은 `RichLine` 렌더러로 표시. 모든 미션 완료 화면에 적용 |
| MJT 문항 번호 | 교수자 최종 승인의 감수 목록 · 학습 미션 설계 요약 | v6 미션은 학습자 제시 순서(단일 표현 판단 → 판단과 이유 → 복수 표현 비교 → 수정안 선택 → 직접 수정)로 번호와 순서를 맞춤. 섹션 id(`mjt-n` = `mpj_items[n]`)·저장된 감수 결정·응답 귀속은 그대로. 순서 값은 `V6_MJT_PRESENTATION_ORDER`로 학습자 런타임과 공유 |
| 제안 화행 프롬프트 카드 설명 | 생성계약·운영 프롬프트 | 「선택의 여지와 구체성으로 적정·부족·과함을 가릅니다.」 → 「제안의 구체성과 상대의 선택권을 검토합니다.」 설명문만 변경, 프롬프트 본문·지문(sha256) 동일 |
| 피드백 상태 표시 | 내 기록 | 요청 화행(`request_mitigation_optionality`)만 꼬리표를 미션 피드백 화면과 같은 「좋음 / 수정 권장」으로. 설명문과 「다시 살펴볼 점」은 그대로. 다른 화행은 기존 범주 이름 유지 |

검증: `npm run typecheck` 통과. 관련 테스트(감수 화면·학습자 런타임·내 기록·학급 토론 등 9개 파일)와 새 `recordFlow.test.ts` 통과. 데모 완료 화면은 로컬에서 백틱 0개 확인. 교수자 화면과 내 기록은 배포 후 운영 화면에서 확인한다.

남은 것(이번에 바꾸지 않음): AI 검토 의견의 문항 위치 표시(`ContentReviewPanel`)는 v5 미션에도 쓰여 내부 배열 번호를 유지한다.
